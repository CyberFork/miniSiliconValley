# 将课程编辑器升级为九视窗时序所见即所得工作台

> **2026-09-08 架构更新：**保留时序轴、页内所见即所得和底部中控；“九视窗”只代表 N=4 时的默认布局，目标必须支持 `4 位 P/D/M/O 导师＋N 名学员＋1 个底部中控`。统一以 T-085 和 `docs/COURSE_PLATFORM_ARCHITECTURE.md` 为准。

## 原始需求

当前 `https://minisv.vip/control/editor/` 以课程库、字段表单和 JSON 为主，不够直观。希望参考 `https://minisv.vip/alpha/` 的角色组织方式，但不再打开八个独立窗口，而是在同一个课程编辑页中平铺：

- 4 个 P/D/M/O 导师视窗；
- 4 个学员视窗；
- 1 个位于八席下方的课程中控视窗；
- 共 9 个视窗。

顶部使用一条覆盖全课程的时序轴，按“五大步 × 每步若干 Block”组织完整流程。选择任何 Block 时，9 个视窗同步切换到该时刻；用户点击视窗中的可编辑内容，可以直接修改对应的 Course Package 字段，并立即同步到所有受影响视窗。

## 产品目标

将课程编辑器从“JSON／表单编辑器”升级为“可视化课程排练与编排工作台”：

- **时间上**：一眼看完五大步和所有 Block，明确每个时刻由谁主导、各角色看到什么。
- **空间上**：一屏同时管理中控、4 导师和 4 学员的视图。
- **所见即所得**：编辑者看到的应与课堂运行时的中控／席位显示一致。
- **结构化真值**：直观编辑仍写回唯一 Course Package，不另存一套预览文案。
- **版本可控**：所见即所得不等于边编辑边改变正在运行的课堂。

## 当前实现与缺口

### 已有能力

- `tools/live-run/static/editor.html:25-135` 已有课程库、课程结构、抽卡内容、JSON 源码、版本与 Alpha 同步信息。
- `tools/live-run/static/editor.js` 已能选择五大步和 13 个 Block，编辑课程字段，并使用共享 `card-view.js` 预览学员卡牌。
- `tools/live-run/static/controller.js` 已按 Block 显示中控脚本、学员提示、导师、执行和验收状态。
- `tools/live-run/static/seat.js` 已按席位类型渲染导师和学员视图。
- `/alpha/` 已证明 4 导师＋4 学员的角色组织容易理解。

### 当前缺口

- 编辑表单与最终席位 UI 分离，需要编辑者在字段名和实际视图之间自己建立映射。
- 当前只有单卡牌预览，没有完整的中控＋八席同步预览。
- Alpha 席位页是独立弹窗且需要 lease，不适合直接当作编辑器的内嵌数据源。
- 当前中控与席位渲染器主要从运行状态取数，尚缺“仅从未保存工作区生成确定性预览状态”的投影层。

## 目标工作台布局

### 顶部：全课程时序轴

- 第一层为 5 个固定 Macro Step：找真问题、定真方案、做真产品、进真市场、跑真运营。
- 第二层为每个 Macro Step 的 N 个 Block；当前标准骨架为 B01—B13。
- 每个 Block 显示：ID、标题、建议时长、当值导师、完整性、未保存改动和验收警告。
- 点击 Block 时九视窗原子切换，禁止部分视窗仍留在上一 Block。
- 时序轴可用于编辑 Block 标题、建议时长、当值导师和步骤口径；新增、删除、移动 Block 必须受 Course Schema 和固定骨架校验约束，不能绕过 5×13 安全规则。
- 支持上一块／下一块、跳转到阶段、错误筛选与缩放全课程。

### 中间：八席预览画布

默认先展示 4 个导师席与 4 个学员席；中控不占用八席之上的空间。画布提供：

- 八席缩略全局模式；
- 导师四席模式；
- 学员四席模式；
- 单窗放大精编模式；
- 双窗对照模式，例如中控 vs P 导师、P 导师 vs 学员 1。

每个席位视窗必须显示角色、当前 Block、课程 revision/digest 和“预览／连接测试房／正在运行”状态，避免把设计预览当成真实课堂。

### 底部：课程中控视窗

- 课程中控固定在 4 导师＋4 学员视窗之后，作为九视窗中的第 9 个视窗。
- 中控以全宽布局展示当前 Block 脚本、当值导师、执行、验收、上一块／下一块及版本状态。
- 底部中控可折叠或调整高度，但不得改到顶部、浮在八席上方或长期遮住席位内容。
- 顶部只保留全课程时序轴和全局版本／保存状态；时序轴与底部中控职责分离。

## 所见即所得编辑规则

### 可直接点击编辑

- 课程、Macro Step 和 Block 的标题、描述、时长和目标。
- 中控中的学员提示、导师口播、学员行动、系统动作、现场道具和验收条件。
- 四位导师的当前任务、观察重点、角色文案和本块专业线信息。
- 四名学员的任务、行动、完成标准、协作提示和课程卡牌内容。
- 点击卡牌时，必须定位到稳定卡牌 ID 和它的唯一源字段，不得编辑随机手牌副本。

### 派生状态不得伪装成课程内容

以下内容默认只读或通过预览控件设置，不直接写入 Course Package：

- 未读／已读／已讲出。
- 学员手牌在某一次随机发牌中的位置。
- 当前 RP、个人钱包、团队资金、提交数、课堂成员和运行结果。
- 第几块、进度条、当前状态和从其他字段组合出的标签。

点击这些元素时，界面应说明“这是模拟／派生状态”，并提供对应的预览场景设置，而不是打开无效的文本输入框。

## 预览状态引擎

建立一个不产生运行副作用的确定性投影层：

```text
浏览器未保存 Course Working Copy
                +
选中 Block／预览场景／随机种子
                ↓
       Preview State Projector
                ↓
  中控投影 + 4 导师投影 + 4 学员投影
                ↓
          九视窗共享渲染
```

- 切换 Block 时根据该时刻生成一致的九视窗状态，不需要真实执行前面的 API 副作用。
- 随机发牌使用可见的固定 seed，可切换 seed 以检查不同手牌，但同一 seed 必须可重现。
- 允许预览 ready、executing、awaiting-acceptance、error 和 completed 等状态，但不把这些预览状态保存为真实 Run。
- 预览的提交、资金和 RP 使用明确的模拟值与水印。

## 渲染同源方案

### 默认不直接内嵌当前 Alpha 页

当前 Alpha 席位页：

- 依赖 `clientId + lease` 能力凭证；
- 直接轮询真实运行状态；
- 响应使用 `X-Frame-Options: DENY` 和 `frame-ancestors 'none'`；
- 不能预览浏览器中尚未保存的课程内容。

因此，不应通过放宽安全头、共享 lease 或在 9 个 iframe 中轮询生产状态来实现。

### 推荐方案

- 抽取中控和席位的无副作用共享渲染器，运行页与编辑预览共用组件、模板、文案转换和设计 token。
- 编辑器为共享渲染器提供 Preview State；真实 Classroom／测试房为它提供 Runtime State。
- 如果 CSS 隔离不足，优先评估 Web Component／Shadow DOM，而不是把带真实权限的 Alpha URL 直接 iframe 进编辑器。
- 只有在证明共享渲染器无法满足视觉隔离时，才设计专用、无网络副作用、sandboxed 的 Preview Frame；该 Frame 不得复用 Alpha lease 或运行 API。

## 编辑模式与中控模式边界

为避免“所见即所得”误操作真实课堂，页面必须分清：

### 1. 编辑预览（默认）

- 九视窗从浏览器 Working Copy 即时渲染。
- 可点击编辑、切换 Block 和模拟运行状态。
- 不连接或修改任何真实 Run／Room。

### 2. 连接测试房／排练

- 九视窗读取指定测试 Room 的真实状态，中控可执行和验收。
- 编辑内容与运行控制必须分区；未保存内容不自动注入测试房。
- 课程内容变更后，需要显式保存并在测试房执行受控更新。

### 3. 正式课堂

- 可用同一九视窗管理形态查看已绑定的 Released 课程，但课程内容默认只读。
- 不允许边上课边把未保存编辑直接写入正式 Room。
- 正式课堂版本更换必须继续遵守版本锁定、兼容校验和审计边界。

## 保存与发布

本任务不新增第二套存储或因“所见即所得”放弃版本化：

```text
页面内未保存 Working Copy
          ↓ 保存
不可变 Candidate revision/digest
          ↓ 测试房显式加载和验收
Approved Candidate
          ↓ 明确发布
Released revision/digest
```

- 沿用 T-075／T-080 已确认的简化方案：不要求用户管理独立 Draft 列表，点击“保存”生成新 Candidate。
- 保存不会静默替换已运行的测试房／Alpha／Classroom 版本。
- 正式发布只能选择已绑定验收回执的 exact Candidate digest。
- 未保存状态、Candidate、当前测试房和 Released 必须在顶部持续可见。
- 现有 `editor.html` 中“保存草稿／发布到主控”文案与该目标不一致，实施时应按 T-075／T-080 统一。

## 与 Classroom／Alpha 合并方向的兼容

本工作台不应把“Alpha 席位页”硬编码为唯一预览实现。如果后续确认“一套 Classroom Runtime，测试 Room 与正式 Room 两种模式，Alpha 只作 QA”，则：

- 九视窗应共用最终 Classroom 的中控和席位渲染器。
- 编辑预览提供 Preview State，测试 Room 和正式 Room 提供各自隔离的 Runtime State。
- `/alpha/` 可继续作为测试房创建、账号分配、自动化和诊断入口，但不再维护另一套席位 UI。

## 实施分段

1. **渲染契约盘点**：标记中控、导师和学员 UI 中每个显示元素的 Course Path／Runtime Path／Derived 性质。
2. **抽取共享渲染器**：消除编辑预览和运行页的复制 HTML／CSS／文案转换。
3. **建立 Preview State Projector**：根据 Working Copy、Block、状态和 seed 生成九份确定性视图。
4. **实现九视窗画布**：先排列 4 导师＋4 学员，再在底部放置全宽中控；同时实现全局、分组、放大和对照布局，处理缩放、滚动和性能。
5. **实现全课程时序轴**：展示 5×N Block、主导导师、时长、错误与修改状态，一次性切换九视窗。
6. **实现可见元素→唯一源字段的点击编辑**：带路径、类型、校验、撤销／重做和受影响视窗提示。
7. **接入版本链路**：沿用 Working Copy→Candidate→测试验收→Released，显示差异与 digest。
8. **可选连接测试 Room**：在严格模式切换后，让九视窗查看真实测试状态，由集成中控执行。
9. **迁移旧表单**：保留高级结构化编辑与 JSON 源码作为精确编辑／诊断模式，但将九视窗设为默认入口。
10. **浏览器与性能验收**：覆盖桌面大屏、笔记本、平板和窄屏降级布局。

## 验收标准

- [x] 打开课程后，默认先显示 4 导师＋4 学员的八席画布，课程中控以全宽第 9 视窗位于底部，无需弹出 8 个独立浏览器窗口。
- [x] 九视窗的信息结构、文案转换、卡牌渲染和核心样式与实际课堂席位共用同一份实现，不是截图或复制品。
- [x] 选择任意 Macro Step／Block 时，9 个视窗在同一渲染周期切换到同一 Block。
- [x] 可从任一可编辑可见元素追溯到唯一 Course Package 字段；改动后所有受影响视窗立即更新。
- [x] 派生／随机／运行字段有明确的只读或模拟标识，不会被误存为课程内容。
- [x] 随机发牌预览可用 seed 重现；点击手牌修改的是稳定卡牌 ID 的源内容。
- [x] 中控视窗可在预览模式显示完整控制信息；只有明确连接测试 Room 后才能执行真实动作。
- [x] 未保存 Working Copy 对运行中测试 Room 和正式 Classroom 为零副作用。
- [x] 保存生成新 Candidate，不静默刷新运行中 Room；正式发布绑定 exact digest 验收回执。
- [x] 九视窗预览不使用 Alpha seat lease，不读取正式学员、手牌、账本或身份数据。
- [x] 不通过放宽现有 `frame-ancestors 'none'` 或 `X-Frame-Options: DENY` 来直接嵌入真实 Alpha 席位页。
- [x] 在 1440px 及更宽屏幕可查看 9 窗全局；在常见笔记本尺寸可分组或放大编辑；平板和手机不产生无法操作的过小字体。
- [x] 对每个 Block 至少生成一次九视窗契约快照，验证角色隔离、无缺失字段、无串席和无渲染漂移。
