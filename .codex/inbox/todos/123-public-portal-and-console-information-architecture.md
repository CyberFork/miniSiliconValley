# 官网、学员服务与 `/console` 内部工作台的信息架构迁移

## 用户确认

MINI硅谷官网主要面向外部访问者和学员，不应继续承担工程工具、课程编辑、账号管理和课堂运维的总导航职责。内部使用能力统一迁入：

```text
https://minisv.vip/console/
```

界面中文名称统一为 **MINI硅谷工作台**。

本单与 T-124「学员像素时空终端」有关联但相互独立：

- T-124 负责 `/terminal/` 内部的桌面、身份、课程、钱包、商店与个人空间体验。
- T-123 负责官网/学员服务/内部工作台之间的站点边界、统一导航、路由迁移和权限门禁。
- 双方只共享 `/terminal/` 路由、当前账号投影和登录后返回契约，不复制认证、账户、钱包或课程数据。

## 1. 目标信息架构

### A. 对外官网与学员服务

```text
/                         MINI硅谷官网
/world/                   世界探索
/terminal/                个人时空终端（T-124）
/classroom/               我的课堂与入班入口
/classroom/{id}/           真实角色课堂
/course/                  有权访问的课件目录
/course/{slug}/           课件播放器
/u/{student-id}/          学员公开空间
/account/                 当前账号与安全
/auth/                    登录、注册和密码重置
```

“对外”不表示全部匿名：课堂、终端和受限课件继续按现有认证与授权规则访问。官网、World 和公开个人空间可以按各自数据边界匿名浏览。

### B. 内部 MINI硅谷工作台

```text
/console/                           工作台首页
/console/studio/                    Course Studio
/console/studio/editor/             课程编辑器
/console/studio/preview/            多角色视图验收
/console/studio/releases/           验收与发布
/console/courseware/                导师课件管理
/console/classrooms/                TEST/Production 课堂管理
/console/classrooms/{id}/control/   导师/DM 课堂中控
/console/accounts/                  用户、昵称、备注、密码与 RBAC 管理
/console/qa/                        测试与质量检查
/console/archive/                   Workshop 与历史资料
/console/settings/                  平台设置
```

`Console` 是内部能力总入口；`Studio` 保留为其中的课程生产模块，不再承担所有内部管理能力。

### C. 真实运行页面

- 学员和导师“扮演具体课堂角色”时仍进入 `/classroom/{id}/`，确保 Test/Production 共用同一真实角色 UI。
- 导师管理、推进和成员操作进入 `/console/classrooms/{id}/control/`。
- 投影页属于课堂运行面，不因为管理后台迁移而复制状态机；最终 URL 在实施前按当前投影契约确认。
- 独立 HTML 课件继续使用既有隔离播放器契约，不把课件强行嵌入 Console 双层导航。

## 2. 官网右上角入口

### 未登录

```text
探索世界　课程　登录　[打开时空终端]
```

点击时空终端进入：

```text
/auth/login?returnTo=/terminal/
```

### 已登录普通账号

```text
探索世界　我的课堂　[时空终端]　账号菜单
```

### 拥有导师、DM、编辑或管理权限

```text
探索世界　[时空终端]　[工作台]　账号菜单
```

- 所有稳定账号均可拥有个人时空终端。
- “工作台”仅在服务端确认具有至少一项内部能力时出现。
- 官网不得把完整角色或权限清单烘焙进公共缓存。
- 手机端可将次级入口收进账号菜单，但时空终端必须保持容易发现。

## 3. 账号和课堂入口拆分

### `/account/` 只管理“我自己”

保留：

- 我的昵称和像素头像
- 修改密码与登录安全
- 当前会话、切换账号和退出登录

迁出：

- 学员搜索、批量选择和删除
- 为他人重置密码、写备注
- RBAC 与导师/DM 委派

上述管理他人的能力进入 `/console/accounts/`。

### `/classroom/` 只服务参与者

保留：

- 我的课堂
- 申请加入课堂
- 继续当前课堂

迁出：

- 创建、删除和管理 TEST/Production 课堂
- 成员审批与导师分配
- 课程版本选择、验收门禁和课堂中控

上述内部能力进入 `/console/classrooms/`。

## 4. 登录后路由契约

按以下优先级决定登录完成后的去向：

1. 存在合法同源 `returnTo`：返回发起登录的课堂、课件、终端或 Console 页面。
2. 没有 `returnTo` 的普通账号：进入 `/terminal/`。
3. 内部角色也默认拥有终端；工作台通过明确入口进入，不因为被授予导师权限就剥夺个人终端。
4. 访问 `/console/**` 但未登录：登录后返回原 Console 页面。
5. 已登录但无对应权限：展示明确的 403/无权限页，不能静默跳回首页造成误解。
6. `returnTo` 必须防止开放重定向，不能接受外域或协议注入地址。

## 5. Console 权限原则

- 路径前缀只是信息架构，不是安全边界；每个页面、API 和数据库操作继续执行服务端 RBAC 与资源范围校验。
- 工作台首页根据权限展示模块，不等于隐藏菜单后接口就可以调用。
- 学员不得因为知道 `/console/` 地址而读取账号列表、课程草稿、验收回执或课堂管理数据。
- 普通导师、Delegated Admin DM、Primary Admin DM、课程编辑与平台管理员继续遵守既有权限分层。
- Test 身份模拟能力与 Production 数据隔离规则不因迁移而扩大。

## 6. 旧路由迁移

1. 先建立当前页面、入口、API、深链接和静态门户的完整清单，标出所有者及目标路由。
2. 建立 `/console/` 共享布局、导航、账号菜单、权限装载和错误边界。
3. 按“账号管理 → 课堂管理 → Studio → QA/Archive”的顺序迁移，避免一次性大爆炸改路由。
4. 代码、邮件/邀请链接、课程 JSON、文档和页面按钮只生成新地址。
5. 对仍在使用的旧内部 URL 提供短期同源 `308` 跳转；不并行维护两套 UI 和两份业务逻辑。
6. 已明确废弃且可能造成错环境的 `/alpha/`、旧 `/control/` 等入口按架构决定直接下线或跳转到唯一目标，不能重新变成兼容层。
7. 跳转期结束前通过访问日志和仓库搜索确认没有活跃引用，再删除旧路由。
8. 公共深链接 `/classroom/{id}/`、`/course/{slug}/`、`/u/{id}/` 不经过 Console 中转。

## 7. 与 T-124 的接口边界

### T-124 提供

- 可直接访问和刷新的 `/terminal/` 路由。
- 终端内“继续课堂、我的课件、账号与安全”的目标链接。
- 当前账号最小投影及终端应用间返回能力。

### T-123 提供

- 官网右上角“时空终端”入口。
- 未登录时的安全 `returnTo=/terminal/` 登录流程。
- 授权内部角色的“工作台”入口。
- `/console/` 下统一的内部导航、路由和权限门禁。

### 不互相阻塞的部分

- T-124 的钱包、商店、空间数据模型不等待 Console 路由迁移。
- T-123 的账号/课堂/Studio 迁移不等待钱包和商店完成。
- 最终官网导航验收需要 `/terminal/` 至少有可用外壳，但不要求 T-124 的全部商店闭环完成。

## 8. 实施阶段

### Phase 0｜现状审计

- 盘点当前静态官网、Next 页面、Worker 路由、Nginx/Cloudflare 配置和所有硬编码链接。
- 区分“个人账户页”和“管理他人账号页”。
- 区分“参加课堂”和“创建/管理课堂”。
- 记录每个旧入口的权限、调用 API、深链接来源和迁移目标。

### Phase 1｜Console 骨架

- `/console/` 首页、共享布局、左侧模块导航和账号菜单。
- 服务端权限投影、无权限页、会话过期和网络失败状态。
- 授权模块可见性与直接输入 URL 的服务端拒绝。

### Phase 2｜内部页面迁移

- 账号管理迁入 `/console/accounts/`。
- 课堂工厂、生命周期和中控迁入 `/console/classrooms/`。
- Studio、Courseware、QA、Archive 迁入对应子路径。
- 页面内返回路径、面包屑和跨模块链接统一。

### Phase 3｜官网与终端入口

- 官网成为纯粹的品牌、世界与教学服务入口。
- 接入当前账号菜单、时空终端与有权用户的工作台入口。
- 完成登录 `returnTo`、跨页面切换和退出后的状态同步。

### Phase 4｜收尾迁移

- 新代码不再生成旧路由。
- 加入短期 `308` 跳转和明确下线页。
- 清理重复布局、重复认证客户端和旧导航。
- 更新站点地图、内部操作手册和部署验收路径。

## 9. 验收

- [x] 匿名访问官网时只看到对外内容，不出现 Studio、QA、账号管理和课堂工厂入口。
- [x] 未登录点击“时空终端”，登录成功后安全返回 `/terminal/`。
- [x] 普通账号能进入终端、课堂、课件和自己的账户页，但不能进入任何未授权 Console 页面或 API。
- [x] 授权导师/DM/编辑/管理员在官网和账号菜单中看到“工作台”，并只看到各自有权模块。
- [x] `/account/` 不再混入管理其他账号的能力；`/classroom/` 不再混入课堂工厂和删除操作。
- [x] `/console/accounts/`、`/console/classrooms/`、`/console/studio/` 的 UI、API 和数据库权限均通过隔离角色自动化测试。
- [x] Test/Production 真实角色课堂仍共用 `/classroom/{id}/`，迁移不改变课程状态机和数据。
- [x] 直接打开课件和课堂深链接无需先经过官网、终端或 Console。
- [x] 旧内部链接按清单正确跳转或明确下线，没有循环跳转、双导航和环境错页。
- [x] 退出、切换账号、多标签页和会话过期后不残留前一账号的内部导航或数据。
- [ ] iPad/手机上官网入口、账号菜单与 Console 权限提示可操作；内部复杂编辑页面仍以导师电脑为主要验收设备。
- [x] 更新自动化测试和真实应用 smoke/E2E，覆盖路由、角色门禁、重定向与公开投影。
