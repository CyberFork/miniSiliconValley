# 进阶课后作业与问卷：模板复用、课堂定向发放及受控管理

## 2026-09-15 实施口径

用户要求清理并完成所有遗漏 Todo 后，本单由“待讨论”进入实施。为避免另造团队体系，当前 Classroom 就是发放边界：

- 模板支持短回答、长回答、单选和多选，1—30 题，可复用并以不可变 revision 保存。
- 每次发放锁定模板 revision，并快照当时课堂中 active learner 收件人；后续改模板或增删成员不会悄悄改变历史作业。
- 平台 Admin 可管理全部课堂；导师仅能管理自己担任 DM／Admin DM 的课堂。模板创建者或 Admin 可编辑，其他导师可复用。
- 学员只读到发给自己账号的作业；支持草稿、正式提交、截止后只读和导师文字反馈。
- TEST 与 Production 依附目标 Classroom 自然隔离；不把 T-119 公开自填昵称记录猜测绑定到任何账号。
- T-119 继续作为独立公开练习保留，不迁移、不覆盖、不降低其现有数据边界。

## 拆分来源

用户要求简化 T-119，并把复杂功能另建 TODO。本单接收原 T-119 的团队定向问卷与可复用模板需求，以及尚未确认的进阶管理能力。

原始方向：

> 我们需要开发问卷系统，应该是需要指定发送给对应课堂的学员（操作单元是某个学习团队，在发送之前，可以自定义问卷模板，方便后续复用）这个是需要继续讨论和低优先级的todo，可以先记录。

最新拆分要求：

> 把T-119的功能进行简化把复杂的功能单独新建TODO。

[T-119](119-team-targeted-questionnaires-and-reusable-templates.md) 先独立交付免登录固定作业表单、自由提交和免登录只读查看。本单保持低优先级、待讨论，不阻塞 T-119，也不把以下候选功能当作全部已批准开发。

## 原有需求保留

- 自定义问卷/作业模板，保存、编辑并供后续重复使用，不只固定《我的第一款游戏》一种表单。
- 以学习团队为操作单元，选择对应课堂中的目标团队，向其学员定向发放，而非默认全平台发送。
- 学员在课后模块找到自己的作业，填写提交，相关人员查看结果。
- 继续参考 `cowork/我的第一款游戏，课后作业.docx`，但该材料不是所有未来模板的唯一结构。

## 后续讨论点

1. **模板与题型**：题型范围、必填项、自定义配置、复制复用；模板后续修改如何与已发问卷/既有答案分离，是否需要版本快照。
2. **课堂和团队发放**：全队或部分成员选择、发送前收件人确认、后续成员变动、重复发送与收件名单历史。
3. **身份与授权**：Admin、课堂 Admin DM、授权导师、学生分别能做什么；实名/匿名、单人回答和团队汇总可见范围。不能从账号管理权限直接推导所有问卷权限。
4. **作业流程**：课后入口、草稿、提交后修改、截止时间、提醒和补交等是否需要；这些限制不反向加入 T-119。
5. **反馈与结果**：完成率、导师批改、反馈、评分、汇总、导出和筛选的最小必要范围。
6. **进阶内容能力**：高级表格、在线画板、附件版本和素材管理是否值得做；T-119 的基本可选图片上传不必等待这些功能。
7. **历史数据衔接**：若未来需要导入 T-119 提交，必须保留来源与原始记录；自报姓名/昵称不是经过验证的账号身份，不自动绑定或覆盖 Membership。

## 架构与实施边界

- 先对齐“模板 → 选择课堂/团队 → 发放 → 填写 → 查看/反馈”的最小闭环，再确定实际模型和页面，不先建设通用表单平台。
- 受控管理若启用，复用既有账号、Classroom、团队和授权机制，不另造身份系统；内部管理位置与 T-123 的 `/console/` 架构对齐。
- T-119 的免登录查看风险是其当前明确边界；本单未来增加权限时需明确切换方案，不能声称公开历史数据一直受保护。
- 题型、权限、期限、审核和分析等仍为待讨论项，不作为现阶段验收门槛。
