# 补齐主页账号入口并统一账号下拉菜单可读性

> 后续整体布局见 [T-109：官网与内外入口重组](109-public-website-internal-navigation-and-workshop-archive.md)。官网将从工程总导航转为公开品牌介绍，但仍需本单的统一账号入口；菜单可读性与会话问题可以先修，无需等待官网重做。

## 用户反馈

> 主页没有账号管理。账号右上角管理下拉菜单不同选项字体颜色不一样。

截图中「账户中心」为深色底配深色字，几乎不可读；「切换账号」为深底白字；「退出登录」为浅底红字。普通菜单项的差异不是账号权限提示，应统一。退出操作可以保留明确的警示色，不要求全部按钮机械同色。

## 本轮源码核对

### 主页没有接入账号菜单

- `/` 由 `deploy/minisv/gateway/default.conf` 直接提供静态 `index.html`。
- `deploy/minisv/site/index.html` 顶部只有导航和 Course Studio 入口，没有登录态/账号菜单挂载点。
- `portal.js` 只读取 `/healthz`、`/release.json`，未读取当前身份。仅在 React 的 `app/page.tsx` 增加组件不会自动更新这个静态门户。

### 下拉菜单存在外层导航样式污染路径

- `AccountMenu.tsx` 的「账户中心」是 `<a>`，切换/退出是 `<button>`。
- `account-menu.module.css` 原本为普通链接/按钮共同设置白字深底，说明截图中的深色字不是组件预期。
- `app/classroom/platform.module.css` 的 `.top nav a { color: inherit; ... }` 比组件 `.actions a` 选择器更具体，会影响嵌套菜单链接；菜单浅色面板继承的是深色字。
- `app/studio/studio.module.css` 的 `.user a`、`app/course/course.module.css` 的 `.top a` 也存在跨组件后代选择器，需要一起审查；前者还有 padding/background 覆盖风险。
- 本轮依据截图和静态源码记录，尚未在浏览器中读取 computed style；最终修复必须记录实际命中的规则，不猜测 CSS 加载顺序后盲目加 `!important`。

## 期望行为

1. **主页未登录**：右上角有清楚的登录入口，主页内容仍可匿名浏览。
2. **主页已登录**：与 Studio/Classroom/课件库显示一致的当前账号，并可进入账户中心、切换账号、退出登录。
3. **账号列表切换**：使用 T-106 的已验证账号会话列表，不复制旧的「切换即退出」逻辑。
4. **请求失败/会话过期**：明确展示状态，不把网络故障误显示为已注销，也不展示上一账号残留身份。
5. **个人账户与管理他人区别**：这里补的是当前账号菜单；全站账号管理仅向有权限者提供入口，不因为主页新增按钮就赋予导师或学员管理所有人的权限。

## 实现方案

### A. 同一账号契约，覆盖静态主页

- 为门户选择共享账号菜单的构建产物/挂载组件或复用可复建的公共导航壳；不要另写一份独立认证和切换流程。
- 登录态从受保护的同源服务读取最小身份信息；现有 `/api/auth/session` 同时返回 sessions，评估是否需要专门的最小导航身份投影，而不是把全部会话资料塞进公共页面。
- 公共 HTML 和共享静态缓存中不得烘焙账号信息；个性化请求使用私有/不缓存策略。
- 切换/退出后主页及其他已打开页面同步，清理旧请求和身份缓存；不要要求用户进入 Studio 才能操作账号。
- 不向已冻结的 P/D/M 原版课件文件注入菜单或改写其字节来实现全站导航。

### B. 组件样式隔离

- 外层 `.top nav a`、`.user a` 等只作用于其自有导航项，改用直接子级或明确类，避免命中账号弹层后代。
- 普通项共用 action 类/语义 token，明确文字、背景、边框、字号、padding、hover/focus/visited 状态。
- 退出使用独立 danger 变体；禁用/忙碌状态不能让有效入口看起来不可用。
- 不把链接改成按钮来规避 CSS；账户中心继续用语义正确的导航链接。
- 面板、文字、按钮、焦点框都由账号组件控制；保留品牌像素风格，但优先保证可读性。
