# 课件一键直达：去除播放中转页、World 导览与整站入口绕行

## 用户原始需求

> 进入课件不需要有一个中间界面还要跳转第二次。给你的链接这个弹出框是 world 页面的，为什么这里还有？再看看还有没有其他过度设计的地方。
>
> 也是写入 todo。

用户提供的 P 导师课件入口：

`https://minisv.vip/courseware/product-mentor-foundations/?revision=0&digest=b2852b39462bc05464582b3c36f773e68fa84775b9e7c7673a128fac97d7cda5`

截图显示整站首页及“世界线已断裂。你们要重新学会如何建造。”WorldBriefing，而不是直接进入所选课件。

## 1. 调研基线与已确认原因

本轮公开 release 为 `20260911T192157CST-t093-t111-r2`；主工程源提交 `256ac17d8b4c2fb6757e8b9408eaffcb929ca417`，原仓库 `CyberFork/minisv` 的课件来源提交为 `679213a61b835335016eac7649213983a0e48489`。依据这些已部署来源只读核查，未用落后的本地工作树判断线上行为。

### A. 平台先增加了一次纯中转点击

- `app/course/[slug]/CoursewareFrame.tsx:57–61` 对 static-bundle 先展示版本身份及“在独立页面打开完整课件”，还需点“进入全屏课件”。
- 该分支被 `/course/{slug}/` 和 Studio 内部课件预览共同复用；不是只有 P 课件需要第二次点击，D/M 等静态课件也应纳入核对。
- 这里的按钮只是前往资源入口的链接；固定版本/保持资源原样并不要求用户必须先读一页技术说明再点一次。

### B. P 包注册的是整站根入口，不是课件专用入口

- `app/lib/courseware-store.ts:59–68` 将 P 的 `entryPath` 注册为 `/courseware/product-mentor-foundations/`。
- 该条注册的 sourceIdentity 对应上述 chj commit 与内容树 `3a041c4714190cc026f6de8e06e15cec0e5f765d`；按其既有 canonical 字符串复算 digest 与用户链接的 `b2852b…cda5` 一致，确认是同一个 P r0，不是随便检查最新 chj 后猜测。
- 原包 `app/page.tsx` 直接返回 `WorldApp`。`WorldApp.tsx:80–85` 默认 `view="home"`，所以进入的是 mini 硅谷整站首页。
- `WorldApp.tsx:100–115` 在没有 `msv-world-state-v1` 本地存档时显示 WorldBriefing；它不限定为用户真正进入 World 页面才触发。
- `WorldApp.tsx:633–634` 的“进入迷你硅谷”只关闭弹窗，不切换到课件。
- 原包没有读取 URL 中的 `revision/digest` 来选择教学视图，也未发现现成的 URL view/PPT 直达解析。平台传入 exact 参数保证身份，不会自动让原包跳到 PPT；不能凭空加一个 `?view=overview` 就宣称修复。

## 2. 同一打开链路的其他冗余与待确认项

### 已确认，应收口

- **嵌套站点导航**：平台课件库 → 播放中转页 → chj 首页 → 大纲 → 课件；包内还有“首页/课程大纲/我的/World”等整站导航，品牌按钮返回包内 home，而非明确的播放器返回路径。课件打开不应等价于又进入一套官网。
- **技术说明占据播放首屏**：`CoursewareFrame` 和课件目录长期展开 packageId、revision、完整 digest 及工程解释。用户曾明确要求身份可见，因此不能删除身份；应保留紧凑可见的版本标识及可展开/复制的完整诊断，不用大块说明拦住播放。
- **“全屏”文案混淆**：当前中转链接称“进入全屏课件”，但该组件只做页面跳转。默认应直达课件；真正的全屏功能若提供，应为播放界面内可选操作，不再成为另一道进入门槛。
- **首次访问与老浏览器表现不同**：已有 World 存档可能掩盖弹窗问题。不能通过给测试浏览器预写 localStorage、要求用户先关闭一次弹窗，或仅用已有存档验收来代替修复。

### 待与课件作者核对，不擅自删除

- `CourseHome` 的“开始”先进入 outline；`CourseOutline` 的“课程总览”才进入 `CourseOverview`，第 1 章又被特殊映射到总览问题档案（slide index 6）。需明确导师所选课件应从哪个教学入口开始，不能仅凭文件名自动认定第一章是第 1 张 PPT。
- PPT 封面、可选目录、分章节选择、逐步揭示、课堂规则说明及真正的教学任务可能有教学作用，不能统称“过度设计”全部删除。
- 用户随后明确要求优化 P 课件内部地图式大纲的背景体积，并对调底部放大/发布模块，另见 [T-117](117-product-mentor-outline-background-and-layout.md)。该教学目录需保留可用，本单只去掉强制入场绕行，不以删除大纲页面来代替直接播放。
- 旧 chj 首页的四阶段、章节和“导师是 DM”等口径若出现在公共入口，应按 T-103/T-109 核对；不能因为整站被包成 P 课件，就把其旧导航结构当成当前课程真值。

## 3. 目标体验与实现边界

1. 已登录且有权的导师/学员从课件库、Classroom 导师课件入口或 Studio 课件预览点击一次后，直接看到所选课件的教学首屏或合法深链接页；不再被要求确认“进入”、关闭 World 弹窗或重新找大纲。
2. 未登录时走必要的登录流程，成功后恢复相同课件与 exact 参数，不重新回目录或官网。对用户可访问的 HTML 入口核对友好登录跳转；不能为此放开私有资源或把资源/API 鉴权响应改成随意可读。
3. 保留必要的登录、权限、Candidate/Released 范围与版本校验，但让已通过的正常播放路径自动继续；真正无权限、资源丢失或版本失效时提供明确错误。
4. World 导览只服务 World 场景，课件播放不自动初始化无关世界存档、人物档案或世界线流程。独立 World 的正常导览入口不因本单被全局删除。
5. 采用轻量直接播放/经校验后自动进入的方案，不为了省一次点击再增加一套播放器状态机、确认向导或设置页；按安全隔离及现有架构决定渲染方式，而非简单强制 iframe。
6. 课件回看、换页、全屏和退出保持清楚；保留当前 URL 的 revision、digest 及该课件真实支持的页面/揭示参数。无需引入课堂 Block→PPT 页的强制细粒度映射，也不让翻课件推进 Classroom。
7. 入口必须指向实际教学内容，不能只隐藏弹窗却继续停在 chj 首页；也不能简单把原导览字样改成“课件介绍”来掩盖整站入口错误。

## 4. 不可变版本与原包处理

- 优先核对是否存在可直接使用的稳定教学入口；本轮在当前 P r0 中未找到 URL 直达支持，需要明确解决这个限制，不是假设已有。
- 若需拆出专用课件入口或调整原包启动逻辑，沿 T-100 的受控源码/资源构建流程产生新 revision。不要覆写 P r0 静态字节、改旧 digest 或向已发布包注入隐藏弹窗的脚本。
- 如修复通过新版本交付，明确哪些目录默认入口与后续课堂绑定升级、哪些旧 exact 课堂仍保留原版，以及旧链接如何提示升级；不把旧 r0 静默指向不同内容，不宣称所有历史链接已经修好。
- 本次提取播放入口不重写 P 导师教材，也不把首页/World/档案/运营功能塞进课件编辑器；内容结构调整交作者确认。

## 验收

- [ ] 使用无 World 存档的全新浏览器状态，有权限账号点击 P 课件后直达明确教学首屏，无中转确认、WorldBriefing 或官网找课流程。
- [ ] 已有存档、刷新、重新打开、深链接进入均符合直接播放契约，不靠预写本地状态绕过引导。
- [ ] D/M 等静态课件、inline HTML 与 Studio 内部预览逐一核对：去掉纯中转页，但权限范围和内容隔离没有被放宽。
- [ ] 未登录 → 登录 → 原目标课件正确恢复；无权限/版本失效明确报错，不悄悄改版本或退回不相关主页。
- [ ] 版本身份可见且完整信息可展开核对；工程说明不遮挡教学首屏，页面跳转与真正全屏的文案/行为一致。
- [ ] 导师和学员从各自真实入口、桌面与 Pad 验证；浏览返回有明确去向，不陷入包内首页/目录循环。
- [ ] 不误删教学封面、目录、任务或逐步揭示；不改变 World 正常导览、Classroom 状态及已发布不可变包。
- [ ] 记录改动前后点击链、对应 URL/revision/digest、实现/测试/部署证据；若旧版本仍需保留旧行为，单列范围并与用户确认，不提前整单关闭。
