# 开发导师模块思维课件更新：变形金刚到乐高的模块层级递进

## 用户原始需求

> 关于开发导师课件的更新，帮我创建todo，可以优化之后再创建：变形金刚比如就是轮子可以是车的也可以是飞机起落架的。玻璃可以是車窗也可以是飞机机舱。还有什么通用零件也可以举例。然后是乐高，是组件的更进一步，因为前面变形金刚提到了组件，这个组件是出厂就设定好的，只能重组，玩家是没有能力改变组件形态和功能的，只能在组件基础之上进行组合。而乐高则不一样，乐高有更小的颗粒度，用乐高有限的几种基础零件玩家可以手动生成各种组件。而在组件的基础之上进行组合就才进入和变形金刚一样的状态。

## 2. 优化后的教学主线

```text
第一层  看见复用
        同一构件在不同整体中承担不同角色
        ↓
第二层  使用预制组件
        变形玩具：在设计好的结构和连接约束内变换组合
        ↓
第三层  自己创造组件
        乐高：用更小的标准零件先搭出轮组、座舱等组件
        ↓
第四层  把自制组件再次组合
        轮组／座舱／机翼 → 完整玩具 → 更大的场景系统
        ↓
软件迁移  按需求选择复用或自建，明确接口，再测试组合结果
```

学生主结论建议：

> 我们既可以使用现成组件，也可以用更小的零件创造组件，再把组件组合成整体。关键不是拆得越细越好，而是这一层要完成什么任务、怎样连接、怎样验证。

### 需要保留的三个准确性边界

1. **变形不等于任意重装。** 使用“预制结构的变换与重组”讲直觉；具体玩具可能通过折叠、转动、收纳实现变形，不一定可拆卸，也不一定同时具有汽车、飞机、机器人三种形态。三形态演示可采用明确标注的课堂示意，不冒充某款真实产品。
2. **乐高没有消除基础零件的约束。** 玩家通常并未改变单块积木的形状和材料；自由来自更细粒度的标准构件，让玩家能重新设计上一层组件的组成、功能和接口。不能讲成“乐高能改变任意零件的本性”。
3. **自建不是天然比复用高级。** 递进的是可设计的层级，不是方案优劣；直接复用和自己构造可以同时出现在同一项目。复用仍需验证，自建需要承担实现、测试和维护成本。

## 3. 通用构件举例

投屏优先只放 **轮子、透明件、铰链/转轴** 三个易看懂的例子，其余作为教师备课或逐步展开，避免同屏塞满六组说明。

- **轮子**：玩具汽车的行驶轮、玩具飞机起落架中的轮子。可以共用的是支撑/滚动能力，轮子本身不是完整起落架，还需要支架、轴等结构。
- **透明件**：车窗、座舱盖、机器人观察窗或罩盖。共用的是透视与隔离等特性；应说“机舱的透明罩/窗”，不把一块透明板等同于整个机舱。
- **铰链/转轴**：车门转动、玩具机翼折叠、机器人手肘活动。共用的是受约束的相对转动，方向和活动范围仍需满足设计。
- **插销/连接件**：连接车身、机翼或四肢。强调尺寸、方向和连接方式必须匹配，不是“任何地方都能插”。
- **外壳板/结构板**：车身覆盖件、玩具机身外壳、机器人胸甲。用于讲覆盖/连接/支撑，不暗示任意板材都能作为真实飞机的气动机翼。
- **齿轮**：玩具传动机构、螺旋桨演示机构、关节运动机构。用于讲运动传递，不能只凭出现齿轮就认为具有真实动力或可任意交换。

统一提问顺序：

1. 它在这个整体里叫什么？
2. 它承担什么任务？
3. 哪些能力或连接约束没有变？
4. 换到另一个整体，还缺什么条件才能使用？

教师提示强调：**名字与场景角色可以变化，但复用要检查接口、尺寸、强度、空间等约束。** 演示是玩具/课堂模型，不是汽车或航空工程的兼容性结论。

## 4. 乐高要明确展示两次组合

不能直接从一堆积木跳到成品，否则看不见“创造组件”这一关键层。

```text
基础零件层                     功能组件层                 作品层
积木、轮胎、轴、连接件    →    可滚动的轮组          →    玩具汽车
透明件、框架、铰链        →    能开合的座舱          →    玩具飞机
长条积木、连接件、铰链    →    可连接/折叠的机翼     →    组合场景
```

- 先选择组件任务，再选零件，不是随意堆完后才起名字。
- 组件完成后给它一个边界与接口，例如“能滚动的轮组，连接点在哪里”。
- 把组件接入整体，再检验是否能完成原定任务。
- 拆开组件，改变内部组合，再次满足相同接口；引出替换与迭代。
- 无动力零件时只说“可滚动轮组”，不凭空称为动力组件或发动机。

模块尺度的解释：同一套轮组相对车身是组件，相对轮胎和轴又是整体；玩具汽车放进交通场景时可以成为更大系统的一个单元。观察尺度变化，不代表各层使用相同类型的接口。

## 5. 页面与互动建议

### 页面 A：同一个构件，为什么换了角色？

- 从旧 S02 承接，采用变形玩具课堂示意。
- 先展示构件，再由教师选择汽车/飞机/机器人示意；用相同颜色或标记追踪同一构件，避免视觉上偷偷换成另一个物件。
- 学生先判断角色变化，教师再点击构件，逐步揭示名称、职责、能力和约束。
- 给一个不能直接复用的反例，例如接口尺寸不匹配，避免形成“能拼上就能用”的印象。
- 投屏结论：**换位置和角色，不等于可以忽略接口与能力。**

### 页面 B：乐高多给了我们哪一层设计权？

- 基础零件 → 自制组件 → 完整作品，三层保持可见的关系。
- 小任务：先用给定零件选择或设计一个轮组，说明它的任务、需要的零件和连接点，再接到整体。
- 再问：轮组不好用时，是换整个组件，还是拆开重做内部？何时选择哪一种？
- 投屏结论：**先创造组件，再像使用预制组件一样组合整体。**

## 6. 对应到软件开发

### 使用预制模块

调用已有登录服务、地图组件或通知服务：按对方约定的输入、输出和失败处理方式使用，不需要在本次任务中重新设计内部实现。第三方服务与 UI 控件处于不同层级，教师讲解时不把它们当成同一种东西。

### 自己构造模块

可继续使用原课件的校园失物招领情境：

- 用输入框、选择器、按钮等 UI 构件做一个“发布失物表单”组件。
- 用校验函数、业务规则、数据结构和存储接口实现“失物发布”模块。
- 再与检索、认领、通知等模块协作，组成完整用户路径。

避免把“几个按钮拼起来”直接等同于完整业务模块；显式区分 UI、逻辑和数据职责。自建模块内部也可以复用现成模块，不制造二选一。

选择复用或自建时，学生检查：任务是否匹配、接口是否兼容、有哪些限制、测试/维护成本如何。具体安全敏感能力不作为鼓励学生从零实现的练习。
