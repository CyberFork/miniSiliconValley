## 最终口径（2026-09-19 用户确认开始实施）

唯一决策记录：[P1／P2 已确认设计](../../../../docs/DEVELOPMENT_P1_P2_CONFIRMED_DESIGN.md)。
原始调研与要求保留在 [历史讨论快照](../../../../docs/decisions/T133-discussion-history.md)；早期“五组”、七格和课时未定已被最终问答替代。

- 扩展已有《立棍》，保留设备预约短案例、起点／目标／终点、分层纠偏、注意力与证据；新增校园寻宝贯穿示范。不是独立 Agent 开发课。
- 两课均 120 分钟，P2 独立：8 跑偏案例＋27 六项与寻宝＋10 逐问对齐＋40 自己的主棍及全部子棍＋22 优先子棍执行返工＋13 互查收束。
- 整款游戏为主棍；每个模块为子棍；微棍只需知道，提示词中说明 AI 负责拆解，不让学生填写或操作。
- 六项固定为：执行者 → 上下文与项目设计 → 目标 → 约束 → 避免 → 验收。主棍与子棍同结构；子棍继承整体边界。
- 完整游戏愿景＋本轮优先范围；所有功能模块完成核心模板，不能把范围偷缩成只写一个模块。
- 一次只问一个问题；优先 5–8 个关键问题，维护已确认／待决定清单，再给初稿；阻断执行的未知不能擅自猜。
- 学生自选豆包 Work／WorkBuddy，不规定设备、不绑产品 UI；课内启动自己的游戏，真实首版、验证和一次修正，课后继续。
- 提供可编辑 Markdown、主棍整份复制和逐个子棍复制、下载／打印。仅页面内存，不冒称云端保存；无新后台。
- 默认浏览器可运行原型，可按项目选其他可验证结果。校园寻宝是明确标注的预设课件示范，不充当学生 AI 实操证据。
