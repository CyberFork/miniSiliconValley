```text
① 已有策划／一句游戏想法
          ↓
AI读材料、识别缺口、整理补全，关键决定向人问清
          ↓
主棍：人决定、人确认
子棍：AI派生、人确认与调整
执行棍：AI编写、自查对齐，不要求学生逐根批准
          ↓
② 一份自包含、可复制交给开发AI的完整立棍方案提示词
          ■ 本功能到此停止

③ 用②开发、自测和返工：后续独立进行
```

主棍与每根子棍固定六项：**执行者 → 上下文与项目设计 → 目标 → 约束 → 避免 → 验收**。

### 判断

当前工作台是**旧流程的模板填写／拼接器**，不是没有价值，但默认任务分配与最新需求不一致：

1. 起点错位：学生先写主棍和模块地图，仍承担了本应由AI辅助整理的工作。
2. 输入负担过重：技术字段、模块ID、交接和Markdown表格提前成为填写任务。
3. 停止点错位：提示词会从子棍确认继续进入③制作、测试和返工。
4. 输出不完整：重点是派生子棍，未确保最终汇总出可独立交接的主棍＋子棍＋执行棍提示词。
5. 分发未接通：本机安装Skill不等于网页已经有Skill，短启动句也不等于普通聊天工具已加载技能全文。

## 3. 推荐实施方案：改入口和材料，不加AI后台

本节是本次部署的推荐实现路径；如实施时希望改成网页内置AI对话，应另行讨论，不静默扩大本单。

### 3.1 学生首页

- 页面主标题改为「从我的策划，生成立棍方案」或同义清晰文案，显式展示①→②，③只作为后续说明。
- 默认只需粘贴已有策划，或写一句游戏想法；不要求先写主棍、模块地图、接口或测试记录。允许已有P1材料作为可选补充。
- 不新增必须填写的复杂表格。已有DOCX可在支持附件的外部AI工具中直接提供；本单不扩建服务器文件上传、DOCX解析或作业管理。
- 主棍空白模板、模块地图、小车示例、手动子棍编辑可保留在「示例／进阶参考」中，不再抢占默认入口，也不能继续被默认复制进学生自己的最终方案。
- 使用现有MINI硅谷UI技能和已有组件；重点改善主次、字号、触摸可用性，不增加装饰性步骤或重复中转页。

### 3.2 两种方式，服务同一套①→②流程

**支持加载Skill的工具：**

- 提供可下载的完整 `ligun-game-coach` Skill包、简短启动句、策划输入说明。
- 明确先在工具中加载Skill，再提交策划；仅输入 `$ligun-game-coach` 不代表任何工具都会自动拥有该技能。

**普通对话工具：**

- 提供「复制完整对齐提示＋我的策划」，作为不支持Skill加载时的兼容入口。
- 兼容提示词必须包含真实工作流、六要素、确认边界、执行棍计划自查和最终②交接规范；**不能只复制 `assets/start-prompt.md`，也不能只写一个Skill名称**。
- 启动材料引导外部AI完成问答与方案生成，不预填学生的确认，不把页面字符串拼接伪装成AI完成设计。
- 不预设某国产模型／客户端都支持Skill；实际教学工具的加载、文本长度、复制和多轮行为需要真实试用后标注。

两种方式都明确说明：**网页负责材料准备与分发，外部AI负责读策划、问答补全并生成②。** 当前没有AI调用能力的网页按钮不能叫「已生成完整立棍方案」。

### 3.3 ②的验收定义

②不是“请你再帮我生成方案”的二次启动词，也不是散落的模块摘要。它应是一份能交给没有本次聊天记录的开发AI的完整提示词，包含：

- 具体项目的完整主棍及人的确认状态。
- 全部模块子棍，含本轮与未来简版；已知未来要求与真正未知分开。
- 本轮执行棍：上层依据、具体交付、依赖、边界、未来检查的输入与预期结果、未执行状态；不能机械地把子棍换名。
- 后续开发顺序、整体路径检查计划、待定项和必要依赖。
- 给③的开发、自测、纠偏指令，但本次生成②不执行它们。
- 不遗留“同上”“使用上一版”、不可访问的本机路径或缺失聊天上下文。

AI可以自动整理已给信息、补齐表述和推导验收条件；关键玩法、冲突和未知需人决定。主／子棍未确认时不能冒称最终②；确认后执行棍由AI自行检查，不把任务逐根退回给学生。
