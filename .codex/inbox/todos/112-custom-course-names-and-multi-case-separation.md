# 课程按教学主题自定义命名，解除课程与单一案例的旧耦合

## 用户需求

早期课程按 Google、饿了么等具体案例命名；后续一份课程/课件可以包含多个案例，因此希望自定义名称，而不是被案例名称限定。

方向：课程名称表达教学主题，案例是课程中的内容。不能继续把“一个课程＝一家公司案例”作为产品默认前提。

## 当前已具备的能力

依据本地现行源码核对，未在本轮登录线上修改内容：

- 编辑器“多角色直改”中的课程身份区有“点击修改课程名称”，写入 `course.name`。
- 也可通过“高级结构 → 课程名称”编辑同一字段。
- `updateCoupledField()` 会同步生成包级 `title`；课程库显示来自 `course.name`，不是限定 Google/饿了么的枚举。
- 修改名称后保存整门课程，产生新 Candidate revision/digest；现有 exact 课堂不会自动替换为新版本或热更新其名称。
- `course.id` 为稳定加载/引用键，与可读名称分开；只改名不需要克隆课程或修改 ID。

因此不要把“首次支持课程改名”作为从零实现任务，也不应要求用户先完成多案例架构改造才能改名。

## 仍需收敛的旧假设

- 新建弹窗的课程名称占位文案仍是“案例名｜五步创业闭环”。
- 元数据帮助语仍写“新案例通过克隆创建”，容易把课程与案例继续等同。
- `validateCoursePackage()` 强制旧 `case.campaignId === course.id`。
- `contentPackages.casePackages` 虽已是集合，历史类型的 `caseId` 仍必须等于课程 ID；这不能直接视为已完整支持多个不同历史案例。
- `course.period` 改动会联动 `case.period`，多案例下不应把课程总体跨度自动覆盖到单个案例时间。

这些限制主要属于结构化课程 JSON；导师 HTML/PPT 中讲多个案例不应因此被禁止，也不要求为 PPT 每页建立 Block 映射。

## 目标边界

1. **课程名**：自定义教学主题，例如“AI 创业实践：从问题到产品”（仅示例，不自动采用）。
2. **导师课件名**：独立的教材/PPT 名称，可讲多个案例；沿用现有课件库与超链接方案。
3. **案例名与 caseId**：指向具体历史或模拟案例，不兼任整个课程的身份。
4. **课堂名**：指某次开课实例或团队测试，例如“周六一组”；与课程模板名称区分。
5. **courseId**：保持稳定，旧 `eleme-…`/`google-…` ID 可以继续作为历史技术标识，不再据其拼写决定教学范围。新建 ID 可用中性标识。

## 分阶段实施

### A. 命名与界面收敛（轻量，优先）

- [ ] 保留当前两个改名入口并在新 UI 中清楚展示；修改同一字段，不另建一份目录别名作为第二名称真值。
- [ ] 新建、复制、帮助、空态和默认命名改为课程主题导向，移除“必须按案例/公司命名”的暗示。
- [ ] 课程库、编辑器、视图验收、发布与新建课堂的课程名一致，仍显式保留 ID/revision/digest 供核对。
- [ ] 说明改名的保存与版本影响：浏览器未保存稿、Candidate、新发布版本、已有课堂各自显示哪个名称；不原地改写旧快照。
- [ ] 检查标题、长度、空白、特殊字符和显示溢出；与 T-109 的 skill 新 UI 保持一致。

### B. 结构化多案例解耦（先设计再改模型）

- [ ] 沿用已有 CasePackage/ScriptPackage 能力，梳理独立 caseId、来源、卡片、剧本和课程引用关系，避免新造第二套案例正文。
- [ ] 区分旧 case 字段的兼容含义与新多案例关系；设计明确迁移流程后再解除 courseId/caseId 的旧相等约束，不能只删除校验。
- [ ] 各案例保留自己的名称、时间、来源和事实/模拟边界；课程总体描述不自动改写具体案例元数据。
- [ ] 同一课程可以包含多个历史案例及独立模拟案例；F 来源卡只能引用本案例的有效证据，模拟内容不能因课程含历史案例就被当作史实。
- [ ] 导师仍通过已绑定的课件链接自由打开 PPT；不附加逐页、逐 Block 的强制精细映射。
- [ ] 老版本与已开课堂保持原引用和原 digest；必要升级只产生新 Candidate，经过既有验收/发布链路。

## 验收

- [ ] 将一个案例式课程名称改成不含公司名的自定义名称，保存后刷新仍保留，不改变 courseId。
- [ ] 不改 `case.name`、caseId、卡牌/来源/导师课件标题或他人课堂实例名称。
- [ ] 包级 title、课程库与各读取同一 exact 版本的页面显示一致；不出现一处新名、一处旧名却宣称是同版本的情况。
- [ ] r9 旧课堂保留旧快照，新 Candidate/新课堂展示对应新名；界面说明清楚，不误判为两份课程真值。
- [ ] 多案例 JSON 改造后，一门中性名称课程可包含两个不同历史 caseId 与一个模拟案例，来源和发牌/展示归属不串线。
- [ ] 支持多个案例不强迫复制整门课程，也不强迫拆成多份 PPT；旧包与迁移后的新包均有回归验证。

本轮只核对与记录；未擅自给任何课程改名，也未迁移线上课程 ID/数据。
