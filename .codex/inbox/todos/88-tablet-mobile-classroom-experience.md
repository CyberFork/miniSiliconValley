# 将无实体键盘的 iPad／平板作为学员课堂一等设备

## 原始需求与范围校准

真实上课时，主要需要考虑的是**学生学员端**：学员大概率使用 iPad、Android 平板等没有实体键盘、主要依赖触摸和屏幕软键盘的设备。

设备分工已经明确：

```text
学员             iPad／Android 平板为主要设备；手机作为兼容与应急设备
P/D/M/O 导师     使用电脑，不要求以平板作为主要工作设备
Admin DM         使用电脑运行课程中控和成员管理
课程编辑人员      使用电脑进入 Course Studio 和课程编辑器
课堂公共投屏      由 DM 电脑或独立投屏设备打开
```

因此本任务不再要求把复杂 Studio 编辑、DM 中控、成员管理或导师课件制作完整适配到手机／平板。它集中保证：**学员只拿一台无实体键盘的 Pad，也能独立登录、理解任务、查看私密卡、参与课堂、提交结果并安全退出。**

## 一、正式支持边界

### 学员 Pad 必须完整支持

```text
/auth/login/
/account/                         首次改密、账号状态和退出
/classroom/                       学员课堂列表
/classroom/{classroomId}/         学员真实席位 UI
```

如果学员后续需要作品页、团队协作页或上传页，这些新路由也必须继承本任务的触摸和平板契约。

### 手机作为兼容和应急设备

手机不作为主课堂设备，但学员应能完成：

- 登录和首次改密。
- 查看自己的 Classroom。
- 查看当前任务和私密卡。
- 完成核心提交。
- 查看提交结果与课堂状态。
- 退出或切换账号。

手机可以使用更紧凑的单列布局，但不能因为设备较小而暴露他人私密信息或丢失核心功能。

### 本任务不要求移动端完整支持

```text
/studio/editor/                   课程编辑人员使用电脑
/studio/preview/                  内部验收人员主要使用电脑
/studio/courseware/               导师／管理员使用电脑
/studio/releases/                 发布人员使用电脑
/classroom/{id}/control           Admin DM 使用电脑
/classroom/{id}/members           Admin DM 使用电脑
/course/{slug}/                   导师课件主要由导师电脑打开
```

这些页面仍需做到不会意外泄露或完全崩坏，但不作为本任务的平板核心验收对象。DM 与导师电脑端的验收分别继续由 T-086、T-087 覆盖。

## 二、学员 Pad 的核心任务流

学员端应围绕一条简单、连续的触摸任务流组织：

```text
登录
→ 首次改密（如需要）
→ 进入今天的 Classroom
→ 看清现在只做什么
→ 查看自己的私密卡／线索
→ 完成现场活动
→ 使用软键盘或触摸选择提交结果
→ 看见已提交／待验收／需要补充
→ 进入下一 Block
→ 课程结束并安全退出
```

学员不需要理解 Candidate、Released、digest、CoursewarePackage、Membership 或状态机等后台概念。

## 三、无实体键盘交互原则

### 触摸优先

- 所有学员核心操作使用约 44×44 CSS px 或更大的触摸目标。
- 相邻按钮保留足够间距，避免滚动时误触提交或退出。
- 不依赖鼠标 hover、右键、双击、键盘快捷键或精确光标。
- 拖拽不能是唯一操作方式；卡牌选择和排序必须有轻触、上下移动按钮或其他替代方式。
- 需要长按时必须同时提供普通按钮，因为浏览器长按可能触发系统菜单。
- 所有交互在 Apple Pencil、手指和 Android 触摸下都不能要求鼠标特有事件。

### 尽量减少长文本输入

课程任务不应默认要求学生在 Pad 上输入大段文字。优先使用：

- 点选卡牌。
- 单选／多选。
- 标签选择。
- 简短句子或关键词输入。
- 模板化回答槽位。
- “证据＋判断＋下一步”等分段短输入。

如果课程确实需要长内容，应允许导师引导学生先在纸张、白板或其他创作工具中完成，再在系统中提交简短摘要或链接。不得因为没有实体键盘而让学员无法通过当前 Block。

### 屏幕软键盘

- 输入框字号避免触发 iPadOS/iOS Safari 自动放大。
- 软键盘弹出后，当前字段、错误提示和提交按钮仍然可见。
- 页面不得在软键盘显示／隐藏时跳回顶部或丢失滚动位置。
- 点击键盘“完成／前往”时行为明确，不造成重复提交。
- 切换应用、旋转设备、短暂锁屏或键盘收起后，未提交内容不能无提示消失。
- 数字、短码等字段使用适当 `inputmode`，减少切换键盘。

## 四、学员席位信息架构

### 首屏优先级

Pad 打开 `/classroom/{id}/` 后，首屏优先显示：

```text
当前是第几步／哪个 Block
现在只做什么
课堂当前状态
我的主要操作
```

随后显示：

```text
我的私密卡／线索
提交结果
导师反馈／补充要求
RP、个人钱包和团队资金摘要
```

后台版本号、完整审计、长篇说明和低频帮助不得挤占首屏主任务。

### 私密卡

- Pad 上以一列或适合阅读的有限列数显示，不把多张卡压缩成小字缩略图。
- 卡牌标题、F/R/G/U 边界、来源状态、正文和行动要求不能被截断。
- 支持轻触展开／收起和清楚的已读状态。
- 翻卡、抽卡或选卡不能只依赖 hover 或高精度拖拽。
- 横竖屏切换后仍停留在当前卡牌和 Block。
- 页面和缓存中只能出现当前学员自己的私密卡。

### 提交与反馈

- 提交按钮在填写完成后清楚可见，不被软键盘和浏览器底栏遮挡。
- 提交中、成功、失败、离线、重复点击和被导师退回有不同且明确的文字状态。
- 网络未确认前不能显示“提交成功”。
- 重复点击必须通过幂等键避免重复记录、重复 RP 或重复扣款。
- 被退回时直接显示需要补充什么，并保留可以继续编辑的原内容。
- 下一 Block 尚未开始时显示等待状态，而不是空白或无响应。

## 五、Pad 响应式布局

- iPad／Android 平板竖屏和横屏均正式支持。
- 竖屏以单列任务流为主；横屏可以使用“任务＋私密卡”双列，但不能牺牲字号。
- 不允许将桌面页面整体缩小来适配 Pad。
- 页面级不得出现横向滚动；只有卡牌带等明确组件可局部横向滚动并显示提示。
- 顶部栏、底部操作栏和弹窗不得遮挡内容或主要按钮。
- 横竖屏切换后保持 Classroom、Block、已填写内容、当前卡牌和滚动上下文。
- 使用适合移动 Safari 的动态 viewport 单位，不依赖固定 `100vh`。
- 考虑 `safe-area-inset-*`，避免 Home Indicator、圆角和浏览器工具栏遮挡。
- 保留系统文字缩放和浏览器页面缩放能力。

## 六、账号、共享设备与隐私

学生 Pad 可能由机构或家庭共用，因此需要与 T-087 一起验收：

- 页面始终清楚显示当前学员姓名和席位。
- 学员可以直接找到“切换账号”和“退出登录”。
- 共用设备默认不勾选“保持登录”。
- 切换账号后清除前一账号的私密卡、提交、钱包和页面内存缓存。
- 退出后浏览器后退不能重新显示前一学员的受保护内容。
- 标签页恢复、设备锁屏恢复和系统应用切换器需要评估敏感页面遮罩。
- 不把用户名、密码、私密卡或完整课堂数据写入 URL。
- 首次密码修改流程必须可以只用触摸和软键盘完成。
- 管理员的测试身份切换在电脑端完成；学员 Pad 不提供可枚举全班账号的免密选择器。

## 七、网络与课堂状态恢复

Pad 依赖课堂 Wi-Fi，第一阶段不强求完整离线课堂，但必须能从短暂断网恢复：

- 显示在线、同步中、离线、恢复中和需要刷新等状态。
- 重新联网后自动拉取当前 exact Classroom 和 Block。
- 学员未提交输入应在合理范围内保留，恢复后由本人确认再提交。
- API 超时或失败不应让按钮永久不可用。
- DM 在电脑推进到下一 Block 后，Pad 能自动同步或提供明显刷新按钮。
- 已退出、被移除或权限变化后，Pad 的旧缓存不能继续访问课堂。
- 长时间课堂运行后不能因累积所有历史 Block DOM 而明显变慢。

## 八、无障碍与儿童可读性

- 字号、行高和对比度适合儿童在桌面距离使用 Pad 阅读。
- 状态同时使用文字、图标或形状，不只依赖颜色。
- 专业术语需要可理解文案；学员端不展示内部工程术语。
- 动态错误和成功状态使用适当的 `role=status/alert`。
- 外接键盘存在时可以使用 Tab 和 Enter，但核心流程不能依赖外接键盘。
- 屏幕阅读器可识别当前任务、卡牌边界、主要按钮、提交结果和错误提示。
- 尊重系统减少动态效果和文字大小设置。

## 九、学员目标设备矩阵

自动化响应式测试至少覆盖：

```text
iPad mini 竖屏       744 × 1133
iPad mini 横屏       1133 × 744
iPad 竖屏            820 × 1180
iPad 横屏            1180 × 820
iPad Pro 竖屏        1024 × 1366
iPad Pro 横屏        1366 × 1024
Android 平板竖屏     800 × 1280
Android 平板横屏     1280 × 800
手机兼容             390 × 844
大屏手机兼容         430 × 932
```

自动化 viewport 不能代替真实触摸设备。Production 发布前至少使用：

- 一台真实 iPad 或 iPad mini Safari。
- 一台真实 Android 平板 Chrome；如暂时没有，第一轮至少补 Android 手机 Chrome 并登记缺口。
- 无实体键盘、仅手指操作完成全部学员流程。

## 十、性能重点

- 学员首屏优先加载当前 Block、任务、本人私密卡和提交控件。
- 不下载或挂载其他学员视图、导师私有提示、Admin DM 数据和完整 Studio 投影。
- 不在开课时下载整套导师课件或所有历史图片。
- 非当前 Block 资源延迟加载；长课程及时卸载不再需要的大型视图。
- 图片按 Pad 实际显示尺寸提供压缩版本，避免原图占用过多内存。
- 记录首屏资源体积、接口耗时、长期运行内存和重连表现。
- 具体性能预算在真实 Hecate 环境和目标 iPad 基线测量后确定，不以开发电脑速度代替。

## 十一、失败关闭规则

以下任一问题未解决时，不得签发 T-086 的最终 UiAcceptanceReceipt：

- 学员 Pad 出现页面级横向溢出。
- 当前任务、卡牌或提交按钮被顶部栏、浏览器工具栏、软键盘或安全区域遮挡。
- 核心学员操作依赖 hover、鼠标、右键、实体键盘或精确拖拽。
- 课程要求大量键盘输入且没有 Pad 可完成的替代交付方式。
- 横竖屏、短暂锁屏或切换应用导致 Block、输入或账号上下文丢失。
- 私密卡、钱包或提交串到其他学员账号。
- 退出／切换账号后仍能通过后退或缓存看到前一学员内容。
- 断网重连或重复点击造成重复提交、重复 RP、重复扣款或假成功。
- Pad 无法同步 DM 在电脑端完成的课堂推进。
- 真实 iPad Safari 无法完成登录、首次改密、任务、卡牌、提交、反馈和退出全流程。

## 十二、测试与验收

### 自动化测试

- 目标 Pad viewport 的截图、横向溢出和遮挡检测。
- 触摸目标尺寸、可访问名称和触摸操作。
- hover／鼠标／键盘非必需性检查。
- 横竖屏切换和软键盘布局。
- 登录、首次改密、退出和普通账号切换。
- 学员课堂列表、当前任务、私密卡、提交和等待状态。
- 网络离线／恢复、慢速、超时和重复点击。
- 账号切换后的缓存与私密数据隔离。
- 长时间多 Block 运行的内存和交互性能。

### 真实课堂设备演练

设备组合调整为：

```text
1 台 Admin DM 电脑
4 台导师电脑
N 台学员 iPad／Android 平板（无实体键盘）
1 个课堂投屏
```

学员必须只使用触摸和屏幕软键盘完整运行五步骤／全部 Block。回执记录：

- Pad 型号、OS、浏览器、方向和网络。
- 登录与首次改密。
- 每个 Block 的任务阅读、私密卡和提交结果。
- 软键盘、滚动、旋转、锁屏／恢复和断网恢复。
- 账号退出、切换和私密缓存检查。
- API／Console 错误与截图。
- exact CourseRelease 和 App Build ID。

### 验收标准

- [ ] 学员只使用无实体键盘的 iPad／Android 平板即可完成整门课程。
- [ ] iPad／平板竖屏和横屏均无页面级横向溢出、遮挡或不可触达按钮。
- [ ] 学员核心操作不依赖 hover、鼠标、右键、实体键盘或精确拖拽。
- [ ] 屏幕软键盘弹出时字段、错误和提交按钮仍可操作。
- [ ] 私密卡完整可读，且只出现在当前学员会话。
- [ ] 提交成功、失败、离线、退回和等待状态清楚。
- [ ] 重复点击与重连不会重复提交、奖励或扣款。
- [ ] DM 在电脑推进课堂后，学员 Pad 可以可靠同步。
- [ ] 横竖屏、锁屏、切换应用、刷新和短暂断网后状态可恢复。
- [ ] 退出和切换账号不会泄露前一学员私密信息。
- [ ] 一台真实 iPad Safari 完成全流程验收。
- [ ] 一台真实 Android 触摸设备完成兼容验收，平板缺失时明确记录为待补设备缺口。
- [ ] 手机可以完成学员核心应急流程，但不作为首要视觉基线。
- [ ] 验收回执绑定 exact CourseRelease 和 App Build ID。
- [ ] 学员 Pad 未通过时，不得发布对应 Production Classroom。
