# 学员像素时空终端：账号、课件、公开空间、钱包与装饰商店

## 用户需求与确认过程

用户提出：学员登录后使用一台像素风格的在线虚拟手机，像能穿越硅谷的高科技时间机器。桌面以操作系统图标组织硅谷空间、我的身份、我的课程、课后作业、游戏中心、我的钱包和在线商店。空间展示成就与创意，可分享和访问他人；资产可以购买身份、系统和空间装饰。

用户认可“像素房间外观＋作品展柜交互”的个人空间方向，并补充：

> 4. 不需要展示时间。使用 --:--占位即可，表达时间混乱。7.空间直接对外公开。9.导师手动发放即可。早期还没有配置。我们现在是先做这个相当于用户账号登录之后可以看到的壳子，早期就是一个个人信息、钱包、课件为主要展示内容，其他内容后续会跟上。

> 其他的按你推荐，当前有的东西开发到 3. 钱包＋商店。

> 游戏中心留一个入口即可，后续我会添加具体的内容。

范围不是仅制作静态展示皮肤：目标推进到个人钱包与可实际兑换、装备的装饰商店。游戏中心仅预留入口，不开发游戏内容。

## 与 T-123 的边界

- 官网右上角入口、`/console/` 内部工作台、旧后台路由迁移和全站信息架构由 T-123 承接。
- 两单共享 `/terminal/`、当前账号投影与安全 `returnTo` 契约，但互不复制业务逻辑，也不要求钱包/商店完成后才开始 Console 迁移。

## 1. 学员终端外壳

- 学员登录后的默认入口为个人终端桌面；官网、Admin、DM、导师后台保持各自职责，不强迫管理界面使用虚拟手机。
- 课程、课件等深链接仍直接打开对应内容，不能强制绕回桌面、再次确认进入或观看开机动画。
- 设定是掌上时空终端，布局不锁死为窄手机：电脑可展示设备外观，iPad 充分使用屏幕，手机保留轻量边框。
- 一次一个主应用，提供返回与桌面；单击或单次触摸打开，不依赖双击、右键、hover 或重叠窗口拖拽。
- 终端时间栏固定显示 `--:--`，不显示真实时间，也不自动显示课程历史年份。课程正文需要的历史信息不因此删除。
- 学员可切换应用并返回当前课堂；应用切换不推进或重置 Classroom 状态，未提交内容按既有保存规则保护。
- 桌面保留：硅谷空间、我的身份、我的课程/课件、课后作业、游戏中心、我的钱包、在线商店。当前以身份、钱包、课件为主要内容；课程/课件最终文案以不混淆课堂运行和课件浏览为准。

## 2. 身份、课件与统一数据

- 我的身份复用现有账号 ID、昵称、像素头像和登录/切换/退出能力；与 T-114 的 Admin 学员 CRUD 界面分开。
- 我的课程/课件接入现有课堂及课件目录、鉴权和直接播放入口，不复制课程 JSON、账号或课程状态机。
- 各应用保留可刷新、可直接打开的路由；终端是呈现层，不是另一个认证系统。
- Studio 真实 UI 预览复用正式学员端同一外壳和组件，避免预览旧界面、正式课堂使用新界面。
- 不默认用 iframe 包装全部旧页面，避免双导航和嵌套滚动；既有独立 HTML 课件的隔离播放按原契约保留。

## 3. 硅谷空间与装饰

- 采用像素房间外观＋可点击作品展柜：身份牌、作品工作台、创意墙、成就柜等固定展位。
- 首期固定装饰位置，可换背景、家具外观及展示作品；不开发自由行走、碰撞、任意拖放和地图建造系统。
- 空间直接对外公开，访客查看不要求登录；本人编辑、上架作品和装备装饰仍需鉴权。
- 学员主动选取公开展品，个人草稿、课后作业原始回答、私密卡、钱包明细、管理备注、密码及登录凭据不得随空间公开。
- 团队作品明确团队及贡献归属，不能变成某个人独占的成果。
- 现有 `/world/` 历史世界与学员个人空间分开：前者是公共历史探索内容，后者是个人创意基地。
- 可访问他人公开空间，但首期不附加私信、自由评论、排行榜和复杂社交体系。

## 4. 个人钱包与导师手动发放

- 个人资产随稳定账号跨课程保留；与课堂团队资金分开，TEST 奖励或测试交易不能影响正式资产。
- 钱包展示实际余额和收支记录；未初始化与实际余额为零应区分，不编造可消费余额。
- 导师通过受授权的管理操作手动发放，记录对象、数量、原因、操作者及时间；具体管理入口复用现有导师工作流。
- 本期不开发自动奖励、奖励条件、任务规则、额度配置平台或按活跃度刷积分机制。
- 导师身份不是全站任意改钱包的权限；服务端按既有课堂关联和明确授权校验发放范围。学员不能通过修改请求自行发放。
- 发放、消费及纠错应可追溯，重复点击和失败重试不能重复入账；不直接抹掉历史流水来修正余额。
- 积分名称、首批商品与价格作为实施时的内容选择，不在本单中虚构为用户已确认数值。

## 5. 在线商店与已拥有物品

- 支持真实的“查看商品 → 预览 → 确认兑换 → 获得物品 → 装备”闭环，不只展示无效购买按钮。
- 明码兑换身份装饰、终端主题和空间摆件。成就本身不能购买，装饰不影响课程权限、评分或学习机会。
- 不做充值、提现、转账交易市场、随机抽奖、消耗品或付费解锁课程。
- 服务端原子处理扣款与物品发放；余额不足、商品不可用、重复购买和网络失败均给出明确反馈。
- 首期物品按永久拥有处理；不可重复扣款购买已经拥有的同一物品。卸下只是取消装备，不销毁物品。
- 商店内提供“已拥有”，不额外增加独立背包桌面图标；身份、终端和空间分别筛选适用装饰。
- 装备与持有状态服务端持久化，刷新或跨设备一致；不能靠前端本地存储伪造购买及所有权。

## 6. 游戏与课后作业边界

- **游戏中心仅保留桌面入口及稳定入口页，明确提示内容后续开放。具体游戏由用户后续添加。** 不自行添加游戏、不开发游戏引擎、游戏奖励体系或内容上传平台，不用点击无反应代替占位说明。
- 课后作业最初只保留入口；用户随后于 2026-09-14 明确要求立即完成 T-119。终端现在直达独立的免登录《我的第一款游戏》固定表单和公开提交查看页，作业数据仍不进入钱包、课堂或公开空间。
- T-119 承接并实现《我的第一款游戏，课后作业.docx》的 11 个主题、3 张表格与可选图片；复杂模板、团队定向发放和受控管理仍留在 T-125，不反向耦合终端。

## 7. 视觉参考与实现边界

- 使用 `mini-silicon-valley-design`：蓝绿 MINI硅谷品牌、像素图标、复古未来设备外壳；正文中文保持清晰可读，暗色区域保证对比度。
- 参考 [98.css](https://github.com/jdan/98.css) 的复古边框/窗口与 [React95](https://github.com/react95-io/React95) 的组件组织；[WinBox](https://github.com/nextapps-de/winbox) 仅作为窗口交互参考，不预先承诺引入完整窗口管理器。
- 不整站导入冲突的全局 reset、不复制其他项目 Logo 或未核实授权的资产。组件和资源依赖实施时再选型核验。
- 首屏只加载必要内容，其余应用按需加载，避免再现 Studio 初次等待近 20 秒的问题。
- 与 T-088 的触摸、软键盘、横竖屏、会话隐私和真实设备验收，以及 T-118 的表单留白规范对齐。
