# Admin 学员账号中心：CRUD、昵称、备注、密码与像素头像

## 2026-09-14 最新对齐（优先于原始称呼）

- 用户补充 `/account/` 应是后台式账号管理界面，支持学员 CRUD、备注、ID、账号、昵称、密码管理和随机像素头像；随后将管理角色明确为 **Admin**。权限不绑定某个具体人的账号，也不自动授予所有课堂 DM。
- [详细设计：Admin 学员账号中心](../../../docs/ADMIN_STUDENT_ACCOUNT_CENTER_DESIGN.md) 包含页面组织、逻辑字段、密码边界、CRUD 和验收。本轮只设计记录，尚未实施。
- Admin 访问 `/account/` 默认进入“学员管理”，另保留“我的账户”页签；非 Admin 继续管理自己的账户。设备“添加账号”与后台“新增学员”是不同操作。
- 原始用户引文和文件名保留便于追溯；以下实施要求已按最新 Admin 角色修订。

## 用户原始需求

> 并且可以新增学员和快速设置账号名称和密码，当前这种编码 - id 的方式是可以的，比如当前已经有 01～04 的 ID，可以基于这个在后续新增别名和密码管理，这些账号都可以由 DM 统一管理。所以还需要考虑账号管理中心的模块，主要是 DM 进行管理，这个也是后台的功能。可以在这个下拉栏加入入口。

## 1. 账号身份与别名分离

- 保留现有 `msv-student-01`～`04` 这类编号式登录名，不要求为了可读性重建或重命名已有账号。
- 底层稳定 account/profile ID、编号式登录名、可编辑别名（显示名称）、课堂学员席位是不同概念；“学员 3”席位不等于某个固定账号 ID。
- Admin 可快速为现有账号设置或修改别名；界面同时显示“别名 · @编号式登录名”，无别名时沿用默认名称。
- 修改别名不改变登录名、底层 ID、Membership、课程进度、作品归属或权限；搜索同时支持别名和编号式登录名，与 T-113 对齐。
- 不通过给有历史记录的账号改别名，静默把账号及其记录移交另一个学生。新学生与已有账号的选择必须明确。

## 2. 新增学员与课堂配置衔接

- Admin 可在后台新建学员账号，快速填写别名和初始密码，保存后给出可核对的编号式登录名与创建结果；学生不必自行注册。
- 延续现有编号规则分配未占用的编号，例如在可用时继续 05、06；以服务端唯一性校验为准，不从浏览器列表长度推导，也不能覆盖已有 01～04。
- 优先复用既有托管账号创建、账号存储与审计能力；不要另建一套只存在于课堂表单或浏览器本地的学员身份。
- 从 T-113 学员选择器可进入“新增学员”。创建成功后刷新可选项，并让操作者确认/回填到刚才操作的席位；其他席位、人数、课程版本和已填配置不丢失。
- 取消新增或创建失败不改变原成员选择；账号创建成功但加入课堂失败时，应说明账号已存在并允许重新选择，不能盲目再创建一个重复账号。
- 创建账号与把账号加入某个课堂是两个明确步骤。是否允许修改已经开课的成员，沿用现有 Room 规则，不通过本单绕过冻结或权限约束。

## 3. Admin 统一管理别名和密码

- 后台列表可按账号编号/登录名/别名搜索，清楚显示账号状态和授权范围内的课堂归属。
- 提供明确的“修改别名”“设置初始密码／重置密码”操作，显示目标账号并确认结果；不能让“保存别名”顺带重置密码。
- 密码管理是设置新密码或重置，不是查看已有明文密码；复用当前认证系统的密码策略、安全存储、失败限制与会话处理。
- 操作前提示密码变更对该学员登录及会话的影响，完成后遵循现有会话失效规则；不要静默影响其他学员或 Admin 自己的登录。
- 如创建/重置后需要展示凭据，只在明确的受控交付流程中短暂显示，不将密码留在账号列表、URL、日志、审计正文、导出文件、代码或 TODO 中，也不默认把所有学员密码保存在浏览器。
- 使用隔离账号验证密码设置与登录，不修改现有用户或学员的真实密码作为冒烟测试。

## 4. 后台入口与权限边界

- 右上角下拉菜单为 Admin 提供清楚的 **“学员账号管理”** 入口，进入 `/account/` 管理视图；同一账号中心内保留“我的账户”，与设备账号切换和“＋添加账号”分别标注用途。
- 后台工作台也提供同一入口，避免只能通过某个页面的菜单进入；路由与 T-109 的对内信息架构统一，不另造第二套管理页面。
- 本模块服务 Admin，复用现有管理员授权模型。普通导师、仅具备课堂 DM 权限的账号和学员，不自动拥有后台学员 CRUD 权限；前端与 API 均检查。已有受限的密码找回协助能力不在本单中擅自撤销或扩大。
- “某课堂的 Admin DM”不能自然扩展为“可管理全平台所有学生”。列表查询、别名修改、密码重置与创建后的管理归属都必须由服务端验证授权范围，关联 T-105。
- 同一账号可关联多个课堂，密码通常是账号级凭据而非课堂级配置。实施前明确跨课堂账号的管理范围、修改影响，以及尚未加入课堂的新账号归属，不能因可见一个席位就任意修改别的团队学生账号。
- 学员账号管理与 DM 委派权限分开；被委派的 DM 不能借本入口向他人授予 DM、平台管理员或更高权限。是否拥有本模块具体操作权沿用明确的授权契约，不用“所有导师”代替权限校验。
- 若内部管理用户无法执行某操作，给出范围/权限原因与合法下一步，不出现按钮无反应或功能无故消失；不通过自动提权消除提示。
- 新模块和菜单使用 `mini-silicon-valley-design`，与现有新 UI 一致；账号菜单普通点击可进入，不能依赖 Ctrl/Cmd 点击。

## 验收

- [ ] Admin 能从右上角菜单及后台工作台进入 `/account/` 学员管理视图；“我的账户”、设备登录账号列表和“新增学员”用途明确区分。
- [ ] 保留 01～04 的原登录名和底层 ID，可设置别名并在后台、T-113 搜索和课堂成员展示中看到正确名称，不改变历史归属。
- [ ] 新建学员可一次设置别名与初始密码，生成未占用编号；并发或重复操作不覆盖已有账号，失败有明确提示。
- [ ] 从学员选择器新建后回到原席位选择新账号，不丢失其余配置；取消/失败不误分配。
- [ ] 用隔离账号验证初始密码登录、单独修改别名不改密码、重置后旧密码失效及会话策略；页面和日志不泄露密码。
- [ ] Admin、仅课堂 DM、委派 DM、普通导师和学员分别按授权契约验证；课堂身份不自动授权后台 CRUD，前端隐藏不能替代服务端拒绝越权请求。
- [ ] 多课堂账号的别名/密码变更范围明确，不能误改其他团队账号；学员管理不能绕过 DM 委派限制。
- [ ] 搜索无结果、无权限、已停用账号、提交冲突和网络失败有明确状态，不静默清空已填表单或伪报成功。
- [ ] 提供实现、隔离测试、部署和入口复验各层证据；不得以“菜单已加入”代替账号创建与管理链路完成。
- [ ] Admin 可新增、查询及修改学员备注；非授权 API、学员页面及课件不泄露管理备注，密码不得写入备注。
- [ ] 新账号自动获得随机像素头像，种子持久化，刷新及跨设备一致；可显式换头像，取消编辑不改变原头像。
- [ ] 隔离账号完成真实删除链路；有历史依赖时明确阻止删除并说明原因，可停用但不以停用冒充 D 已完成。删除不破坏课堂、作品和学习记录，不影响其他账号。

## 5. 新增字段与 CRUD 范围

- 复用账号 ID、唯一登录名、displayName、状态及 Membership。补充管理端备注、持久化随机头像种子；详情按已有来源展示创建/更新时间和最近登录。具体字段与最新 schema 对齐，不重复创建账号真值。
- 管理列表包含头像、ID/编号、账号、昵称、备注摘要、状态和操作；提供 ID/账号/昵称搜索，分页查询不能只过滤已加载的一页。
- 密码在表单中作为初始设置/独立重置动作，不是可读取的明文字段；首次改密、强度和会话策略沿用认证系统。
- 第一版创建后保持 ID 和登录账号只读，用昵称满足日常改名；不把既有学员账号改名后交给另一个学生继承历史记录。
- 删除入口需检查权限、账号类型、依赖及影响，符合条件才执行；有依赖必须给出阻止原因及停用替代。不级联删除课程记录、不删除导师或 Admin、不把课堂移除或设备退出当成删除账号。
- 与 T-118 共用表单留白规范；采用最新 MINI硅谷 UI，管理页突出列表与操作，不增加无关大标题和入场弹窗。
