# 课堂添加学员支持账号搜索选择

## 用户原始需求

> 添加学员需要能够使用搜索账号的功能。

用户截图为课堂创建配置中的“学员 1～4”账号选择框，当前选项显示“学员 01 · @msv-student-01”等账号。对应入口为 `/classroom/#factory`。账号增多后，应能输入关键词定位账号，不必在长下拉列表中逐个寻找。

## 目标行为

- 每个学员席位的账号选择器支持输入搜索，可按账号名（如 `msv-student-03`）或显示名称（如“学员 03”）匹配；支持部分关键词，账号名前的 `@` 不应导致找不到。
- 搜索结果同时展示显示名称和唯一账号名，区分同名学员；选择后保存稳定账号 ID，不用搜索文本或显示名称代替账号身份。
- 选中、清空搜索或搜索其他席位时，保留已选学员、席位归属及其他已填课堂配置；修改“学员 3”不能改变其他席位。
- 已被当前课堂其他学员席位选中的账号要明确标识并阻止重复分配，沿用现有成员唯一性规则。
- 明确区分“正在搜索”“没有匹配账号”“加载失败/重试”和“已选中”；搜索失败不清空已有选择。
- 仅在现有授权范围内搜索可分配的学员账号，不借此公开全站账号、不放宽成员管理权限；不把导师或不可分配的账号误当学员加入。
- 账号较多时也能找到授权范围内的匹配项；若账号数据分页或限量加载，不得仅搜索已加载第一页却提示全局无结果。具体采用本地过滤或服务端搜索由实现依据现有 API 决定。
- 复用同一选择组件覆盖 TEST / Production 工厂中已有的学员配置入口；已有成员管理页面若提供添加/更换学员，也应使用相同搜索方式。无需为本单另造成员管理系统。
- 适配课程配置支持的实际学员人数，不硬编码四个搜索框；沿用 `mini-silicon-valley-design` 的统一 UI，支持键盘及触摸选择。
- 2026-09-12 用户补充新增学员及账号管理需求，另由 [T-114](114-dm-learner-account-management-center.md) 承接；2026-09-14 明确管理角色为 **Admin**。搜索选择器仅为具有账号创建权限的 Admin 提供“新增学员”入口，完成账号创建后回到原席位确认选择；新建取消或失败不丢失原表单。别名修改后也应可按新别名搜索，仍绑定同一账号 ID。仅具备课堂 DM 权限者仍可按既有授权搜索、选择账号，不因此获得后台 CRUD 权限。

## 验收

- [ ] 输入 `student-03`、`@msv-student-03` 或“学员 03”，能定位并选择对应账号。
- [ ] 两个显示名称相同的账号可通过唯一账号名区分，保存的是所选账号的稳定 ID。
- [ ] 给学员 3 搜索/更换账号时，学员 1、2、4 的选择及其他表单内容保持不变。
- [ ] 2、4、6 名学员配置均可逐席位搜索；重复选择同一账号时有清楚提示并阻止提交重复分配。
- [ ] 无结果、加载失败、清空搜索、取消选择均有明确行为，不静默丢失已填内容；快速输入时旧响应不会覆盖新关键词结果。
- [ ] 超过一页的授权账号集合也可正确搜索，键盘和触摸均能完成选择，结果列表不被父容器裁切。
- [ ] 隔离测试中创建课堂后，成员列表与所选账号 ID / 学员席位一致；后端仍校验账号可分配性、权限和重复成员。
- [ ] 与 T-114 联调“搜不到 → 新增学员 → 回填原席位”；其余席位和课程配置不变，无管理权限的用户不能借搜索入口创建账号。

## 边界与后续动作

- 本单是“为课堂选择学员账号”，不是 T-106 的“切换当前登录账号”。账号创建、别名及密码管理交由 T-114 统一实现，本单只集成入口和创建后的选择回填，不自行实现第二套账号系统；基础搜索不必等待整个管理模块完成。
- 下一步在 canonical 最新工程中核对 FactoryPanel 的学员选择器与账号查询接口，再实现搜索选择及回归测试；不要依据落后的本地源码覆盖已上线的 T-111。
- 本轮仅记录需求与验收要求，尚未实现、部署或修改任何实际课堂成员。
