# 真正的已登录账号列表与多账号会话切换

## 用户澄清

> 切换账号应该是有已经登录的账号列表可以选择啊，为什么直接退出登录了？

用户需要的是本浏览器已经成功登录的多个账号之间快速切换，不是退出当前账号后重新输入另一账号的密码。本条纠正 T-087「模式 A」的需求理解；原实现完成回执仅说明旧方案已实现，不代表满足这次澄清。

## 已核对的原因

- T-087「普通切换账号」明确要求先退出服务端会话，再返回登录页。
- `app/components/AccountMenu.tsx` 的 `logout(mode)` 对 switch/logout 均调用 `POST /api/auth/logout`，区别只是登录页查询参数。
- 因而目前没有真正的多账号会话列表；不是浏览器偶发失效，也不能通过仅修改按钮文字解决。

## 正确交互

右上角账号菜单提供：

1. **已登录账号列表**：显示姓名、用户名、角色、当前使用标记及会话是否过期。
2. **点击切换**：目标账号会话仍有效时直接切换，不退出其他已登录账号、不重复索要密码。
3. **添加账号**：验证另一账号后加入列表；取消或登录失败不影响当前账号。
4. **会话过期**：标明需要重新登录；仅对目标账号重新验证，不能先把当前有效账号退出。
5. **退出当前账号**：明确撤销该账号在当前浏览器保存的会话，其他账号不自动退出，回到可用账号选择界面。
6. **退出此设备所有账号**：独立操作并确认；不与普通切换共用行为。

列表只包含本浏览器已验证的账号，不是平台全部用户列表，也不等于授予管理员任意免密登录他人的权限。移除列表中的账号不是删除平台 Account 或课堂 Membership。

## 实现约束

- 后端维护当前浏览器可切换的有效会话集合和当前身份；具体存储方案在实现前审查，不直接依靠前端 userId 切换身份。
- 不保存明文密码，不把可用会话令牌放 localStorage、URL、页面源码或日志；使用服务端验证、受保护 Cookie 和同源写入校验。
- 每次切换重新校验目标会话、账号状态、首次改密要求和访问权限；被停用、过期、已撤销账号不能继续切入。
- 真账号切换与 Test impersonation 是两种不同能力；不能通过普通账号列表放宽模拟身份的课堂范围或管理员限制。
- 切换后清理或隔离旧身份的课程、私密卡、钱包、提交、查询缓存和未完成请求，拒收切换前的迟到响应。
- 当前页面若有未保存工作先提醒，不静默丢弃或以新账号提交旧账号草稿。草稿如保留，必须绑定原账号且仅该账号可恢复。
- 建议本轮同一浏览器上下文只有一个当前活跃账号；其他标签页同步身份变更并停止旧身份写操作。多标签同时使用不同账号属于另一能力，不偷偷通过混用 Cookie 实现。
- 当前页面目标账号无权访问时跳到其有权访问的首页并说明；不要沿用上一个账号的管理页面权限。
- 列表只做最小身份展示；共享学员设备上提供清楚的「退出此设备所有账号」，避免下一使用者拿到前一人的有效会话。

- [x] 点击「切换账号」先显示列表，未选目标时不调用退出接口、不撤销任何有效会话。
- [x] 添加 B 失败或取消、B 已过期时，A 仍可正常使用。
- [x] 退出 B 后 A 仍有效；退出全部后旧会话全部失效，浏览器后退不能恢复访问。
- [x] 停用、改密或撤销目标会话后，列表及时反映失效且服务端拒绝切入。
- [x] A/B 在 Studio、Classroom、课件库之间切换，姓名、角色、权限和数据完全对应目标账号。
- [x] 多标签、慢请求、未保存编辑、Test 模拟身份均不导致串号、越权或误提交。
