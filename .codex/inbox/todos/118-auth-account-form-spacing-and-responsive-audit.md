# 检查并修复登录及账号表单的卡片内边距与响应式布局

## 用户原始需求

> 所有这些登录框之类的，padding 可能都有点问题，检测并修复，添加 todo。

截图是“进入你的世界线 → 添加账号”登录表单：卡片有浅色背景及右下阴影，但标题、说明、字段标签、输入框、操作按钮几乎直接顶到卡片左右边缘。需检查共用表单，而非只给这一张截图打补丁。

## 1. 本轮已确认的样式链

源码基线：canonical 仓库 `CyberFork/miniSiliconValley`，本轮 main commit 为 `d4bc1605757336e04c6bc8d6f682ab8d16f5e221`。

- `app/auth/AuthShell.tsx:33`：`formPanel` 包裹登录、注册、找回及重置页面的内容。
- `app/auth/auth.module.css:86–87`：`formPanel` 有响应式 padding，但内部 `authCard` 只声明 `width: min(100%, 520px)`，没有卡片自身的 padding。
- `deploy/minisv/site/ui-theme.css:215–219`：adventure 主题给 `authCard` 添加浅色背景和偏移阴影，却没有补充卡片内容的留白。因此外层页面间距存在，不等于新出现的视觉卡片有内边距，和截图贴边现象一致。
- `app/auth/AuthForms.tsx` 多种表单共用 `authCard` / `authForm` / `field`；修复应覆盖所有使用者。
- 输入框本身在 `auth.module.css:151–161` 已有 `padding: 12px 14px`，不能把问题误诊为所有输入框都没有 padding。
- 密码“显示/隐藏”按钮绝对定位于输入框右侧；未在本轮看到该输入框为按钮专门预留右侧空间。长密码/显示明文时是否被覆盖属于待视觉验证项，不能直接当作截图已经证明的问题。
- `AccountClient.tsx` 的账户资料、更新密码、设备及 DM 密码协助卡片复用同一 CSS 模块，需回归检查，但不能未经验证就声称每一张卡都有同样缺陷。

本轮匿名读取线上 release 信息返回 403，未核实线上构建身份或浏览器计算样式。以上为用户截图与最新主分支源码证据；实施时还需在真实页面确认最终级联和实际生效样式。

## 2. 检查与修复范围

- 登录：无账号、已有账号、添加账号、重新验证、取消返回列表、错误/加载/成功提示。
- 注册、找回密码说明、有效/失效重置链接、首次登录强制改密页面。
- 本设备账号选择列表和相关操作区；右上角账号菜单内的卡片、分隔线与按钮。
- 个人账户中心的资料/密码/设备管理；已有 DM 学员协助表单，以及 T-114 新增后台学员管理时使用的相关表单。
- 只修复已复现或共用样式明确影响的范围；不顺带重构认证、注册准入、密码策略、账号权限或课堂状态机。

## 3. 修复要求

### 分清四层间距

1. 页面到视口边缘的外侧留白及安全区域。
2. 视觉卡片边框/背景到内部内容的 padding。
3. 标题、说明、Tab、表单字段、提示、按钮、页脚之间的 gap/margin。
4. 输入框和按钮内部文字、图标的 padding。

- 按 `mini-silicon-valley-design` 和已有设计 token 统一间距，不对全部表单/输入框粗暴追加相同 padding，也不让外层与内层双重叠加后把内容挤得过窄。
- 登录卡片明确拥有自身的内边距；标题、说明、标签、输入框和按钮共享稳定的内容对齐线。按钮可占满卡片内容区，但不直接顶到卡片外边缘。
- Tab、底部分隔线若有刻意通栏设计，必须与正文内容区区分清楚，不能让整张卡片的正文都成为零内边距布局。
- 调整卡片宽度与 `box-sizing` 的组合，保证新增 padding 后不超出父容器；同时保持表单可用宽度，不通过缩小整个页面或大幅缩小字体掩盖问题。
- 密码输入为“显示/隐藏”按钮保留足够空间；按钮可点且焦点框可见，不遮挡输入文字、光标或自动填充内容。
- 复选框说明、忘记密码、长按钮文字和错误提示在窄屏下合理换行；不能依赖横向滚动才能操作登录表单。
- 手机/Pad 软键盘展开后仍能看到并滚动到当前字段和提交按钮；处理安全区域、焦点轮廓及阴影，不用 `overflow: hidden` 掩盖溢出或裁掉交互。
- 修复样式源与实际发布引用，核对主题样式及其复制/生成文件的关系。避免只改 CSS Module，而部署主题覆盖后仍然无效；也避免直接篡改构建哈希产物。
