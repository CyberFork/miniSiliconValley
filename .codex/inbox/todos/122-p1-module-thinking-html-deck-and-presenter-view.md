## 2. 教学目标与内容边界

核心目标：让学员能把一个大问题拆成职责清楚、可协作并能重新拼接的模块，而不是只记住软件术语。

- 学员产出：一张“项目模块地图”与至少一张“模块接口卡”。
- 主线：具体情境 → 学生选择/动手 → 说明理由 → 导师命名概念 → 模块拼装与测试。
- P1 聚焦模块、用户路径、功能归纳、接口、高内聚/低耦合与协作；P2 再承接目标、边界和完成标准，不把完整立棍课程提前全部搬入 P1。
- 不把模块简化为页面、按钮或人数分工，不把“独立责任”误讲成完全没有依赖。通俗比喻与技术概念不完全等价之处需在教师提示中说明。
- 当前生活/课堂案例不是新增历史事实。校园订餐模拟不能冒充饿了么真实技术架构，不重建 T-090/T-091 的历史剧情。

## 4. 一份内容，投屏与教师两个视图

建议交付两个入口，而非人工维护两套互不关联的 PPT：

```text
同一套课件源内容与稳定 slideId
├─ 投屏视图 index.html       学生看到
└─ 教师视图 presenter.html   老师自己查看与控制
```

文件名为组织建议，正式路由复用现有课件平台，不为此另造教学系统。页面、教师提示和素材来自同一份编辑源；发布时按可见范围输出，不能让两套页码、题目或版本各自漂移。

### 投屏视图

- 16:9，展示标题、简短概念、图示、案例、问题、学生操作说明与交付要求。
- 题目先出现，讨论后由教师显式揭示提示或结论；不会一开始泄露答题依据或完整示范。
- 不出现发币操作口令、点名策略、备课扩展、判断标准及下一页预告等教师私用内容。
- 主结论和中文是真实 HTML，不烘焙进大图片；后排可读，不把 XMind 整棵树直接投屏。

### 教师视图

- 当前页投屏预览、下一页预览或标题、页码/目录跳转，以及上一页/下一页/逐步揭示控制。
- 当前页讲述要点、提问顺序、可能回答、可选追问、常见误区、活动组织、验收标准、建议时长及手动发币提示。
- 把“现场必看提示”和“备课扩展”分开，后者可折叠，避免课堂上读一大篇说明。
- 允许预览未来页但不立即改变投屏；只有明确的切页/揭示操作才改变观众画面。

### 内容分层示例：S08 高内聚

- 投屏先显示“通知模块里哪项任务不该出现？”及生成提醒、发送提醒、记录送达、修改积分四个选项。
- 教师端提示先投票、请学生解释，再追问“这一项为什么不是通知模块的责任”；保存可接受理由、误区及发币建议。
- 教师点击揭示后，投屏才出现本页结论；教师执行说明本身不投屏。
- 源提纲“导师备课扩展（不作为学员主线）”整体归教师资料；例如 AI 三种观察视角不默认塞进学生主线。

## 5. 双屏使用与同步边界

- 首期以**同一台老师电脑、同一浏览器、两个窗口**为主，不先开发跨设备远程遥控或第三个大型控制台。
- 老师在教师端点击“打开投屏窗口”，把投屏窗口移到投影仪/电视对应的扩展屏并全屏；教师窗口留在电脑屏幕。
- 系统必须使用**扩展显示**而非镜像。线上授课只共享投屏窗口，不共享整个桌面；单屏设备无法保证教师提示对观众不可见，需在操作说明中提示。
- 双端同步课件 ID/版本、当前 slideId 与揭示步数；同一台机器开两套课件时按独立播放会话隔离，不能互相抢翻页。
- 初次打开、刷新和重开投屏窗口应恢复当前播放位置；连接失败给出明确状态及重开操作，不要求教师逐页手动对齐。
- 浏览器拦截弹窗时提供显式重开方式，不自动重复弹窗；全屏遵循用户点击触发。
- 课件翻页与揭示只控制本 PPT，**不自动推进 Classroom Block、中控状态或发放资产**。

技术参考：[reveal.js Speaker View](https://revealjs.com/speaker-view/) 提供单独教师窗口、逐页提示、下一页预览与计时的成熟交互范式。是否复用该库由实施时评估，不为制作一套课件预先承诺整站换播放器。

## 6. 教师资料与学生可见范围

- “教师端不投屏”是视觉隔离；“学员不能读取教师资料”是另一个权限问题，不能只依赖 CSS 隐藏、未公开链接或前端角色判断。
- 学员可访问的 HTML、JSON、静态 bundle 和打印输出中，不携带教师专用提示；教师资料经现有权限检查后加载或作为独立教师材料交付。
- 保留一个编辑源，构建时按观众/教师分别输出；不要因为用了双视图就维护两份独立课程真值。
- 教师讲义和学生课件分别导出，学生 PDF 不夹带备课页、口令和教师答案说明。
- 现有课件库允许学员看课件，不等于允许学员读取 presenter 资料。上线时须核对路由和静态资源访问边界，未满足前不能误称“教师私有”。

## 7. 互动与硅谷币：提示，不做自动发币系统

- 最新 XMind 有每 2～4 分钟互动、参与/理由/证据助攻币、团队奖、每页发币提示和公平参与 SOP，应纳入教师侧，不丢掉新增内容。
- 具体数额作为当前源提纲中的课堂建议保留，不当作平台已经配置好的奖励规则；其中不同活动上限或计分方式需在备课阶段核对一致性。
- 按用户对 T-124 的确认，由导师手动发放；PPT 点击、答题、切页不自动调用钱包加币。
- 若后续提供发币入口，跳转/复用既有授权管理能力，不在本课件实现第二套余额、奖励规则或假入账提示。
- 个人币和团队币分开；公平原则包括不因答错扣币，不只奖励抢答快者。S16 的“押一个点”按观察预测理解，不做赌币或扣款。
- 互动先支持口头、举牌、纸卡、便利贴及教师控制的展示。不默认新增在线测验、拖拽评分、自动判分和剧本状态机。
