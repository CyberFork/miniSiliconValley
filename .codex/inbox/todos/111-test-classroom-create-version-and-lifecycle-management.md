# 补齐多测试课堂的新建入口、版本选择与归档删除管理

## 用户反馈

课堂中心只看到一场 r9 测试课，用户希望测试新保存的 r12，却找不到创建入口；旧测试课堂也没有删除入口。

## 源码核对

- `createClassroomInstance()` 每次生成独立的 roomId、teamId、factorySeed；未发现只能创建一场 TEST 的全局限制。列表只显示一场不能证明系统限额为一场。
- `ClassroomHub.tsx` 的 `FactoryPanel` 位于 TEST/PRODUCTION 列表之后，仅在有 Studio 权限且 bootstrap 加载成功时出现。
- 初始加载先取课堂列表，再并行取完整 Studio bootstrap 和账号；`setBootstrap` 要等两者都成功。任一依赖失败可能出现“有旧课堂列表，但无创建表单”，页面只有顶部通用错误，缺少就地原因与重试入口。
- 没有在 TEST 区标题旁放显眼的新建入口。视图回执缺失时当前版本还会被 eligible 过滤，关联 T-108。
- 当前 `RoomCard` 只提供进入课堂，当前 `/api/platform/classrooms` 为列表/创建；本轮未发现当前平台提供课堂删除/归档的完整 UI/API 链路。
- 旧 `ClassroomApp.tsx` 存在 legacy archive-room 操作，不等于现行 ClassroomInstance 流程已经有可用的归档入口，不能直接套用后宣称完成。

本轮依据截图和源码记录；未读取该用户线上完整响应，不能断言入口消失具体由哪一个请求或权限条件导致。

## 目标行为

### 1. 多场测试独立存在

- 同一课程允许有 r9、r12 等不同版本的测试课堂，也允许同一 exact 版本创建多场，用于不同人数、账号组合和发牌 seed 的测试。
- 每场显式展示 classroomId、courseId/revision/digest、人数、运行状态和更新时间；默认名称可带课程版本，避免都叫“测试课堂”无法分辨。
- r9 旧课堂始终锁定 r9，不因编辑器保存 r12 或点击“重置”而被静默升级。
- 新版本通过自己的有效视图验收后新建 TEST；r9 的回执不能冒充 r12 的回执。

### 2. 新建与版本入口始终可发现

- TEST 标题/列表顶部提供“新建测试课堂”，不要求用户先滚过全部课堂或找页面底部的工厂。
- 该入口按权限显示；缺课程/回执/账号等条件时显示具体原因与下一步，而不是整个创建区消失。
- 流程明确为：选择课程与 exact 版本 → 完成该版本视图验收（如缺）→ 配置人数/成员/课件 → 创建独立 TEST。
- r12 待验收时也能看到 r12 和“去验收 r12”；不回退到 r9，也不误导用户删除 r9 才能测试 r12。
- 从发布页的 r12 跳入创建时，完整保留 r12 courseId/revision/digest 与视图回执；响应迟到或指针变化时明确提示，不静默换版本。
- 课程、账号或课堂列表加载失败要分别反馈、可分别重试；保留已经显示的课堂和已填表单。
- 与 T-109 对齐：长期入口归于 Studio 的内部测试/课程管理，不再让普通学员的正式课堂入口承担测试管理。

### 3. 旧测试课堂的归档与删除（已决策并实现）

- 建议先提供“归档测试课堂”：从活跃列表移出，保留深层“已归档”入口、版本、进度及历史证据，归档后只读。
- 区分“重置同版本重新测”“归档不再使用”“永久删除测试数据”，不能三个按钮都只是清空进度。
- 永久删除属于破坏性动作；明确授权、二次确认和影响预览，不因本条反馈直接执行删除。
- 归档/删除只作用于指定 TEST 实例及明确属于它的数据；不删除全局账号、课件包、课程版本、其他团队 Membership 或正式课堂。
- 已关联 UI 回执、Released、正式课堂或审计证据的 TEST，必须先判定依赖。建议禁止硬删，保留只读归档；不能让既有发布证据被悬空引用或悄悄改写。
- 明确归档后回执是否继续可用于新的发布/开课的政策；历史证据保留与当前可用性分开建模，不能不经设计就统一抹掉或认定有效。
- 权限按当前 Room 管理契约设计，不能让“任何导师”删除其他团队课堂，也不能只在前端隐藏按钮。
- 并发运行/归档/删除需服务端原子校验与可审计结果；出现冲突应中止并解释，禁止部分删除。

## 验收

- [x] 同一账号可以找到新建入口，同时保留 r9 旧 TEST 并创建 r12 新 TEST。
- [x] r12 无回执时明确引导验收 r12，有回执返回后继续已填配置，不自动改成 r9。
- [x] 同版本不同人数/成员组合可分别创建 TEST，实例状态与数据互不影响。
- [x] 课程/账号加载失败、无权限、无课程、回执失效均给出相应提示，不只剩旧课堂卡片。
- [x] 普通点击即可打开新建、版本验收、进入课堂和归档列表；纳入 T-110 的 Enter/触摸/Ctrl/Cmd 回归。
- [x] 旧 TEST 有明确的重置/归档管理入口；归档后可从历史列表找到，恢复策略与可写性明示。
- [x] 永久删除经设计评审确定为不提供；无依赖/有回执依赖/权限不足/Production/并发冲突均使用隔离数据覆盖，历史证据不会悬空。
- [x] 不改写 r9 课程数据，不复用其回执冒充 r12 验收，不删除参与多个课堂的共享账号。

本单先记录调研与实现要求，尚未新增或删除线上课堂。T-108 负责创建门禁可操作性，T-110 负责普通点击与加载性能，本单负责多测试实例入口及其生命周期管理。

## 实施记录（2026-09-11）

- TEST 标题旁已增加原生 `#factory` 新建入口；课堂卡完整展示 classroomId、exact revision/digest、人数、lifecycle、run generation 与更新时间。
- 默认名称带课程名和 revision；同 exact 多课堂、新 Candidate 多 revision 并存均由真实本地 D1 测试验证，旧课堂 exact 引用不漂移。
- 新增 `classroom_archives` 不可变保留标记与 `POST /api/platform/classrooms/{id}/archive`。归档只允许真实登录的本课堂 Admin DM，只作用指定 Test。
- 归档使用 `runId + resetGeneration + scriptVersion + idempotencyKey`，五个事务节点逐点注入失败均完整回滚；数据库触发器拒绝 Production、更新和删除归档记录。
- 归档后剧本、作品、成员、资金和课件仍可读取；解锁、结束、reset、提交、审核、成员/账号/Test 身份管理与新 UI 回执均由服务端拒绝。
- 已有 UI 回执保留为历史证据但动态失效，不能继续发布或创建 Production；Studio 不把归档 Test 计入当前验收状态。
- 永久删除和原地恢复明确不提供；历史卡可携带原 exact 引用创建全新 Test。
- 自动化通过 TypeScript、ESLint、134 项平台测试（新增测试后的最终数量以本轮提交证据为准）、生产构建与编译后 ClassroomHub 浏览器回归；未访问生产数据、未代签人工回执。
