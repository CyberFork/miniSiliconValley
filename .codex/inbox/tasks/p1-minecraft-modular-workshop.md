# TASK-P1-MC-WORKSHOP

## 任务摘要

将开发导师 P1《模块思维》改成儿童能看见、操作和验证的课件：以 Minecraft 的场景与熟悉要素承载教学，再在课件内提供原创方块工坊，让学生搭出固定规格的轮子、推进器并保存为模块，用模块组成火箭推进小车，在有重力和起伏地形的场景中亲自试驾。

Three.js 展示区域需支持窗口内展开和全屏，解决当前操作画面过小的问题。保留原有教师／投屏双视图和 P1 三项学习成果。

**阶段 A 与阶段 B 可玩样段已实现；当前停在任务要求的用户亲自试玩关卡。阶段 C 完整 P1 改造及最终人工验收尚未完成，未部署或替换线上 P1。**

## 1. 决策依据与优先关系

### 用户明确要求

> 给小朋友的课件，一定要具象！具象！再具象！

> 先改 P1。

> 需要把现在既有的课件知识点和 MC 本身的游戏要素进行融合。

> 只需要在课件中进行操作即可。甚至可以在课件中直接开发一个方块编辑器。用来自行拼装并展示。可以选择几个方块拼接为轮子（5 个同方块）、推进器模块（两个金属＋一个燃料），然后保存模块。

> 改轮子大小是不是太复杂了，我感觉其实不需要这个。还有就是可以拿中间的模块拼接为一个火箭推进的小车，可以让我玩一玩，在有重力的不平的场景中展示。另外就是 three.js 的展示窗口可以扩展大小，当前的课件的展示窗口太小了。

用户随后同意收敛范围并要求记录，最新选择为 Task，而不是再记一条轻量 TODO。

### 本单覆盖的旧建议

- 不采用“灯与线路作为整节主线”的旧方案。红石不作为必须先学的知识。
- 不做轮子尺寸调整、缩放参数或变尺寸轮胎的教学活动。
- 不强制保留变形玩具、乐高、失物招领、订餐等旧案例在学生主线；保留其知识点和历史课件版本。
- 也不把方块工坊的轮子和推进器误说成 MC 原生配方。最新确认包含 **MC 原生机制举例＋MC 风格原创课堂拼装** 两层。
- 旧 [Minecraft 初稿](../../../docs/plans/P1_MINECRAFT_CONCRETE_REDESIGN_2026-09-21.md) 中灯主线、26 节点具体脚本等为历史讨论，不是本任务的直接执行稿。

### 不变的课程目标

- 仅开发导师 P1，独立 120 分钟；WHAT／WHY／HOW 组织方式保留。
- 最后每位学生交付：自己的游戏模块地图、关键模块详细设计卡、正常／异常验证记录。
- 模块六字段：职责、输入、处理规则、输出、接口、正常／异常表现。
- 学生不要求写程序。MC 机制不熟悉时，教师可现场用简短操作介绍。
- 工坊是教学手段，不能取代个人游戏设计和互查，也不能演变成一节纯赛车游戏课。
- P2、其他导师、正式课堂状态机、账号、钱包和作业后台均不在范围内。

## 2. 成功后的完整体验

1. 学生在具有 MC 辨识度的场景中认识整体、基础方块和具有明确用途的组合。
2. 在课件内选择、放置方块，搭出固定轮子与推进器示意。
3. 选中组合，填写名称和一句职责，保存为模块。
4. 模块库显示刚保存的真实组合，可以整体选择、移动、旋转、重复放置。
5. 将多个轮子和推进器接到简单预制车架上，形成同一辆火箭小车。
6. 切换试驾，小车进入有重力、碰撞和起伏地形的场景，用户可以操作推进、刹车和重置。
7. 回到拼装调整允许的连接或方向，再用相同路线复测；不涉及轮子大小调整。
8. 从实际观察中总结分工、复用、连接、整体测试，再迁移到学生自己的游戏三项成果。

不能在步骤 5—6 偷换为另一辆预制车；模拟必须使用当前作品中的模块及其允许的装配状态。

## 3. 内容改造要求

### MC 原生例子与已有知识点

- 建筑中的方块、结构部分、房间与基地：解释观察尺度与部分／整体。不能把任意圈出的一堆方块都叫好模块。
- 工作台、熔炉、箱子：解释职责、现成能力和使用条件。合成材料生成物品，与组合多个功能单元分开讲。
- 熔炉的输入、处理、产物和工作状态：解释正常操作、未满足条件、观察与复查。
- 箱子／漏斗／熔炉的简单配合：在需要时解释交接和协作，不堆复杂自动化或红石细节。
- 玩家操作、世界变化、掉落与拾取／背包：帮助学生从世界中物件的组合，迁移到游戏功能分工。明确是教学划分，不声称是 Minecraft 源码的真实结构。

以上是可用案例池；按知识点选择少量连续场景，不要求每项都扩成一个大演示。采用的原生机制应按确定的游戏版本核验，不编造配方和行为。

### 工坊承担的中间层

必须有三个清晰操作层：

```text
基础方块：选择材料，摆放单块
功能模块：给组合命名、描述职责，作为整体保存和使用
完整作品：用多个模块装配火箭小车，并进入测试场景
```

- 保存模块后，必须实际体验整体选择、复用与装配，不能只播放拆散／组合动画。
- 允许查看已保存模块的内部组成，理解模块内部也由更小部分构成。
- 不要求现场改大轮子、重算轮径或填写复杂参数；这条支线明确取消。
- 避免把“摆出外形”自动解释为“已经拥有该功能”。明确模块的行为来自经过说明的课堂模拟规则。

### 学习节奏与教师提示

- 场景、问题、预测、操作、结果、短结论依次出现，术语最后补充。
- 首次出现物件，用“看用途、试一次、说一句规则”的方式带过，不新增 MC 入门课前置。
- 保存模块时先填名称＋职责；讲到设计时逐步补六字段，不用完整表格阻断初次拼装。
- 正常、异常、预测、实际观察分别记录。没有软件的个人项目可纸面走查，不能冒充程序测试。
- 保留原 120 分钟与约 40 分钟个人实践。先做试讲样段再调整逐页安排，不能直接把工坊时长追加到原 120 分钟之外。
- 保留末页复习、同伴互查及学生三项成果；更新所有例子、教师讲稿、打印材料和导出文件，避免旧订餐例子残留造成漂移。

## 4. 方块编辑器与模块库

### 首版必须具备

- 少量可辨认的材料类型，至少满足同种方块轮子、金属和燃料推进器。
- 网格放置、删除、选择组合、撤销与重做；鼠标与触摸均有明确操作路径。
- 建造操作与相机旋转／平移分开，避免拖相机时误放方块。
- 固定规格轮子：5 个同种方块；可用十字排列作为初始课堂示意，最终排列在样段中确定，不是 MC 原生配方。
- 固定规格推进器：两个金属方块＋一个燃料方块；明确其虚拟推进方向。
- 预制简单车架，清晰连接位置与吸附反馈。用户不需要从零建立完整车身。
- 保存模块时有名称、职责、组成预览和成功／失败反馈。
- 模块库能加载本次保存的模块、重复放置、整体移动与旋转；方向变化需与后续模拟一致。
- 保存作品、切换拼装／试驾时保留模块来源和装配状态。

### 数据与保存边界

- 区分模块定义与装配实例：同一个轮子可以多次使用，每个实例有自己的位置、方向和身份。
- 修改某个实例不能悄悄修改其他实例或已保存定义；如支持更新定义或另存新版，提供明确操作，不默认批量替换。
- 保存内容包含方块组成、名称、职责、连接信息和所采用的课堂行为类型，不能只保存截图或视觉模型。
- 首版为本机保存与 JSON 导入／导出，不新建服务端模块库、权限或作品发布后台。
- 明确提示“保存在此浏览器／此设备”，刷新恢复可用；清理浏览器数据、换设备的限制说明清楚。
- 模块与作品按课件版本和工作区标识区分；导入检查格式、数量上限、材料／行为类型，不能把文件当任意脚本执行。
- 保留原始导入文件，失败时不覆盖当前未保存作品；存储不可用或容量不足时明确提示并允许导出。

## 5. 火箭小车试驾

### 用户能实际操作

- 拼装／试驾是明确的两种模式。
- 提供推进、刹车、重置车辆；有屏幕按钮，不能只靠键盘。
- 首版使用短、清楚的测试路线，包含平地、缓坡、起伏和一处小落差。不建设开放世界或复杂赛车关卡。
- 相机可观察车辆，提供跟随／复位能力，翻车后能清楚恢复测试。
- 松开推进后停止施加推进力，不直接把速度设为零；刹车和重置是不同操作。
- 进入试驾前提示缺少必要模块、未连接或重叠等不能运行的装配问题，不能静默换成标准车。

### 真正的物理模拟

- Three.js 用于渲染；采用适当的物理计算处理重力、车体与地形碰撞、轮子接触及推进力。
- 车辆在坡面、下落与落地时受模拟状态影响，不沿预设轨迹位移动画冒充试驾。
- 支持实际出现滑落、翻车等结果；不要为了展示成功而强制车身水平或吸附在路面。
- 可以采用固定规格、简化的轮子与碰撞体，不要求五个外观方块逐个作为独立刚体，也不要求复杂悬挂或精确工程仿真。
- 模块的简化行为、视觉外形与碰撞模型在教师说明中交代清楚，不称为 MC 原版车辆物理。
- 推进方向、允许装配位置与行为一致；是否允许转向以及具体方向限制在样段中确定，首版不自动扩展完整驾驶系统。
- 物理步进与显示帧率解耦；切到后台、返回页面和重置时避免巨幅时间步导致爆炸、穿模或飞出世界。

### 对应教学问题

- 哪个模块负责推进？哪个负责支撑和滚动？
- 推进器方向变了会怎样？
- 各部分单独符合说明，装起来以后还能完成任务吗？
- 平地能跑，起伏路面上实际表现如何？
- 改动之后，能否回到相同初始状态、同一条路线进行比较？

课堂只讨论虚拟装置和软件模块，不引入现实燃料、推进器制造或真实工程参数教学。

## 6. 展示区扩大、全屏与双视图

P1 本次新增和保留的 Three.js 区域采用统一机制：

1. **讲解状态**：三维场景占主要面积，旁边只有必要问题和少量说明。
2. **展开状态**：在当前课件窗口内最大化场景，收起非必要面板，不再弹第三个操作窗口。
3. **全屏状态**：可拼装和试驾，保留必要工具及明显退出入口。

必须检查：

- 改变实际 canvas 尺寸与相机视口，不是单纯 CSS 拉伸。
- 展开、收起、浏览器 resize 不重置作品、车辆、相机或模块选择；需要复位时由用户明确点击。
- 同页揭示与状态更新不反复销毁场景。首帧有稳定显示，避免此前切页白闪／黑闪问题回归。
- 拼装／试驾取得焦点时，方向键和空格不误触幻灯片翻页；释放操作焦点后课件键盘导航恢复。
- 触摸按钮、相机操作、放置操作不冲突；无 Hover 也能完成关键任务。
- 教师操作与投屏共享作品、操作和必要的模拟状态。确定唯一的模拟状态来源或可验证的同步方案，不能两边独立跑出不同结果。
- 展开教师预览不能把教师笔记投到学生端。教师资料继续物理分包并使用既有权限。
- 跨课件、跨 session 隔离，刷新恢复行为明确。
- WebGL／物理资源加载失败时提供静态讲解和重试／恢复路径，不能用降级动画冒充物理测试通过。
- 保留本地资源可用性，不临时热链引擎、贴图或授权不明的 MC 资源导致课堂断网失效。

## 8. 验收场景

- [ ] **AC-01 方块到模块**：五个同种方块形成固定轮子组合，保存后可整体选择、移动、重复放置，内部组成一致。
- [ ] **AC-02 推进器**：两个金属＋一个燃料构成课堂推进器，职责和方向可辨认，明确非 MC 原生配方。
- [ ] **AC-03 同一作品**：玩家拼装的小车直接进入试驾；删除、改变允许方向等操作不会被静默忽略或换成预制标准车。
- [ ] **AC-04 保存反馈**：刷新能恢复已保存作品；导入导出往返一致；非法文件与保存失败不丢当前作品。
- [ ] **AC-05 实例隔离**：移动或调整一个已放置实例，不使其他轮子或模块库定义同步变动。
- [ ] **AC-06 重力与地形**：车辆在小落差处实际下落并与地面接触；坡面表现来自物理状态，不是假动画或直线平移。
- [ ] **AC-07 可操作**：推进、刹车、重置和翻车恢复可以真实点击／触摸完成；推进停止与刹车效果可区分。
- [ ] **AC-08 可复测**：重置恢复同一作品与起始条件，能在同一路段比较修改前后结果。
- [ ] **AC-09 展开全屏**：拼装中和试驾中均可展开／退出，不丢状态、不拉伸、不重置相机、不出现白闪黑闪。
- [ ] **AC-10 按键隔离**：操控小车或编辑器时不误翻页，回到讲解后原有导航可用。
- [ ] **AC-11 双屏一致**：教师端操作后投屏显示同一作品和试驾结果，其他 session 不受影响，教师笔记不泄露。
- [ ] **AC-12 课程完整**：WHAT／WHY／HOW、六字段、三项成果和末页复习可逐项定位；新内容合计仍为 120 分钟试讲基线。
- [ ] **AC-13 具象性**：目标年龄学生无需先背名词，可以指出某模块职责、连接处，并讲出一次实际检查结果。
- [ ] **AC-14 范围控制**：无轮子大小调节、复杂悬挂、损坏系统、真实燃料系统、多人联机或新账号／作品后台。

- 支持设备与浏览器，确定可重复的最低测试环境，不凭空承诺帧率。
