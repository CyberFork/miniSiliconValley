# Mini Silicon Valley 道具、经济与学员系统规格 v1.0

> 文档类型：课堂道具清单＋游戏经济规则＋学员端／DM端产品需求
> 配套文档：[DM／导师操作手册](DM_MENTOR_MANUAL.md)
> 适用范围：实体课堂、学员小程序／WebApp、DM控制台、内容后台

## 0. 已锁定的设计结论

Mini Silicon Valley 不使用一个总分混合表示所有成果，而使用三个彼此独立的账户：

```text
个人声望 RP       = 我学会了什么、贡献了什么、别人为何愿意继续与我合作
团队资金 C        = 项目共同拥有、共同决策的商业货币
个人钱包 C        = 团队真实分配给个人、由个人决定用途的商业货币
```

它们不能互相兑换：

- 声望不能购买，不能转让，不能被骰子扣除。
- 团队资金不能由某个玩家单独占有或单独支出。
- 个人钱包不能购买学习成绩、正确答案或他人的发言权。
- 历史相似度不产生声望，也不直接产生金钱。

最终不设置“声望＋金钱”的单一总榜。结局同时展示：

1. **个人成长**：声望等级、代表性贡献和能力解锁。
2. **团队经营**：现金、资产、持续收入、负担和项目价值。
3. **个人商业结果**：个人钱包、被分配收益和再投入记录。
4. **共同作品**：世界线、五项任务成果与六分钟Demo Day。

这样既保留角色成长和商业经营，也避免“有钱等于学得好”或“会说话等于贡献大”。

## 学员可见经济边界

学生只看具体的钱箱、工具、任务结果和可执行选项；公式、抽象经济解释、PDMO方法论由导师端承载并在行动后命名。

## 1. 三账户经济系统

### 1.1 个人声望 RP：学习与协作的社会信用

声望是个人、长期、不可消费的成长记录。它回答：

> 这个Young Builder提供过哪些可信证据、完成过哪些行动、如何帮助团队作出更好的决定？

每节90分钟任务课最多获得12 RP：

```text
证据处理       0–2  能说明来源、可信度和适用边界
关系建模       0–2  能解释支持、限制、矛盾或因果关系
角色交付       0–3  完成本轮P／D／M／O承诺的可验收作品
有效支撑       0–2  对主导者的决定或作品产生实际改变
迭代与复盘     0–2  根据反馈修改，并说清认知变化
责任与记录     0–1  按时提交、维护账本或承担承诺后果
合计上限       12
```

计分证据必须指向课堂记录：信息讲解、连线理由、决策单、原型、测试记录、运营动作或复盘卡。DM不得凭“印象好”“发言多”加分。

声望不会被花掉，而是在达到门槛后永久解锁能力：

```text
0 RP    Young Builder     使用所有基础行动与公共信息渠道
5 RP    可信讲述者        每章1次，请DM补充某张卡的来源说明
12 RP   连接者            每章1次，发起跨队公开证据交换
20 RP   角色专家          装备1张P／D／M／O角色技能卡
32 RP   同行教练          每章1次，为队友提供一次有依据的重投支持
48 RP   世界线策展人      解锁进阶史料支线或主持一次复盘
```

解锁能力的边界：

- 只能增加行动方式、信息深度或协作机会。
- 不得跳过核心任务，不得直接看到答案。
- 主线所需信息不能被高声望玩家垄断。
- 声望高的玩家必须承担“让别人更能行动”的责任，而非获得更多支配权。

### 1.2 团队资金 C：项目共同商业货币

团队资金记录在团队金库中。1 C是一枚抽象资金币，不对应真实人民币。

每个新战役建议初始资金为10 C。团队资金通过以下方式获得：

```text
挑战项目收入
- L1／L2／L3基础收入：2／4／7 C
- 完整成功：基础收入+2 C
- 普通成功：获得对应基础收入
- 有代价成功：基础收入-1 C，并承担剧情后果
- 学习性失败：0 C，但获得洞察，剧情继续

验证收入
- 新增1条合格用户证据：+1 C，每章最多2 C
- 完成可重复验证的MVP结果：+2 C，每章最多1次

资产收入
- 在结算时按资产卡获得1–3 C持续收入
- 未支付维护费的资产不产生收入，并触发风险

外部资金
- 赞助、合同、预售或VC事件按卡片获得资金
- 必须同时记录条件、承诺、稀释或偿还要求
```

团队资金可用于：

- 购买工具、渠道、设施、团队能力、品牌和扩张资产。
- 支付服务器、制作、调研、营销、运营和维护成本。
- 购买专家服务、额外测试机会或新的行动路径。
- 向个人钱包发放本章工资／利润分配。

以下支出禁止：

- 购买正确答案、学习RP或史实提前揭晓。
- 购买“自动成功”或取消全部后果。
- 由一个人绕过团队决策直接支出。

### 1.3 个人钱包 C：商业结果与个人选择

个人钱包与团队金库使用同一种资金币，但账户归属不同。个人钱包的资金只能来自：

1. 团队发放的工资或利润分配。
2. 明确标记为个人报酬的NPC合同。
3. DM事先写入章节规则的个人商业事件。

个人资金不能因为课堂表现由DM凭空奖励；学习表现进入声望，不进入钱包。

个人钱包可购买：

```text
1 C  个性化徽章／名片皮肤       纯展示，不改变规则
1 C  支援券                     送给队友一次额外准备行动；不能直接转现金
2 C  角色工具许可               本章一次，增强已装备的角色技能
2 C  导师问询券                 向DM提出一个“方向型”问题，不能询问答案
3 C  调研通行证                 解锁一条可选深度信息支线
3 C  个人训练卡                 课后完成任务后，为下章增加一个行动选项
任意 返投团队                   转入团队金库，记录为“个人再投入”
```

禁止玩家间直接转账，避免索要、胁迫和场外交易。玩家可以购买支援券送给队友，也可以把钱返投团队。

## 2. 收入、成本与个人分配

### 2.1 钱从哪里来

每笔新资金必须有业务来源码：

```text
MISSION_CONTRACT   完成挑战获得的任务合同收入
USER_VALIDATION    用户验证、预售或测试奖励
ASSET_REVENUE      已有资产产生的持续收入
FINANCING          赞助、借款或VC资金；带条件
DM_ADJUSTMENT      仅用于纠错，必须写原因并留审计记录
```

“回答了老师的问题”本身不产生钱；形成可验证的项目成果才产生项目收入。

### 2.2 钱花到哪里

每笔支出必须属于下列类别之一：

```text
RESEARCH       调研、数据、专家与用户访问
PRODUCT        原型、测试、设计和研发工具
MARKET         渠道、传播、品牌和获客
OPERATIONS     人员、流程、交付与服务
MAINTENANCE    已有资产的维护义务
DISTRIBUTION   从团队金库转入个人钱包
```

### 2.3 每章结算顺序

DM严格按以下顺序结算，不能先分钱再补成本：

1. 记录本章项目收入。
2. 支付已经发生的直接成本。
3. 支付资产维护费；付不起时执行资产卡的停用或风险后果。
4. 将团队金库补足到最低储备金。建议最低储备为下一章固定成本的1倍。
5. 得到“可分配利润”。
6. 团队选择分配0%、20%或40%，剩余资金继续留在团队。
7. 系统按公开贡献规则计算每名成员的个人收入。
8. 团队再讨论下一章的购买、维护和扩张。

```text
可分配利润 = max(0, 本章收入 - 本章直接成本 - 维护费 - 储备金缺口)
本章分配池 = 可分配利润 × 团队选择比例（0%／20%／40%）
```

融资款不是收入，不直接进入可分配利润。

### 2.4 个人收益如何按贡献分配

分配池采用“有保底的贡献分配”，防止安静但实际工作的成员被忽略：

```text
50% 平等劳动份额
    四名在场且完成最小行动的成员均分。

30% 角色交付份额
    根据本章公开的P／D／M／O交付量规分配。
    只看作品与承诺完成度，不看口才。

20% 协作贡献份额
    每人将1枚感谢标记投给一名真正改变过自己行动的队友，不能投自己。
    必须说出具体支撑行为；无理由的票无效。
```

系统和纸质钱包账本以0.1 C为最小单位；实体资金币只表示整数，零头写在钱包账本中。缺席或未完成任何最小行动者不获得平等劳动份额，但DM必须记录原因，不得把学习障碍简单解释为“不贡献”。

### 2.5 不把声望与金钱相加

声望是学习与协作记录，资金是商业资源。二者只允许形成“门槛＋成本”组合：

- 声望达到门槛：说明玩家有资格使用某种渠道或能力。
- 团队或个人支付资金：说明项目愿意承担使用成本。
- 两者同时满足时，渠道或工具才可使用。

示例：玩家达到12 RP后有资格发起跨队专家交换；若要邀请NPC专家进场，团队仍需支付2 C。声望不会被扣除。

## 3. 道具目录与具体用法

### 3.1 每个4人团队的实体包

```text
场景板                    1张   放置案例地图、年代和当前章节目标
案例身份卡                4张   开局分发，整章保留私密面朝下区域
P／D／M／O角色牌          4张   攻坚前自由分配，可在下一轮调整
角色技能卡                8张   声望解锁后装备，每人最多1张
信息卡                   12张   每人3张，按权限公开或保密
信息信封                  4个   断网发牌和回收未揭晓信息
挑战卡                    3张   L1／L2／L3各1张，公开目标与量规
压力事件卡                6张   对应六面骰，也可完全替代骰子
资产卡                   12张   放在成长盘商店，可被购买和维护
现实迁移卡                4张   记录现实项目下一步
PDMO认知卡                4张   个人复盘
决策记录单                1张   写主导、支撑、证据、行动与停止条件
团队能力板                1张   连接队友技能、顾虑和支撑关系
成长盘／商店板            1张   分为金库、资产、维护、收入和地图解锁区
红绿黄紫毛线            各1卷   因果／支持／限制／矛盾
灰色虚线贴               12条   标记尚未验证的假设
关系夹／图钉              24个   固定卡片和毛线，避免直接粘坏卡片
六面压力骰                1颗   只决定情境压力，不决定学习成绩
证据／假设／矛盾／缺口标记 各6枚   标明节点性质
资金币                   40枚   团队金库与个人钱包共用
个人钱包信封              4个   一人一个，资金公开、他人不可拿取
个人声望轨                4条   用夹子记录累计RP，不消费
感谢标记                  4枚   章节结算时每人投出1枚，必须说明理由
阶段计时条                1张   DM每次推进阶段时移动标记
```

### 3.2 全班公共道具

- DM屏风：背后放史实结局、压力事件、NPC资料和纠错规则。
- 世界时间轴与硅谷地图：显示当前年代和已经解锁的地点。
- 史实揭晓封套：玩家锁定决定后才打开。
- 公共商店：展示本章可买资产、价格、维护和解锁效果。
- 计时器或大屏阶段条：始终显示目标、剩余时间和所需作品。
- 课堂事故包：备用骰子、毛线、贴纸、空白卡、纸账本和铅笔。

### 3.3 道具在90分钟中的移动

```text
00–08  身份卡进入个人私密区；声望轨和钱包放在玩家面前
08–15  信息卡从信封／小程序进入个人手牌
15–32  玩家讲解后，允许公开的卡进入场景板
32–42  毛线连接信息卡；团队能力板连接角色技能与支撑关系
42–47  DM把矛盾／缺口标记转成挑战卡
47–52  P／D／M／O牌进入对应玩家面前，填写决策单
52–76  投骰或翻压力事件；行动、证据和反馈写入决策单
76–82  资金币进入金库；支付资产；资产卡进入成长盘；处理个人分配
82–86  打开史实揭晓封套，对照玩家世界线
86–90  更新个人声望轨，填写认知卡和现实迁移卡
```

### 3.4 实体与数字状态谁说了算

- 正常联网：WebApp账本是主记录，实体币用于可视化。
- 临时断网：DM签字的纸账本是主记录，恢复后一次性补录。
- 发生差异：暂停交易，不回滚课堂；以最近一次双方确认的检查点为准，由DM做带原因的纠错记录。
- 不允许实体币和数字余额同时各算一份。

## 5. 学员账号与身份系统

### 5.1 四层身份必须分开

```text
Young Builder账号
  长期存在：昵称、头像、声望、成就、作品档案、个人钱包

班级成员身份
  学期存在：班级、团队历史、导师关系、出勤与授权

案例身份
  单场战役存在：历史人物／合作者／复合角色、私密信息、个人顾虑

PDMO行动身份
  单轮存在：本轮主导或支撑的P／D／M／O职责
```

系统不得把“这轮负责开发”写成学员的永久标签。PDMO应轮换，案例身份在战役结束后进入档案而不是继续控制权限。

### 5.2 加入与登录

- 学员自行注册后用用户名＋密码登录，再输入公开`TEAM-XXXXXXXX`队伍ID提交申请。
- 提交申请不授予访问；DM批准或按用户名／昵称直接添加后才建立课堂membership。
- 忘记密码时由DM为自己课堂成员／待审批者生成30分钟单次重置URL；特权账号由后台维护。
- 公开展示只用昵称和头像；真实姓名、联系方式与监护信息不进入游戏事件日志。
- DM、内容编辑、校方管理员使用独立高权限账号，不与学员入口混用。

### 5.3 学员个人主页

必须展示：

- 当前声望总值、等级、下一解锁和得分证据。
- 个人钱包余额与每笔来源、消费和返投记录。
- 参加过的历史战役、案例身份和PDMO轮换记录。
- 代表性证据、决策、作品、复盘和Demo Day档案。
- 已解锁角色技能和可使用次数。
- 数据导出、昵称修改和退出班级入口。

不得展示单一全班财富榜或永久倒数排名。

## 6. 学员小程序／WebApp

### 6.1 学员端九个核心页面

1. **课堂大厅**：账号身份、队伍ID申请、审批状态、已加入课堂与设备恢复。
2. **任务大厅**：时代、地图、本章目标、阶段条和剩余时间。
3. **身份与手牌**：案例身份、私密信息、可信度与分享状态。
4. **情报网**：发布允许公开的节点，声明关系和理由。
5. **团队与PDMO**：显示能力、顾虑、本轮主导与支撑承诺。
6. **攻坚局**：难度、压力、可用资源、行动提交和反馈。
7. **成长盘**：团队金库、资产、维护、商店、购买提案和投票。
8. **我的成长**：声望证据、个人钱包、技能解锁和作品。
9. **复盘档案**：玩家世界线、史实对照、认知卡和现实行动。

### 6.2 关键交互规则

- 信息卡默认只对持有人可见；玩家主动“发布到团队”后才改变权限。
- 私密卡只能引用卡号和允许公开的摘要，不能被队友端直接读取。
- 购买团队资产需要一人提案、一人附议、过半成员确认；DM只审核规则合法性。
- 每笔资金变化显示前余额、变化量、后余额、原因和操作者。
- 投骰由系统或实体骰产生，但结果必须记录；重复点击不得重复结算。
- DM修改余额、卡片或评分时必须填写纠错原因。
- 史实按钮在玩家决定冻结前不可操作。

## 7. DM控制台

### 7.1 开课控制

- 创建班级、战役、章节和多个团队；复制每队稳定的公开队伍ID。
- 审批／拒绝申请，按用户名或昵称直接添加、移出学员并检查容量。
- 帮助有权管理的普通学员生成单次密码重置链接；检查RBAC、权限和实体备份包。
- 开始、暂停、延时、跳转和结束阶段。

### 7.2 信息与剧情控制

- 身份与信息卡分别独立随机；每人从完整12张章节牌池抽3张。可撤回误发卡、设置解锁条件。
- 查看谁已读、谁准备分享、谁长期没有行动。
- 审核关系线的类型、理由和证据状态。
- 从矛盾、缺口或机会生成挑战。
- 投放NPC、压力事件、结果后果与史实揭晓。

### 7.3 结算与经济控制

- 用公开量规分别记录四项挑战结果。
- 记录每名玩家的RP项目及其作品证据。
- 查看团队收入、成本、维护、储备和可分配利润。
- 发起0%／20%／40%分配表决并自动计算个人收益。
- 审核购买前置、余额、维护和地图解锁。
- 纠正错误交易，但不能无痕改账。

### 7.4 课堂保障

- 一键切换实体备份并生成纸账本编号。
- 记录敏感事件、退出或暂停，不公开给其他学员。
- 恢复断线玩家至最近确认检查点。
- 导出完整课堂档案、简版家长报告和匿名教研数据。

## 8. 内容后台与知识库连接

课程设计者需要一个独立内容后台，管理：

- 企业、人物、产品、地点、时间和来源节点。
- 事实、观点、推断、传闻与反事实标签。
- 案例身份、信息卡、关系线候选和解锁条件。
- 五任务章节、三档挑战、压力事件和后果。
- 资产、价格、收入、维护、组合与地图解锁。
- PDMO认知目标、评分量规和现实迁移任务。
- 版本、审核人、发布时间和适用年龄。

知识库节点与课堂卡片使用稳定ID。卡片可以引用知识库，但课堂中只展示当时角色有权知道的切片；知识库全文不等于学员当场可见信息。

## 9. 技术域与最小数据模型

### 9.1 产品模块

```text
身份与权限        Account / Membership / Role / Consent
课堂房间          Campaign / Chapter / Session / Team / Phase
内容与发牌        CaseIdentity / InfoCard / CardGrant / Reveal
关系网            EvidenceNode / RelationshipEdge / ClaimStatus
攻坚局            Challenge / PressureEvent / Action / RubricResult
成长盘            Asset / TeamAsset / Maintenance / Unlock
经济账本          AccountLedger / Transaction / Distribution
成长档案          ReputationEntry / SkillUnlock / Reflection / Portfolio
世界线            Decision / Consequence / PlayerTimeline / HistoryReveal
审计与导出        AuditEvent / Snapshot / Export
```

### 9.2 货币必须使用账本事件

不能只在团队表中保存一个可任意覆盖的`balance`。每笔交易至少包含：

```text
transaction_id
session_id
from_account（系统铸币时为空）
to_account（系统销毁时为空）
amount
currency = C
category
source_object_id
created_by
created_at
idempotency_key
reason
reversal_of（纠错时填写）
```

余额由已确认交易求和或由可核验快照加增量得到。购买、分配和维护必须是原子操作；网络重试不得重复扣款。

### 9.3 声望必须可解释

每笔RP记录至少包含：

```text
learner_id
session_id
rubric_dimension
points
evidence_object_id
awarded_by
created_at
reason
```

声望只允许新增或带原因冲正，不允许无痕覆盖总分。

### 9.4 权限规则

- 学员：只读自己的私密手牌、个人钱包和个人声望证据。
- 团队：共享已发布节点、团队决策、金库、资产与交易。
- DM：管理当前房间；修改须留审计。
- 内容编辑：管理案例内容，不自动获得学员个人资料。
- 校方管理员：管理成员和授权，不自动看到未公开私密卡内容。

## 10. 一轮完整经济示例

四人团队开局金库10 C，个人钱包均为0 C。

1. 团队完成L2挑战并达到普通成功，获得4 C，金库变14 C。
2. 团队提交一条合格用户证据，获得1 C，金库变15 C。
3. 本章支付Beta社区维护费1 C，金库变14 C。
4. 下一章固定成本预计6 C，最低储备为6 C；当前没有储备缺口。
5. 本章可分配利润按章内收入5 C减维护费1 C计算，为4 C。
6. 团队选择分配40%，分配池为1.6 C；其余留在团队。
7. 0.8 C平等均分，每人0.2 C；0.48 C按角色交付；0.32 C按感谢标记。系统显示公式和证据。
8. 分配后团队金库为12.4 C；团队再用4 C购买数据分析面板，金库变8.4 C，并获得资产与下章维护义务。
9. 每名玩家按证据获得0–12 RP。RP不会因购买或分钱改变。
10. 达到12 RP的玩家解锁“连接者”，下一章可以发起一次跨队证据交换。

## 11. 首个可开发垂直切片

以Google 1998“识别真问题”章节为验收场景，产品必须一次贯通：

1. DM创建房间，4名学员用二维码加入并可断线恢复。
2. 系统独立随机分发案例身份；信息卡从完整12张章节牌池独立随机，每人3张，不按角色定向。
3. 每名学员发布至少1个信息节点并说明关系。
4. 团队完成一次PDMO主导／支撑分工。
5. 团队选择L1／L2／L3，投一次压力骰并提交两轮行动。
6. DM按四项量规结算挑战并给出世界线后果。
7. 系统增加个人RP，且每笔RP可回到作品证据。
8. 系统增加团队收入、扣除成本、计算可分配利润。
9. 团队完成一次资产购买和一次个人收益分配。
10. 玩家能用个人钱包购买一个合法个人道具或返投团队。
11. 玩家先冻结自己的世界线，再看到史实与来源。
12. DM导出完整审计档案，断网纸账本可补录且不重复交易。

没有同时跑通声望、团队金库、个人钱包和史实揭晓，不能称为完整垂直切片。

## 12. 测试与验收

### 12.1 规则测试

- 每人每节RP不超过12，历史相似度不会加分。
- 声望不可消费、转让或兑换为资金。
- 团队资金不足时购买失败且余额不变。
- 同一个购买请求重复提交只成交一次。
- 维护费只扣一次，未支付时资产按规则停用。
- 融资款不进入可分配利润。
- 个人分配总额不超过分配池，舍入余数回到团队。
- 玩家不能直接向另一玩家转账。
- 个人道具不能修改RP或解锁核心答案。

### 12.2 权限测试

- A玩家不能读取B玩家未发布的信息卡。
- 其他团队不能查看本队私密节点、钱包和决策草稿。
- DM纠错一定产生审计记录。
- 玩家决定冻结前不能打开史实结局。
- 角色轮换后旧权限立即失效，历史档案仍可追溯。

### 12.3 课堂流程测试

- 首次使用的DM仅凭两份手册能在30分钟内完成备课。
- 4名测试玩家能在90分钟内跑完完整循环。
- 每名玩家至少完成一次信息讲解、一次主导或有效支撑、一次复盘。
- 断网后2分钟内切换纸质模式，课程不中断。
- 恢复网络后纸账本可补录，余额与资产保持一致。

### 12.4 经济平衡观察

每次试玩后记录：

- 平均与最大RP、各维度得分分布。
- 团队收入、支出、现金、资产和维护压力。
- 个人分配差距及其证据是否被玩家认可。
- 哪些资产必买、无人买、过强或无法回本。
- 是否出现囤币、刷分、强迫转账或高声望垄断。

连续三场出现同一失衡时，调整收入、价格、维护或解锁门槛，并提升规则版本号，禁止对正在进行的战役静默改价。

## 13. DM现场速记

```text
声望：个人的、长期的、不消费；凭作品证据获得，用于解锁。
金库：团队的、可消费；先收入、成本、维护、储备，再决定分配。
钱包：个人的、可消费；来自团队分配，可买个人工具或返投团队。

不要相加排名。
不要用骰子扣声望。
不要让钱购买答案。
不要让个人直接拿团队的钱。
不要让玩家彼此直接转账。
所有加分、收入、支出和纠错都要有来源、有理由、有记录。
```
