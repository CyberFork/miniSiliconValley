# 游戏化课程开发决策记录 v4.0

## 目标与总纲

本版本将课程统一为“一世界、两轨线、三引擎、四导师、五步骤、六分钟”。目标不是历史答题，而是在史实约束下练习可迁移的创业判断，并在终局用严格六分钟完成一次团队路演。当前唯一权威口径见[课程语义](COURSE_SEMANTICS.md)。

- **一世界**：全球科技创业有限开放世界。地图、公司、市场和资源彼此关联，开放探索但受时代、证据、预算与行动次数约束。
- **双轨线**：历史认知轨追踪真实人物、事件和约束；现实创业轨把同一问题结构迁移到学员项目。所谓“平行世界线”仅指历史关卡中的反事实分支，不是第三条课程主线。
- **三引擎**：毛线式探索（线索和关系网逐步展开）；美式/TRPG情境（角色扮演、事件卡、主持人追问）；德式资源决策（时间、现金、信誉、样本等有限资源的取舍）。
- **四导师**：P（Product，产品）、D（Development，开发）、M（Marketing，市场）、O（Operations，运营）。这是导师专业线，不是四名学员的固定身份。
- **五步骤**：找真问题、定真方案、做真产品、进真市场、跑真运营。
- **六分钟**：每队终局严格6分钟；Demo Day是终局时序，不作为独立任务计入。

## 团队同步稿（约500字）

Mini Silicon Valley 是一套由真实科技史驱动的有限开放世界创业学习 RPG。“一世界”把全球科技创新史组织成可探索的时间轴与地图，企业、人物、产品、技术和事件彼此连接，构成学习世界。“两轨线”由历史认知轨和现实创业轨组成：学员先进入 Google 当时的情境，在有限信息与约束下调查、协商、判断并体验平行分支，再对照史实提炼认知；随后把认知带回自己的项目，以真实行动完成验证。“三引擎”是毛线式探索、美式／TRPG 情境和德式资源决策，依次负责连接线索、建立代入感、在时间与预算约束中收敛方案。“四导师”是产品、开发、市场、运营四条横向专业线；四名学员统一是 Young Builder，不被固定贴成 P／D／M／O。“五步骤”是找真问题、定真方案、做真产品、进真市场、跑真运营，每一步都留下证据、作品和迭代记录。课程以每队六分钟的 Demo Day 收束，呈现问题、证据、方案、MVP、测试结果、市场运营、失败迭代、下一步行动和资源请求。导师不是答案讲授者，而是 DM：当值导师建立情境并主持，其他导师按专业线观察与支援。系统不要求学生背诵成功故事或复制历史答案，而是让他们在真实历史与现实项目间反复迁移，完成学习、练习、实操、反馈和成长的闭环。

## 双轨闭环

每回合先在历史认知轨取得来源、时间和因果约束，再将约束翻译为现实创业轨的假设、实验或资源请求。现实轨的实验结果反过来触发历史轨复盘：哪些判断受当时信息限制，哪些是可迁移原则。DM在两轨之间设置“映射节点”，要求玩家写出证据、推理和下一步行动；没有证据不得推进关键决策。历史相似度不计分，评分只看证据质量、约束意识、决策逻辑、协作与现实行动性。

## 五步骤机制与产出

### 1. 找真问题（P 产品导师主导）
进入地图和情境，访谈角色、读取事件线索，记录用户场景与痛点信号；禁止提前写方案。产出：问题信号池、受影响角色清单、初始假设。

### 2. 定真方案（P 产品导师＋D 开发导师主导）
从史料、访谈和反例中筛选证据，比较至少三条解决路径，写清价值、可行性、风险、放弃条件与验证边界。产出：真问题陈述、证据夹、方案对比卡、主方案与备用方案。

### 3. 做真产品（D 开发导师主导）
在时间、算力、样本和技能预算内制作可操作的最小闭环，用真实测试或明确标注的课堂模拟暴露断点，并据证据完成一次迭代。产出：MVP V0/V1、测试记录、失败证据与修改理由。

### 4. 进真市场（M 市场导师主导）
定义第一小群可达用户、十秒价值表达和一个获授权渠道；区分触达、尝试、完成与再用，不把曝光当结果。产出：目标人群卡、价值承诺、渠道实验、拒绝／使用证据与下一轮判断。

### 5. 跑真运营（O 运营导师主导）
让订单／任务从进入到交付完整跑通，记录成本、收入、异常、责任与反馈；品牌在这里由稳定兑现承诺而形成。产出：可执行 SOP、团队账本、异常处理、反馈迭代和可持续运行判断。

## 三引擎与三类桌游的明确映射

这不是模糊的风格类比，而是确定的机制分工：

- **探索引擎 = 毛线式桌游**：让学生搜索线索、建立证据关系网、标记假设与矛盾。
- **情境引擎 = 美式桌游 / TRPG**：让学生以随机历史情境身份，在当时信息、立场冲突和事件压力下声明行动、协商并承受分支后果；情境身份不等于导师 PDMO。
- **决策引擎 = 德式桌游**：让学生在有限资源中排优先级、构建MVP、按公开规则结算信号并迭代。

三者在一轮课堂中的固定闭环是：**探索线索/假设 → 情境行动/协商 → 决策资源配置/规则结算 → 史实复盘/现实迁移 → 用新证据回到下一轮探索**。

### 探索引擎｜毛线式

- 参考机制：MicroMacro的大地图搜索与轨迹还原；Sherlock Holmes Consulting Detective的地图/报纸/目录自由选线；Detective的线索、时间成本与事实连接。
- 保留机制：地图热点、有限调查点、人物/需求/事件/技术/约束五类节点、“导致/支持/矛盾/限制”四类连边、证据线与假设线分色、缺口标记。
- 实施回合：选热点 → 支付调查点 → 获得线索 → 连线并说明依据 → DM标证据/假设/矛盾 → 生成下一个待验证问题。
- 产出：证据关系网、问题池、缺失证据清单。
- 禁用：知识问答、一次性开放全部材料、无依据连线。

### 情境引擎｜美式 / TRPG

- 参考机制：D&D的“DM描述环境—玩家申明行动—规则解决不确定”；The King’s Dilemma的两难事件、协商/投票与持续分支；Pandemic的非对称角色能力和团队共同目标。
- 保留机制：非对抗式信息差、随机情境身份、NPC对话、“目标—方法—依据”行动声明、限时协商、压力事件、反事实分支与持久后果。
- 实施回合：DM建立现场 → 角色阅读私有信息 → 各自申明行动 → 协商与追问 → 团队锁定判断 → DM给出受规则约束的分支后果。
- 产出：角色立场图、团队决策记录、反事实世界线。
- 禁用：无任务的自由表演、卧底与淘汰、用骰子代替证据判断。

### 决策引擎｜德式

- 参考机制：CATAN的资源组合/交易/建造成本；Food Chain Magnate的组织能力、营销制造需求与服务交付；Scythe的行动选择与引擎升级。
- 保留机制：时间/证据/工程/触达/现金五类资源、行动点、同时私密分配、MVP配方、公开测试结算、条件融资、复盘后的能力升级。信任是结果指标，不是可任意购买的币。
- 实施回合：领取共享资源 → Young Builder 各自提出有证据的方案 → 团队提交分配 → 支付成本制作／测试 → 按规则结算 → 选择继续／调整／停止。
- 产出：资源账本、MVP配方、测试信号、迭代记录。
- 禁用：与学习无关的胜利分、隐藏结算公式、把钱或规模作为唯一目标。

### 四导师与五步骤的反向设计原则

每个步骤都必须同时写清：（1）三引擎各自促发什么动作；（2）哪位导师主导、其他导师观察什么；（3）Young Builder 团队付出什么资源；（4）用什么公开规则反馈；（5）什么作品能证明已学会。任一机制若不能促发可观察行为、不留作品或不返回反馈，就从课程中删除。

## 终局六分钟时序（每队严格）

- **0:00–0:45 问题**：一句话说明用户、场景和损失。
- **0:45–1:30 证据**：展示关键来源、样本与反证边界。
- **1:30–2:30 方案**：讲清取舍、指标和为何现在做。
- **2:30–3:30 MVP**：现场演示最小闭环及资源约束。
- **3:30–4:30 测试/市场/运营**：报告测试信号、首批用户、渠道和品牌承诺。
- **4:30–5:15 失败反馈迭代**：呈现一次失败或反例，以及据此修改的决策。
- **5:15–6:00 下一步/资源请求/收束**：提出下一实验、明确资源请求，以一句可验证承诺结束。

超时即停止播放；未使用的时段不补回。评委提问在六分钟后另计，不改变终局评分。

## 导师、资源与评分

P/D/M/O 四位导师分别守住问题与价值、实现与验证、触达与表达、交付与账本；它们不是学员权限。Young Builder 每次行动只记录具体贡献、负责人和协作者。公共资源包括时间点数、现金、算力、样本、信誉和关系；DM 可通过事件卡调整供给，但不得无提示创造资源。评分权重：证据质量30%，决策逻辑20%，MVP与执行20%，测试和迭代20%，协作与表达10%。历史相似度明确不计分。

经济系统固定为三个不可互换的账户：个人声望RP记录学习与协作证据，只解锁、不消费；团队资金C属于项目，由团队共同决定调研、产品、市场、运营、维护、购买和收益分配；个人钱包C只接收公开规则分配的商业收益，可购买个人工具或返投团队。最终不把声望和金钱相加排名。团队收入必须来自挑战成果、验证、资产或带条件外部资金，个人分配遵循“50%平等劳动＋30%角色交付＋20%协作贡献”。完整规则、道具清单、学员账号、小程序、DM控制台、内容后台和账本数据模型见[道具、经济与学员系统规格](GAME_ECONOMY_AND_PRODUCT_SPEC.md)，现场执行见[DM／导师操作手册](DM_MENTOR_MANUAL.md)。

## Google首战役

以20世纪90年代后期互联网信息快速增长为历史认知入口，追踪网页索引、排序和早期用户获取等史实节点；玩家在现实轨提出当代信息检索或知识服务项目。每阶段均执行“来源→约束→选择→实验→复盘”闭环，不把Google的成功倒推为唯一正确答案。

## DM执行

DM负责时间、资源账本、史实边界和情境节奏：先发线索，再问证据，随后揭示约束与后果；允许反事实分支，但明确其与史实的差异。每任务结束保存玩家决策、证据链接、资源变化、失败反馈和现实迁移动作；不得以历史相似度奖励或惩罚。

## 90分钟导师体验版

0–8分钟世界与角色；8–20分钟找问题；20–32分钟识别真问题；32–44分钟想解决方案；44–62分钟MVP制作；62–80分钟市场运营与品牌；80–86分钟六分钟终局（导师体验时可由一队示范）；86–90分钟导师复盘与下一步承诺。导师版可减少地图节点，但不得删除证据夹、资源账本和失败迭代。

## HTML信息架构与状态分离

页面采用“世界地图→历史事件/任务→任务工作台→证据夹与资源栏→终局计时器→Dossier复盘”的层级。历史内容、玩家输入、DM事件和评分状态分离存储；只读史实数据不可被玩家编辑，运行状态可保存、回放和导出。`timelineState`（所处年代）、`selectedMapNode`（当前地点）、`missionState`（任务进度）和`teamState`（资源与作品）必须独立管理；点击地图图标只能改变选中地点，不得让时间轴回跳。计时器、资源和评分均使用单一状态源，避免视图重复计算。

## 知识库生产规范

史实条目必须含来源、发布日期/时间范围、作者或机构、原文摘录位置、可信度和不确定性说明；区分事实、推断与教学简化。每条线索建立双向链接至任务、角色和来源，保留版本记录；反事实内容使用显式标签，不得伪装为史实。

## 交付验收

- 课程文档、数据和界面均使用“一世界、两轨线、三引擎、四导师、五步骤、六分钟”术语。
- 五步骤各有输入、机制、产出和可追踪状态；Demo Day 仅作为六分钟终局。
- Google首战役可离线完整运行，证据夹与资源账本可查看，终局计时准确。
- HTML显示与状态持久化分离；史实来源可追溯，反事实有边界声明。
- 评分不含历史相似度；团队能提交失败迭代与现实下一步。
