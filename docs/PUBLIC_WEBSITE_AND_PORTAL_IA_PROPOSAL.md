# MINI硅谷官网、教学空间与内部工作台组织提案

> 日期：2026-09-11
> 状态：已采纳并完成本地实现，等待统一生产发布与线上验收；关联 T-109。
> 本文补充入口与信息架构，不替代 `COURSE_PLATFORM_ARCHITECTURE.md` 中已经确认的课程数据、验收与运行契约。

## 1. 用户已明确的方向

- `/workshop/` 是早期讨论课程搭建方式的工具，已经不再日常使用，应归档。
- **归档仍须保留可找到的入口，只是入口更深**；不等于删除、只留源码或只能靠旧书签访问。
- 当前对内、对外入口混杂，需要重新组织。
- 需要真正介绍 MINI硅谷本身的对外官网，`/world/` 应成为其中的子组件。
- 用户进一步明确顶层只分两区：**对外是新官网、World、学生上课登录入口与课件查看；对内主要是 Studio 和课程管理。** 登录后的教学空间归属对外服务，不是第三个并列顶层。
- 用户明确要求：**整体统一采用 `mini-silicon-valley-design` skill 的新 UI，不仅重做官网首页。** 此要求覆盖对外与对内两区。

下文是已采纳的信息架构及其实现边界，不再是待选方案。

## 2. 当前问题与源码依据

本轮核对工程源码，不将其等同于已登录线上环境的完整验收。

- `deploy/minisv/site/index.html` 将世界、课件、课堂、Studio、Workshop 并列为门户入口，主内容仍是“创业学习总导航”。
- 同一公共主页展示 CourseDefinition、Test Classroom、部署健康检查、Tunnel 与 release 信息；这不是家长理解课程所需的主内容。
- `/` 实际由 `deploy/minisv/gateway/default.conf` 提供静态门户；不能只修改 `app/page.tsx` 就认为官网已经更新。
- `app/classroom/ClassroomHub.tsx` 中，具备相应权限者在课堂中心同时看到 TEST、PRODUCTION 和创建工厂。不是匿名用户获得课堂数据，而是内部制作流程与实际教学管理共用主入口。
- `docs/WORKSHOP_RELEASED_BASELINE_SOP.md` 仍定义 Workshop 的基线同步与讨论流程；部分提案、决议和审计仅存在浏览器 localStorage，归档不能只备份静态 HTML。
- `app/components/WorldApp.tsx` 已有历史地图、任务等体验；官网应复用其内容与合适的展示组件，而非再造一套历史数据。

## 3. 空间组织：对外、对内两大区

```text
minisv.vip/
├─ 对外：品牌展示与教学服务
│  ├─ /：新官网，介绍 MINI硅谷、课程与参与方式
│  ├─ /world/：完整世界探索；首页有轻量世界体验组件
│  └─ 登录后的学习空间
│     ├─ /classroom/：我的正式课堂、当前任务
│     ├─ /course/：有权访问的课件与播放
│     └─ /account/：当前账号与会话管理
└─ 对内：Studio 与课程管理
   └─ /studio/
      ├─ 课程编辑与管理 → 视图验收 → 真实 UI 测试 → 发布
      ├─ 导师课件管理（并行资源，不是课程主线的下一步）
      └─ 资料与历史
         └─ 早期课程工作坊（归档、只读）
```

“对外”指面向最终使用者的服务，不等于全部匿名公开：官网与公开 World 可以直接访问，上课与课件继续要求登录和相应权限。两区按工作目的划分，不是两套账号体系；导师上课可使用教学服务，备课/管理课程时进入有权限的 Studio。

### 官网

- 匿名可浏览，服务首次来访的家长、学生和合作方。
- 主导航围绕“这是什么、怎样学、能做什么、如何参与”，不再把部署模块名当作品牌介绍。
- “去上课”和统一账号菜单清楚可见；有权限的账号可以从菜单进入内部工作台，不让 Studio 成为匿名主页的主要行动按钮。
- 官网课程介绍不占用 `/course/` 的含义；后者继续是登录后课件库，不再误称为完整课程大纲。

### 对外区内的教学空间

- 学员主要看到自己参与的正式课堂、任务和有权访问的课件，优先适配无键盘 Pad。
- 导师可跨团队查看自己参与的课堂；Admin DM 在具体 Room 内使用中控和成员管理，不必为日常上课绕到 Studio。
- Admin DM 是课堂范围权限，不能因为它带有“管理”二字，就将其等同于全站管理或 Studio 权限。
- 未登录访问受保护入口，登录后安全返回原目标；“导师和学员都能看课件”不等于匿名可看，也不放宽既定版本和可见范围。

### 内部工作台

- 课程管理统一归入内部 Studio：课程原型、编辑、配置、课件资源、验收测试和发布，不在官网再并列一个管理系统。
- 面向团队的课程/课堂集中管理入口属于内部；具体 Room 中的 DM 中控属于教学现场操作，保留在课堂内。入口归属不扩大任何账号权限。
- TEST 的主要创建、列表和返回入口归入 Studio；正式 Classroom 中不向普通学员展示测试工厂。
- **真实 TEST 仍使用现有 Classroom UI、API、Factory 和状态机**，可以继续使用相同 Room 路由，不为整理菜单复制一套“Studio 专用测试课堂”。
- PRODUCTION 的开课与 Room 管理仍属于教学空间，只有有权者能操作。
- 内部工具、部署诊断和历史资料按权限展示；隐藏按钮或 noindex 均不等于访问控制。
- 初期优先保留同域和可工作的 URL，仅重组页面职责与导航；不为“内外分开”先引入多个子域或独立认证系统。

## 4. 官网内容骨架

### 全站 UI 前提（用户已确认）

- 实施前读取 `mini-silicon-valley-design/SKILL.md` 及当前任务对应的参考规范；统一设计语言，不继续拼接各历史阶段的页面外观。
- 覆盖官网、World、登录/账号、课堂与中控、课件库/播放外壳、Studio 编辑/预览/管理/发布，以及历史归档入口和展示外壳；不能只给新首页换皮。
- 建立共享的颜色、字体、间距、边框和组件规则，统一品牌回首页、导航、账号菜单、按钮、表单、卡片、弹层、进度及空态/错误提示。
- 保留 MINI硅谷像素冒险风格，但按任务采用适合的布局：学员端优先 Pad 无键盘与触摸，官网兼容手机，导师/DM/编辑管理端优先桌面效率。统一风格不等于所有页面套同一密度和版式。
- 新 UI 需要覆盖实际交互状态并验收，不只是改颜色；尤其消除旧页面深底深字、hover 才能操作、禁用无原因、弹层遮挡等问题。
- 历史原始资料和已冻结的课件版本不原地改写；统一其入口/播放/归档外壳。需要更新 PPT 内部 UI 时按课件版本流程产生新版本，不篡改旧 digest 或验收证据。

### 官网内容顺序

1. **首屏定位**：MINI硅谷是什么，学习者将参与怎样的体验；主行动是了解课程/探索体验，老用户可以直接去上课。
2. **学习方式**：通过历史情境与现实项目，从发现真实问题走向可验证的实践；保留已确认的一世界、两轨、三玩法、四导师、五步骤、最后六分钟 Demo 口径。
3. **导师支持**：P/D/M/O 是导师专业分工，不是学员职业分组；展示产品、开发、市场、运营怎样协作支持学生。
4. **学习过程与成果**：用经审核的任务示例和交付物解释过程，不用内部 JSON、回执或技术术语代替课程介绍。
5. **世界体验组件**：以历史地图引发兴趣，从首页进入完整 `/world/`。
6. **家长关心的问题与参与方式**：与现有家长信息/问答入口整合，不重复维护互相冲突的介绍文案。

内容边界：

- 五步使用当前批准口径，不把早期 chj 四阶段、九章节或设计 skill 中的通用示例重新升格为课程标准。
- “六分钟”明确指最终 Demo，而非整套课程只需六分钟；现有首页标题与主视觉要一起检查。
- 具体年龄、课时、价格、招生时间、师资资历和案例成果，没有确认资料就列入待补清单，不能自行编造。
- 学生作品、照片和个人信息须有发布授权并按需脱敏；内部剧本答案、私密手牌、测试账号不能成为官网展示素材。
- 沿用 `mini-silicon-valley-design` 的像素冒险、奶油底、蓝绿与黄色重点，但让真实文字、可读性和触摸操作优先于装饰。

## 5. World 如何成为子组件

- 首页使用轻量地图片段/精选历史节点作为品牌体验组件，提供“探索完整世界”。它不再承担所有平台入口与品牌介绍。
- `/world/` 保留完整探索与既有深链，并提供清楚的回官网入口。
- 复用既有历史目录、来源与地图能力；需要拆分的是展示边界，而不是复制内容 JSON。
- 首页按需加载重型地图资源，并有可阅读的静态摘要和触摸入口；不能只有 hover 才能操作。
- 不以“把整个 WorldApp 塞进首页大 iframe”作为最终整合方案。
- 匿名体验状态与真实 Classroom 的成员、进度、手牌、钱包严格隔离；体验不意味着加入课堂或写入学习档案。

## 6. Workshop 如何归档又保留入口

建议可发现路径：**Course Studio → 资料与历史 → 早期课程工作坊**。

- 从官网主导航、首页核心卡片和日常上课导航移除，但在内部资料索引保留清楚的文字入口、用途说明和面包屑。
- 入口标注“历史归档 · 只读 · 不代表当前课程标准”，并链接现行课程架构与 Studio。
- 第一阶段可保留 `/workshop/` URL，仅降低导航层级并完成归档态；“入口更深”不要求 URL 必须多嵌套几层。
- 若以后迁移归档路径，旧 URL 应有明确归档提示/安全跳转，不能成为无说明的 404；历史深链和素材路径需测试。
- 内部讨论资料默认面向有权限的团队成员。归档入口的权限与文件/API 保护必须一致，不把历史原始讨论自动转为官网公开内容。
- 备份源文件、依赖资源、最终只读基线、版本信息；盘点并由相关浏览器导出 `msv.workshop.*` 下的本地基线、提案、决议和审计，先确认覆盖范围再停用写入。
- 保留 T-081 已完成的历史成果与验收记录；后续不再把“持续反向同步最新课程到 Workshop”作为主生产线需求。检查快照生成、打包和文档依赖后，再有计划地退役该链路。
- 只读归档不恢复课程编辑、会议写入或对正式课堂的控制能力；新讨论和修改仍走当前项目记录与 Studio。

## 7. 不可改变的底层边界

- 顶层导航分对外/对内两区；运行层面仍只有制作/测试与正式交付两种环境，二者不是必须一一对应的路由树。官网只是对外区的公开展示，不是第三套教学运行环境。
- CourseDefinition 仍是唯一可编辑课程真值；Candidate/Released、两次验收、不可变 exact 引用和独立 Room 状态不变。
- 调整导航不改变课程/课件 ID、已有 Room、成员与账号关系，不自动迁移版本或重新签发验收。
- 公共内容从批准资料整理；课程内容的只读展示可复用统一投影，不能生成第二个可写课程编辑入口。

## 8. 实施落点（T-109）

- `/` 已改为真正的公开官网；首页只介绍课程价值、五步实践、三种玩法、导师支持、成果与参与入口，不展示 Studio、Workshop、Tunnel、release 或内部回执。
- 首页的轻量历史地图由 `app/data/history.ts` 的同一 `historyCatalog` 构建为 `world-preview.json`；`/world/` 保留完整历史世界，二者不是两份历史数据。
- `/classroom/` 是“去上课”，`/course/` 统一称为“课件查看”；二者仍按第一方账号与原权限边界工作。
- Studio 侧栏新增“资料与历史 → 早期课程工作坊”。Workshop 保留 `/workshop/`，但已冻结为受保护的只读历史归档；匿名跳登录、learner 拒绝、mentor/admin 可读，`/workshop/_source/` 永远返回 404。
- Workshop 发布包保留旧工具的逐字节 `_source` 备份和确认基线，但 Web 不提供源码目录。浏览器历史无法由服务器跨设备收集；归档页只读取并导出本浏览器的十个已知 localStorage 键，绝不写入、清理或自动合并。
- 搜索边界按页面职责拆分：官网、World、方法框架与家长入口允许索引；登录、课堂、课件、Studio、Workshop、API 与运维页面统一 noindex。
- 官网与归档外壳使用 `mini-silicon-valley-design` 的奶油网格、深海军蓝、薄荷、黄色与珊瑚色视觉；已冻结导师课件 bundle 不被原地改写。
