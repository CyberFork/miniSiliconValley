# P1 阶段 A：Minecraft 风格模块工坊教学样段

> **用途**：给 P1 导师、投屏与学生端使用的内容底稿。这里是原创课堂模拟，不是 Minecraft 原生车辆或配方。阶段 B 先交付可玩的竖向样段；阶段 C 的完整融入必须等用户亲自试用确认后再推进。

## 1. 覆盖映射：从原有知识点到可见操作

- **WHAT（是什么）**：先看“基础方块 → 功能模块 → 完整作品”三层。学生能指出五个同种方块组成的十字轮、两个金属加一个燃料组成的线性推进器，以及预制车架；知道“外形像”不等于“已有行为”。
- **WHY（为什么）**：把整体任务拆成职责清楚、可以重复使用的部分：轮子负责支撑/滚动，推进器负责沿箭头方向推动，车架负责连接。拆开检查、装回整体，才能解释平地和起伏地形为何可能不同。
- **HOW（怎么做）**：选择材料、按网格放置、点选组合、命名并写一句职责、保存为模块；从模块库整体重复放置到同一车架，切换试驾，推进/刹车/重置，沿同一路线复测。
- **原有六字段（模块描述）**：以“轮子”示范——职责：支撑和滚动；输入：车架连接与地面接触；处理规则：接触地面时允许滚动（课堂简化）；输出：车体获得支撑/滚动表现；接口：连接点与车架、接触地面；正常/异常：四个轮子连接且接触→可试驾；缺轮、重叠或未连接→提示修正。推进器同样填写六字段，重点补充“输入：推进指令/燃料块；输出：沿箭头推力；方向反接→结果可观察并记录”。
- **P1 三项学生成果**：①自己的游戏模块地图：把车辆/场景中的模块画出连接关系；②关键模块详细设计卡：至少一个模块写全六字段；③正常/异常验证记录：记录预测、实际观察、修正和同一路线复测，不把教师演示当个人通过证据。

## 2. 原生机制与课堂原创规则边界

- **可引用的 MC 事实**：工作台把材料组合为物品，熔炉有输入、处理状态和产物，漏斗可作物品交接的机制例子；仅用来帮助理解“组合、职责、输入/输出、交接”。参考：[How to craft](https://www.minecraft.net/en-us/article/how-craft)、[Hopper](https://www.minecraft.net/en-us/article/hopper)。
- **原创课堂规则**：五块同种方块的十字轮、两个金属块＋一个燃料块的线性推进器、模块命名/职责、预制车架吸附、推进/刹车/重置及简化轮地接触，都是本课工坊规则，**不是 MC 原生配方、车辆或物理**。
- **边界**：不讲轮子尺寸调节、灯/红石主线、现实燃料或推进器制造。样段使用项目现有 Three.js 与 Rapier 0.20.0，碰撞规则见实现说明。MC 原生机制的具体游戏版本专项核验、学生试用及正式试讲尚未发生；阶段 C 前保持待核实。

## 3. 10–15 分钟现场样段脚本（建议 14 分钟）

| 时间 | 教师动作与台词 | 学生预测/观察证据 |
|---|---|---|
| 0:00–1:00 | **看场景**：“我们要让同一辆小车走过平地、缓坡、起伏和小落差。先别背名词：谁负责支撑？谁负责推动？” 指轮子/推进器/车架。 | 口头指出职责；在记录卡写一次预测。 |
| 1:00–3:00 | **搭轮子**：选择同一种方块，在网格中心放 1 块，再放上下左右 4 块，形成固定五块十字。强调这是课堂示意，不是 MC 配方。点选组合，问：“少一块还能叫本轮标准轮吗？” | 预测：少块应被拒绝/提示不完整；观察数量和形状。 |
| 3:00–5:00 | **搭推进器**：放两个金属块和一个燃料块，沿箭头排成一条线；指出箭头就是虚拟推进方向。“它的职责用一句话怎么说？” | 写“接受推进指令并沿箭头推车”；观察组成预览和方向。 |
| 5:00–6:30 | **命名与责任**：分别命名“十字轮”“线性推进器”，保存模块；要求职责短句。展示模块库中组成预览，说明定义与之后的装配实例不同。 | 说出名称、职责、组成；检查保存成功反馈。 |
| 6:30–8:30 | **装配同一作品**：打开预制车架，把四个轮子模块重复放置到连接点，再放一个推进器；整体移动/旋转一次，问：“移动一个轮子会不会改掉库里的定义或其他轮子？” | 预测实例隔离；观察吸附、连接状态、模块来源。 |
| 8:30–10:30 | **第一次试驾**：切换试驾，提醒这是当前刚装的作品，不会偷偷换标准车。点击推进进入短路线；松开推进后不应被硬设为零速，必要时点刹车。 | 观察重力、地面接触、坡面/起伏、小落差；记录“预测 vs 实际”。 |
| 10:30–12:00 | **故意制造可解释异常**：在允许范围内反向旋转推进器或留出一个未连接轮，询问：“哪个模块负责？哪个连接/方向违反了规则？”不把失败说成 bug 已解决。 | 记录提示、不能运行或行驶表现；说出一条修正。 |
| 12:00–14:00 | **重置复测**：恢复同一作品和起始条件，沿同一路线再跑；对照第一次记录。收束：“模块能复用，整体仍要测试；正常与异常都要有证据。” | 交一条复测记录；指出是否同一初始状态、是否有差异及原因。 |

> 若现场时间只有 10 分钟，合并异常讲解与重置；仍不可省略保存模块、使用同一作品、重置复测。样段不额外加到 120 分钟之外。

## 4. 教师预测—观察提问卡

- **搭建前**：五块是否足够表达固定轮子？少一块会怎样？推进器箭头反向会影响哪一项职责？
- **连接前**：四个轮子是四个装配实例还是一个定义的四次引用？移动一个实例，其他实例应不应跟着动？
- **试驾前**：平地成功能否预测起伏路也成功？松开推进和点击刹车，预期是否相同？
- **异常后**：车辆没动，是材料组成、连接、方向还是地形接触的问题？你看到了什么，而不是“系统应该怎样”？
- **复测后**：是否回到同一初始状态、同一路线？哪条观察支持你的结论？

## 5. 120 分钟建议安排（保留 40 分钟个人实践）

- 0–10：场景导入、WHAT 与整体/部分。
- 10–25：WHY：职责、接口、复用；看原生机制类比与课堂边界。
- 25–40：六字段拆解（以轮子/推进器为例）。
- 40–54：教师 14 分钟样段（本文件脚本）。
- 54–65：集体复盘：正常/异常、预测/观察、同一作品与复测。
- 65–80：学生规划自己的模块地图与模块选择。
- 80–120：**个人实践 40 分钟**：设计、互查、填写关键模块卡与正常/异常验证记录；末 5 分钟提交三项成果。不得因样段加时而压缩此段。

## 6. AC-01–AC-14 证据计划（未声称已通过）

阶段 A 只定义取证方法；以下均为“待执行”，不构成已通过结果：

- **AC-01**：录屏/截图五块同种十字轮，保存后整体移动、重复放置，并核对内部组成。
- **AC-02**：录屏两个金属＋一个燃料推进器、名称/职责/箭头，画面标注“原创课堂规则”。
- **AC-03**：保存装配清单与进入试驾前后作品 ID；删除/改方向后核对没有静默替换标准车。
- **AC-04**：保存后刷新、导出再导入；用非法 JSON/模拟保存失败，确认当前未保存作品仍在。
- **AC-05**：移动一个轮子实例，截图其他实例和模块定义未变。
- **AC-06**：同一路线录制小落差下落、接触地面及坡面状态；不能用预设轨迹截图替代。
- **AC-07**：鼠标/触摸点击推进、刹车、重置；分别记录松开推进与刹车结果。
- **AC-08**：第一次与重置后从同一点出发，同一路线对照记录。
- **AC-09**：拼装与试驾各做展开/退出/全屏，核对作品、车辆、相机和模块选择不丢。
- **AC-10**：操作方向键/空格时确认不翻页，退出操作焦点后确认课件导航恢复。
- **AC-11**：教师端操作后对照投屏状态；另开 session 检查隔离，确认教师笔记不显示。
- **AC-12**：逐项定位 WHAT/WHY/HOW、六字段、三项成果和复习页；用计时记录总时长是否 120 分钟。
- **AC-13**：邀请目标年龄学生不先讲术语，观察其能否指出职责、连接处并复述一次检查结果。
- **AC-14**：范围审查清单：无轮子尺寸、复杂悬挂、损坏系统、真实燃料、多人联机、新账号/后台。
