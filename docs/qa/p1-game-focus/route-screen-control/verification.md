# S06 投屏控制与通关重开 · 2026-09-24

## 根因
- audience 不自动取得试玩锁，按钮统一按 owner=false 禁用。
- 原“接管”只尝试 ifAvailable，并没有请求教师端释放锁；教师页开着时永远接不过来。
- 成功弹窗暂停物理后，发布心跳也一起停了，投屏错误显示“等待试玩窗口”。

## 修复
- 点击驾驶按钮、按方向键／Space、丢道具、重置和重新闯关，可显式请求原操作端交接。教师／投屏都可接管。
- 原操作端清理输入、保存最后状态、释放 Web Lock 并销毁自己的物理世界；新操作端取得锁后先读最终快照再运行。没有强抢锁或同时运行两份物理。
- 后台隐藏窗口主动让出锁；8 秒接管失败提示保留，不被逐帧状态文字覆盖。
- 成功弹窗暂停期间仍发布权威状态；投屏重开按钮不再禁用。

## 验证
- 61 项 route-game/workshop 测试通过；87 项部署测试通过。
- Safari 真实双 iframe（教师＋投屏）隔离场次 winning-control-qa：两屏同时成功弹窗，投屏点击重新闯关后，两屏弹窗关闭、背包归零；投屏显示当前试玩窗口，教师显示同步观看。再点教师驾驶按钮，操作权反向交接成功。
- 测试夹具只在本地 dist/sample/control-qa.html，未打包上线，没有改用户作品／线上通关数据。
- release 20260924-route-screen-control 已部署；维护 r22/r23 原路径，不增加课件修订。2098 份原课件包文件字节未改；nginx 预检与部署健康检查通过。
- 使用新交接协议须同时刷新教师和投屏窗口；老版本不会理解交接请求，不强行越过仍存活的操作锁。
