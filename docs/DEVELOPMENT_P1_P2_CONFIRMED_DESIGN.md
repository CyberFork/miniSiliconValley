# 开发导师 P1／P2：2026-09-19 已确认教学决策

本页汇总逐题对齐的最终答案；优先于 T-132／T-133 中早期建议。仅修改开发导师课件，不修改其他导师、Classroom 状态、作业系统或账号后台。

## 两课边界
- 两节独立 120 分钟课；不固定休息，导师机动调整节奏。
- 学生为小学六年级至初中：白话、生活／游戏例子先行，专业名词小标签，不要求背诵。
- 保留所有既有核心例子、教学活动、Three.js 三组演示和教师提示；不能用删案例换时间。
- 学生看问题、动作和逐步揭示；教师有逐页目标、讲稿、追问、误区、时间与公平参与建议。
- MINI硅谷 UI 与可访问对比度，保持师生物理分包、会话隔离和刷新恢复。

## P1：最终学会描述模块
- 顺序：5 分钟混乱挑战 → 40 分钟 WHAT／三组 3D 与案例 → 10 分钟 WHY → 20 分钟公共案例 → 40 分钟“马上用到我的游戏” → 5 分钟收束。合计 120 分钟。
- 变形玩具 → 乐高 → 我的世界式方块为正式递进，三组 Three.js 原互动保留；由导师投屏邀请学生操作、预测、解释。不新增 Roblox 学生页。
- 不要求学生写程序；Three.js 是课件互动，不是学生编程任务。
- 最终模块描述六字段：职责、输入、处理规则、输出、接口、正常／异常表现。接口是输入输出协作约定，不是输出之后的时间步骤。
- 公共案例小组做；每人针对自己的同一游戏完成模块地图、关键模块详细设计卡、正常／异常走查记录；两人互查修改。
- Day 2 产品导师“我的第一款游戏”课后作业作为 P1 软性前置，未完成者用 5 分钟速填卡补齐，不设硬门禁，不要求重做整份产品作业。
- 四份独立 A4 内容初稿：速填卡、模块地图、设计卡、验证记录。课件中有活动引导／示例，另提供可下载内容模板／初稿交同事制作实体物料；不代替最终印刷定稿。
- 不新增在线填写、OCR、上传、提交、保存后台。纸张识图转文字由学生自行使用外部工具，再检查结果。

## P2：把模块组织成完成游戏的主棍
- 扩展既有《立棍》，不另创相互竞争的方法。保留设备预约短例和原起点／目标／终点、注意力杠杆、证据、分层纠偏。
- 六阶段：8 分钟跑偏案例＋27 分钟六项与校园寻宝＋10 分钟逐问对齐＋40 分钟个人主棍和全部子棍＋22 分钟优先子棍执行返工＋13 分钟互查收束＝120。
- 固定称谓：整个游戏是“主棍”；每个功能模块是“子棍”，不使用“二级主棍”。微棍仅需知道、不填写不操作；方法提示词说明由 AI 拆解执行并报告。
- 主棍描述完整游戏愿景并标出本轮优先实现范围；整款游戏全部功能模块都有子棍，不删未来模块、不限制固定模块数。
- 主棍／子棍共同六标题和顺序：执行者 → 上下文与项目设计 → 目标 → 约束 → 避免 → 验收。子棍范围收窄，并继承整体边界、接口与共同验收。
- 学生手动或 AI 辅助建立全部模块的可执行核心模板，优先模块再深入对齐并启动实践；不是每个模块都问同样长。
- 独立可复制“对齐模式启动提示词”：一次一问，优先 5–8 个关键问题，维护已确认／待决定清单，不重复询问，不代替学生编答案。先出初稿；影响执行的未决问题不能冒充已决定。
- 学生自选豆包 Work 或 WorkBuddy；不规定设备分配，不绑定某一产品 UI 或未经核对的产品功能。
- 完整示范：校园寻宝（地图、移动、线索、背包、障碍、胜负六模块），覆盖主棍／全部子棍、首版检查与返工。旧校园预约保留为短案例。
- 结构化可编辑文档／Markdown，整份主棍与逐个子棍独立复制，成功／失败反馈、下载和打印备份；复制正文不混入按钮／装饰。
- 课堂内启动自己的项目：优先子棍交给 AI，获得真实可查看的首版，按验收检查并至少一次修正／改进；完整游戏课后继续。
- 默认浏览器可运行原型；项目所需的其他可验证形式也允许，不用 AI 自述替代执行证据。不能为满足要求虚构 bug、测试通过或课堂完成。
- Agent、工具、MCP、RAG、Skills 等仅辅助解释，不发展成新智能体课，不代替项目主线。
- 仅双视图课件、模板与复制交互，不扩建官网后台。模板编辑只为复制／下载，不能误称已上传保存。

## 发布边界
实现、自动化、浏览器验证与用户人工试讲分开记录。未获得真实试讲证据不代签；候选构建不覆盖线上现有版本。
