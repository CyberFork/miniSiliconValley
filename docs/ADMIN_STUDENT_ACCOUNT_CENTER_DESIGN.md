# Admin 学员账号中心设计

日期：2026-09-14

状态：初步设计，尚未实施或部署。供产品对齐与执行 Agent 实施使用。

对应任务：[T-114](../.codex/inbox/todos/114-dm-learner-account-management-center.md)。原任务文件名保留以避免链接失效，管理角色以本文及任务最新修订的 **Admin** 为准。

## 1. 目标与权限定位

将 `/account/` 扩展为按权限呈现的账号中心：Admin 可以集中管理学员，普通用户管理自己的账户。管理能力绑定权限，不绑定某个具体人的账号。

- **Admin**：按服务端授权范围查看、新增、修改、停用及符合条件时删除学员，管理备注和重置密码。
- **课堂 Admin DM / 导师**：课堂成员管理权不自动等于平台学员账号管理权；仅具备课堂权限时，仍只能按已有规则搜索并分配可见账号。已有的受限密码找回协助能力不在本单中擅自撤销或扩大。
- **学员**：只管理自身允许修改的资料和密码，不可查询他人、读取管理备注或调用后台 CRUD API。
- 新管理入口复用既有 Admin 权限模型，不因显示名称包含“Admin”“DM”就授权，不新增隐含超级权限。

本期管理对象限定为学员账号。导师、Admin 的任命和权限委派不放进学员编辑表单。

## 2. 页面组织

Admin 打开 `/account/` 默认进入“学员管理”；“我的账户”作为清楚分开的次级页签，保留个人昵称、密码和设备管理。非 Admin 默认进入“我的账户”，不能通过手输地址或 API 请求绕过限制。首次登录必须更换密码等现有流程优先执行，不被默认页签覆盖。

```text
MINI硅谷 → 首页                         当前账号菜单

账号中心
[学员管理]  [我的账户]

搜索：ID / 账号 / 昵称       状态筛选       [+ 新增学员]

学员列表
头像 · ID/编号 · 登录账号 · 昵称 · 备注摘要 · 状态 · 操作

操作：编辑 / 设置或重置密码 / 停用或启用 / 删除
分页、匹配数量、加载失败重试
```

- 右上角菜单和内部工作台均链接到同一管理视图，不另建一套数据或管理后台。
- 设备菜单的“添加账号”仍表示登录另一个已有账号；管理页“新增学员”才表示创建身份，不能混用。
- 新增、编辑使用一个清楚的表单面板，不设不必要的多步向导。密码重置、删除单独确认。
- 列表保留账号和 ID 便于核对；长 ID 可以缩略并提供查看、复制完整值。备注摘要展开阅读，不挤占主要操作。
- 主用设备为电脑；较窄窗口可用列表容器横向滚动或摘要卡，不隐藏关键操作。表单仍应在平板可阅读、可触摸。
- 使用 `mini-silicon-valley-design` 的最新统一 UI、品牌 Logo、奶油底色、像素边框和清楚的留白；后台不需要巨大宣传标题或世界观入场弹窗。与 T-118 的表单 padding 修复共用规范。

## 3. 学员数据设计

以下是**逻辑字段**，不是承诺新增一张同名数据库表。实施时先对照最新认证、profile、Membership 模型，优先复用字段；只补缺失内容，不复制一套“学生账号库”。

### 身份与资料

- `id`：底层账号/profile 的稳定唯一 ID，只读。用于关联成员、作品和学习记录；不可用昵称或序号替代。
- `username`：唯一登录账号，如 `msv-student-01`。保留现有 01～04；新建时由服务端生成或校验未占用账号。第一版创建后只读，日常改名通过昵称完成。
- **显示编号**：若现有系统有独立学员编号则复用；否则直接展示编号式登录账号，不为“01”另造身份。课堂“学员 1”是席位，不是此账号的永久编号。
- `displayName`：昵称/别名，Admin 可编辑。允许不同学员同名，用账号和 ID 区分；复用现有显示名称字段，不新增互相冲突的 nickname 和 alias 真值。
- `adminNotes`：可选、可编辑的管理备注，纯文本；仅授权管理端返回，不混入公开 profile、学员自己可见的账号响应、课堂课件或作品。避免填写密码及无关敏感信息。
- `avatarSeed`：首次创建时随机生成并持久化的头像种子；若已有头像字段则复用适配。结合固定的像素渲染规则，刷新、切换设备后仍显示同一头像。
- `avatarVersion`：仅在渲染算法需要版本区分时使用；不要上线新算法就静默改变所有既有头像。

### 管理状态与只读信息

- `status`：账号可用状态，沿用现有服务端枚举；界面解释启用、停用等实际状态，不自行发明数据库状态值。
- **密码状态**：展示是否待首次改密等既有认证状态；不是密码内容，也不能用是否显示“星号”假装保存了可读取的原密码。
- **关联课堂**：由 Membership 查询得到的只读摘要，可多个课堂；不得往学员表里硬写单个 roomId 作为唯一归属。
- **创建时间、更新时间、最近登录**：有可靠来源才展示；首次未登录明确显示“尚未登录”，不编造时间。

### 密码不属于可读取的学员资料列

新建或重置表单可以输入初始/新密码，但管理列表、详情 API、备注和导出均不返回原密码。认证系统继续使用现有安全存储方式；不新增明文 `password` 字段，也不另造密码加密方案。

设置密码与保存资料为两个动作。沿用当前密码强度、首次登录改密、重置验证、失败限制和会话失效规则。必要的初始凭据交付只在明确的受控流程中短暂展示，不写进 URL、日志或浏览器持久化存储。

## 4. CRUD 交互

### C：新增

1. Admin 点击“新增学员”，看到可用的编号式账号、昵称、初始密码和可选备注，头像自动生成。
2. 服务端校验权限、字段及账号唯一性；不能用当前列表条数产生新账号，也不能覆盖已有编号。
3. 成功后显示创建结果及稳定 ID，刷新列表。重复点击不产生重复账号；失败保留非敏感表单内容并给出原因，不回显提交的密码。
4. 从 T-113 课堂选择器进入时，保留原课堂配置；创建成功后返回原席位确认选择。账号创建成功但加入课堂失败，应允许选择已创建账号重试，而非再次建号。

### R：查询

- 支持 ID、登录账号、昵称搜索和状态筛选；Admin 备注搜索若提供，只能走同一授权管理查询。
- 分页后的查询覆盖授权范围内的全部匹配记录，而非仅过滤当前页。
- 区分空列表、无搜索结果、无权限、加载中和失败；读取失败不假报“没有学员”。

### U：修改、密码与头像

- 编辑昵称、备注、账号状态；保存不改变 ID、登录账号、历史 Membership 或作品归属。
- “换一个像素头像”生成新种子，保存后才生效；取消编辑保持原头像。头像本地渲染，不依赖外部随机头像服务，更不向第三方发送学生身份。
- 密码重置为独立操作：显示目标账号和影响，沿用现有安全流程；成功提示可验证，失败不伪报已重置。
- 停用不能只是列表改标签：对登录、已有会话和课堂参与的实际影响必须沿用并验证账号状态契约；不影响其他用户或操作者的会话。

### D：删除，不以停用冒充完成

- 学员列表和详情提供明确的删除入口；服务端先检查真实账号、授权范围和依赖，再返回是否可删除及影响。
- 无历史依赖且符合现有删除规则的账号，经目标确认后可删除；按认证系统规则处理该账号的凭据和会话，旧 ID 不再用于新学员。
- 有课堂、作品、学习记录等依赖时，不级联破坏历史证据；明确说明阻止删除的原因，并提供停用作为替代。最终硬删除策略须对照最新数据约束，不能只在前端猜测。
- UI 区分“删除账号”“从某课堂移除成员”“退出本设备账号”；三者不能共用含糊的“移除”按钮。
- 删除、禁用等敏感操作保留最小审计记录，不记录密码或无关备注正文。确认框不能替代服务端执行时的权限与依赖复核。

## 5. 实施衔接与验收

顺序：核对最新账号模型及权限 → 补资料字段和授权 API → 管理列表和新增/编辑 → 密码与删除闭环 → T-113 选择器回填 → 统一 UI 和部署复验。

- 使用临时隔离学员完成 C、R、U、D 全链路，验证新账号可登录、改昵称不改身份、重置后会话规则正确、删除后不可再用旧凭据。
- 用有依赖的隔离账号验证删除受阻原因和停用替代，不操作真实课堂或真实学员密码。
- 分别验证 Admin、仅课堂 DM、导师、学员；越权直接 API 请求同样被拒绝，不能只测菜单隐藏。
- 备注不出现在非 Admin API/页面；头像刷新、跨设备一致；搜索同名学员不会选错 ID。
- T-113 在 2/4/6 席位配置中搜索并回填，其他席位与课程配置保持不变。
- 普通点击打开管理入口，键盘和触摸能完成表单；长昵称、备注、错误消息及忙碌状态不溢出，密码显示按钮不遮挡输入。
- 分别提交实现、隔离测试、部署及入口复验记录，不能仅凭“按钮出现了”宣告 CRUD 完成。

本期不扩展成 CRM，不新增组织架构、复杂自定义角色、批量删除、头像上传或学生敏感档案。后续有实际需求再扩展。
