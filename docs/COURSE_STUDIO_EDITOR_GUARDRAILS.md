# Course Studio 编辑器不可退化约束

> 状态：T-085 修正基线
> 日期：2026-09-08

## 为什么需要这份约束

T-085 统一课程工厂时，曾把完整课程编辑器误替换成只读倾向的角色摘要卡。数据架构虽然升级了，但作者无法看全课程，也失去了“看见哪里就直接改哪里”的原有工作方式。根因是把**底层版本架构替换**错误地等同于**上层编辑器重做**。

以后必须把两层分开：

- 底层采用 T-085：`CourseDefinition → Candidate → ViewAcceptanceReceipt → Test Classroom → UiAcceptanceReceipt → Released`。
- 上层保留成熟编辑方式：完整工作台、可视化直改、全课程导航、抽卡编辑、JSON 源码与版本历史。

## 编辑器主棍

`/studio/editor/` 是完整课程的唯一写入口，不是课程摘要页。

进入后必须同时具备：

1. 左侧课程库，可切换 Google、饿了么及新课件。
2. 五大步、十三小块完整时序轴，任何块均可直接定位。
3. `4 位导师 + N 名学员` 的同屏角色视图。
4. 底部课程中控视图。
5. 点击可见文案，直接修改其唯一 `CourseDefinition` 路径。
6. 高级结构、抽卡内容、JSON 源码三种补充编辑模式。
7. 撤销、重做、导入、导出、克隆、结构检查和不可变版本历史。
8. 保存产生 Candidate；不能静默改变正在运行或已开始的课堂。

RP、钱包、进度、随机手牌等模拟结果只用于预览，必须明确只读，不得反向写进课程定义。

## 禁止的“简化”

以下做法均视为回归：

- 用四张学员摘要卡替代完整编辑器。
- 只展示当前 Block，导致无法浏览完整五步十三块。
- 把可编辑正文降级为只读预览或只能改原始 JSON。
- 为适配新 API 擅自改变成熟布局、交互层级或信息密度。
- 恢复旧全局 Alpha/Run API、旧鉴权或共享运行状态。

## 自动验收

```bash
npm run test:course-platform
npm run test:course-platform:e2e
npm run test:studio-editor:browser
```

浏览器回归至少验证：

- 桌面三栏互不覆盖，移动端无横向溢出。
- 5 个大步、13 个小块、默认 8 个角色视图和 1 个中控齐全。
- 点击可见字段后可直接修改，并立即同步到所有引用位置。
- 动态切换到 6 名学员后得到 `4 + 6 + 1`，不伪造固定席位。
- 四个编辑模式可切换，未登录和学员 RBAC 仍然关闭写入口。

编辑器脚本有明确依赖顺序，只能由 `editor-loader.js` 依次载入主题、卡片渲染器、角色投影器和主编辑器；不得重新拆成并发的 `next/script` 标签。否则本地缓存下可能正常，生产网络中会因主编辑器抢先执行而停在“正在载入”。

视觉与交互回执位于 `docs/qa/t085-editor-restoration/`。
