## T-112：课程命名与案例解耦

课程编辑位置：

```text
Studio → 01 课程编辑器 → 选择课程 → 结构编辑 → 课程名称
```

保存仍遵循 `Working Copy → Candidate → 验收 → Released`。改名不会原地改写旧 Candidate、Released 或已开课堂快照。

数据约束：

- `course.id` 是课程稳定身份；`course.name` 是可编辑教学主题。
- `case.campaignId` 是旧结构中的默认案例指针，不再等于 `course.id`。
- `contentPackages.casePackages[].caseId` 在课程内唯一；默认案例指针必须指向其中一个已声明案例。
- 一门课程可包含多个历史案例和无来源的模拟案例。
- F 卡必须由自己案例的 evidence revision 枚举；模拟案例不得伪装成史实。
- 克隆只创建新课程身份，不重写案例、牌组、卡牌和来源 ID。

旧 field-model 中唯一允许的 `course.period → case.period` alias 只为读取不可变历史版本保留；新 Candidate 规范化时移除，课程总体跨度不会覆盖案例时间。

## T-116：课件一键直达

静态课件入口在服务端完成三件事后立即重定向：

1. 账号认证与首次改密门禁。
2. 目录可见范围或课堂／Studio exact 权限校验。
3. exact `revision + digest` 装入真实课件 URL。

统一函数 `coursewarePlayerHref()` 会保留包声明的启动模式（例如产品导师 `view=overview&slide=0`），再覆盖用户明确指定的 slide/step。旧的 `CoursewareFrame` 只保留 inline HTML 渲染职责，不再显示重复中转卡片。

产品导师当前指针升级到不可变 r2；r0/r1 仍按原 URL 和原字节保留用于审计与明确历史预览。
