# 课程大纲与内容归集指南

正式入口：<https://minisv.vip/course/>

## 课程的统一主棍

Mini Silicon Valley 用真实科技史带学员经历一次完整创业闭环：

```text
一世界：同一座由真实科技史和现实项目组成的学习世界
两轨线：历史认知轨 ↔ 现实项目轨
三玩法：毛线信息交换 → 美式情境攻坚 → 德式经营取舍
四导师：产品 P、开发 D、市场 M、运营 O
五步骤：找真问题 → 定真方案 → 做真产品 → 进真市场 → 跑真运营
六分钟：五步之后完成 Demo Day 终局发布
```

学生都是 Young Builder 团队成员，早期不固定扮演 P／D／M／O。四个字母属于导师专业分工。

## 五个完整步骤

### 01 找真问题

进入历史现场，随机抽取不同信息卡，先描述具体人物、场景、行为和损失，再通过毛线式交换拼出问题全貌。产出是可追溯的问题证据；没有一手证据或仍把方案写成问题，就不能过关。

### 02 定真方案

围绕已经验证的问题产生多个方案，用美式情境挑战暴露假设，再根据证据、风险与资源选择一个方向。产出是方案取舍及其反证计划，而不是“大家觉得不错”的点子。

### 03 做真产品

由开发导师带领把方案缩成端到端 MVP。团队说明什么必须做、什么暂时不做，完成可演示原型与测试记录。真实用户必须能完成一个核心任务。

### 04 进真市场

由市场导师带领确定第一批用户、价值承诺、触达方式和验证指标。团队执行一次真实触达或等价课堂实验，记录响应而不是只写宣传文案。

### 05 跑真运营

由运营导师带领维护交付链、成本、收入、复购与品牌承诺。团队用共同资金做德式经营取舍，形成运营账本、迭代决定和下一轮计划。

### 五步之后：六分钟 Demo Day

六个 60 秒段落依次呈现：问题证据、方案取舍、MVP、用户／市场证据、运营账本、下一步请求。Demo Day 是五步证据的压缩发布，不是独立第六步。

## Course Package v1 是唯一课件真值

每门课由 JSON Course Package 表达：

- `course`：课程身份、周期、5×13 完整性；
- `sources`：史实来源；
- `formula`：一世界到六分钟；
- `macroSteps`：五大步；
- `blocks`：13 个可执行小块；
- `decks`：每步一套随机信息卡；
- 导师 SOP、八席任务、资源和验收门。

正式内置课件：Google 1995—2004、饿了么 2008—2009。编辑入口是 `/control/editor/`。流程为：

```text
编辑草稿 → 深度校验 → 保存 revision → 发布 Released → 新 Run／重置 Run 采用
```

活动 Run 不因发布而静默变课。需要显式“刷新 Alpha”，并保留进度、RP、个人钱包、团队资金和稳定卡牌 ID。

## 新增或修改课件

1. 在编辑器复制一门现有课程或导入 Course Package JSON。
2. 保持 5 大步、13 Block、每步一套卡组的骨架。
3. 为每个 Block 写清：当前情境、学生只做的一件事、可说／可问内容、可见过关条件、双轨内容、主导师和玩法。
4. F 卡必须绑定可追溯来源；R／G／U 分别明确“课堂模拟／我们猜的／还不知道”。
5. 运行服务端验证；修完所有阻断项再保存和发布。
6. 用 Alpha 八席验证发牌、讲述、攻坚、投入、收益和导师交接。
7. 发布后用 `/course/` 核对课程 ID、revision、digest 和结构。

不要在课程页组件里手写另一套步骤或卡牌内容；它只能消费 Course Package 的只读投影。
