## 3. WHAT／WHY／HOW 的教学边界

### WHAT：能认出并描述模块

主线顺序建议：

1. **变形金刚／变形玩具**：使用预制组件，在既有能力、结构和接口限制内改变位置与场景角色。保留轮子、透明件、铰链等追踪演示及复用失败反例。
2. **乐高**：标准基础零件 → 玩家自制功能组件 → 完整作品。保留齿轮传动、传送带、感应门与自动化整体演示，明确两次组合。
3. **我的世界式方块拼接**：材料方块 → 塑形／拼接出的组件 → 完整功能对象。保留当前小车和第二课堂道具案例、层级切换、材料能力与网格连接约束；第二案例仅限抽象课堂模型，不加入现实武器制作信息。
4. **模块四要素**：输入、处理、输出、接口；保留登录卡配对和自动门追问。
5. **功能、模块、产品及观察尺度**：保留轮组尺度题、按钮反例。
6. **AI 也由能力模块构成**：保留基础模型、提示词、工具、记忆／数据、编排／验收和 AI 侦探活动。

准确性边界：

- 三个拼装例子递进的是玩家能够介入设计的层级，不是物理尺寸排序或方案优劣排名。
- 预制组件不能任意变功能；乐高基础件同样受约束；方块材料与行为不是完全相同，现实方块游戏也存在预制功能块。
- 当前是原创课堂示意，不冒充商业玩具真实三形态或《我的世界》官方配方／物理规则。
- 物体拼好不自动等于软件行为已经实现。把门拼出来后，仍需定义触发条件、开门规则、状态和失败反馈。
- 保留四要素但调整关系表达：接口是输入输出及协作约定，不应被画成“输出之后再做一次接口”的第四个时间步骤。
- Roblox 如加入，用于软件迁移，不代替三种拼装例子，也不要求学生安装完整开发环境或把本课改成工具培训。

WHAT 验收：面对新例子，学生能说明任务、输入、输出及连接条件，而不只说“很多小块组成大块”。

### WHY：能判断模块化的价值与代价

- 保留四人同时做失物招领的混乱实验和投票。
- 保留看懂、分工、替换、复用四种价值及场景匹配。
- 保留自建与复用取舍；补强拆得过碎带来的连接、协调、测试及维护成本。
- 不将“模块越多越好”“自建比复用高级”“每个页面就是一个业务模块”作为结论。
- 学生能对自己的游戏说出一处值得拆开的原因、一处暂时不必继续拆的原因。

### HOW：围绕自己的游戏形成三个相互关联的成果

沿同一游戏的一条完整核心玩法持续设计，不让三份成果变成三个独立重复表单。

1. 从既有作业中提取玩家、动作、目标、胜败、障碍／奖励；不重新上一次完整产品课。
2. 画核心玩家路径，再归纳共同任务与责任单元。
3. 用高内聚检查责任，用低耦合检查模块交接。
4. 深化一个关键模块，随后做正常和非成功／异常分支验证。
5. 同伴提出具体问题，学生修正设计，再展示。

## 6. 三项成果的建议结构

### A. 自己游戏的模块地图

- 学生与游戏标识、玩家目标、一条完整核心玩法路径。
- 模块名称、责任及主要输入输出，箭头写明传递的内容。
- 标出复用／自建的考虑，以及尚未展开的系统。
- 当前模板有六个格子不代表每个游戏必须六个模块；不以数量作为成绩。
- 最低验收：能沿路径接回，责任说得清；地图不是页面目录、人物清单或技术名词清单。

### B. 关键模块详细设计卡

在现有接口卡上深化，保留名称、唯一责任、输入、成功／失败输出、依赖、负责人／协助者，并补充：

- 触发时机与前置条件。
- 关键处理规则与必要状态变化。
- 明确不负责的事情。
- 可检查的结果，与验证记录的关联。

字段逐步展开，避免初中生一上来面对密集规格文档。模块优先从核心玩法中选择，不机械要求大家都设计登录模块。

接口配对仍保留：公共校园订餐案例可做跨组交接；个人游戏阶段由同伴扮演该游戏中的相邻模块，不强迫两个不同游戏的模块互相接通。

### C. 正常／异常流程验证记录

每条记录包括：初始状态、输入／操作、预期结果、实际走查或运行结果、差异、修正内容与复测结果（如进行了复测）。至少一条正常成功路径和一条非成功／异常分支。

- 保留神秘黑箱的边界与错误输入提问，不能由少数样例断言唯一内部规则。
- 保留拔掉模块后判断中断／降级，以及接口兼容时替换模块的挑战。
- 失败条件可以是业务拒绝、缺少输入、重复操作或依赖不可用；不只把“异常”理解成程序崩溃。
- 没有程序时标记为纸面／角色扮演走查；只有实际运行过程序才填写程序测试结果。AI 推测不是测试通过证据。
- 不能预填全部通过；发现设计问题并修正，也是有效学习成果。
