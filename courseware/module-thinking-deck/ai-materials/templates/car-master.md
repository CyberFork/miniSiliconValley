# 方块小车主棍 v1｜人类编写与验证

## 执行者
人类编写本主棍，决定并验证玩法。AI 基于主棍编写全部模块子棍，人类验收批准后执行。执行棍由 AI 自动编写、执行、自动验收，学生不写。

## 上下文与项目设计
玩家驾驶方块小车拾取物品，携带钥匙到终点。
模块：移动、地形、道具、背包、提示、终点。
模块组合支持移动、拾取、携带物品、过关判断；不是一个模块等于一个功能。
共同数据：物品编号 key（钥匙）、coin（金币）、tool（工具）；背包是已持有清单唯一来源。移动提供位置，地形提供碰撞，终点只读位置与清单。
这是设计要求，不代表学生的项目已经实现。

## 目标
完整愿景：小车能前后移动、转向、独立喷射，碰到物品可拾取，带钥匙到终点成功。
本轮：先跑通两格背包收下／拒收／丢弃，再接道具与终点；其他模块保留子棍。
默认浏览器可运行原型，附打开方式、调用示例、测试记录。

## 约束
背包最多两件不同物品；重复不增加；满包拒收且已有物品不变。丢弃腾位后可再收物品。
↑普通前进，↓后退，左右转向，Space 独立喷射，不能把↑当作喷射。
公共交接：收纳请求交物品编号，回复已收下／已拥有／已满／无效；背包提供只读清单。
只用虚构资料。变更主棍时 AI 主动报告受影响的子棍和用例，经人类验收后执行。

## 避免
不加入商城，不偷偷扩容，不让钥匙顶掉金币，不改过关条件，不用漂亮页面冒充功能完成。

## 验收
空包收 key → [key]；再收 key → 仍只有一份。
[coin,tool] 收 key → 拒收，清单不变，钥匙仍在路上。
丢 tool 后收 key → [coin,key]。
无钥匙到终点 → 不成功且有提示；带 key 到终点 → 成功弹窗。
单按↑ → 普通移动，无喷射火焰；按住Space → 喷射，松开停止。
逐项记录预期与实际；AI 自动检查后，人类打开成果亲自验证。
