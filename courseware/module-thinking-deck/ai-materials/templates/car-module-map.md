# 方块小车模块地图示例｜P1 背包原型设计稿

> 面向六年级至初中。以下是设计示例，不是已经测试的学生项目；只用虚构资料，不含隐私。

## 1. 产品／整局玩法
- 产品：方块小车闯关。玩家驾驶小车移动、碰到物品并拾取，把 **key** 带到终点。
- 完成：同时到达终点且背包含 `key`；没有 key 只提示缺少条件。
- 当前优先路径：先跑通“两格背包收下／拒收／丢弃”，再接道具与终点；移动、地形、提示先保留接口。

## 2. 玩家可做的功能
- 移动｜合作模块 ID：M01＋M02｜说明：M01 处理方向／位置，M02 提供碰撞与支撑
- 拾取｜合作模块 ID：M01＋M03＋M04｜说明：位置碰撞触发请求，背包决定收下或拒收
- 携带｜合作模块 ID：M04＋M05｜说明：M04 是清单唯一来源，M05 只显示真实状态
- 闯关判断｜合作模块 ID：M01＋M04＋M06＋M05｜说明：位置和清单共同决定结果，M05 提示玩家

## 3. 模块清单
- M01｜移动｜负责：处理方向、位置、速度和喷射状态｜不负责：背包、拾取结果或胜负
- M02｜地形｜负责：提供可走区域、坡道、边界和碰撞｜不负责：保存背包、决定拾取
- M03｜道具／拾取｜负责：检测碰撞，按物品编号请求收纳｜不负责：决定容量，拒收时不移走物品
- M04｜背包｜负责：管理两格清单、去重、收下、丢弃｜不负责：决定终点胜负
- M05｜提示｜负责：显示格子、拒收原因、缺钥匙和成功｜不负责：修改游戏状态、把请求当成功
- M06｜终点｜负责：读取位置和清单，判断是否过关｜不负责：捡物品、修改背包

## 4. 交接箭头与数据所有者
- M02 --[碰撞／支撑结果]--> M01；所有者：M02；路径：整车集成
- M01 --[位置]--> M03；所有者：M01；路径：整车集成
- M03 --[物品编号 `key`／`coin`／`tool` 的收纳请求]--> M04；所有者：M03 管路上的道具；M04 管已收清单；路径：背包优先测试及整车集成
- M04 --[已收下／已拥有／已满／无效，及清单]--> M03、M05；所有者：M04；路径：整车集成
- M01 --[位置]--> M06；M04 --[只读清单]--> M06；所有者分别为 M01、M04；路径：整车集成
- M06 --[成功／缺少条件及 result]--> M05；所有者：M06（结果）；路径：整车集成

## 5. P1 先做与待决定
- 先做：M04 两格收纳／拒收／丢弃；再接 M03、M06、M05。满包拒收不替换原物品。
- 待决定：完整地图中是否加入更多物品、关卡和奖励；不影响本轮 `key` 过关条件。
