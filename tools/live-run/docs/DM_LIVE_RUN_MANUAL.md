# 终极管理员 / 主 DM 操作手册

## 开场

产品与体验不可退化基线见 [`UX_PRODUCT_TRUTH.md`](UX_PRODUCT_TRUTH.md)。

1. 确认 4 名导师顺序：P 产品（主 DM）→ D 开发 → M 市场 → O 运营；确认 4 名学员保留各自身份。角色窗口为 8 个（导师 4 + 学员 4），另有独立主控窗口，共 9 窗口；导师席不占学员席。
2. 按 README 在两个终端分别运行 `python3 launcher.py` 与 `python3 launch_grid.py`；确认主控状态为“就绪”、当前 B01，且 8 个角色窗口按 2×4 排列在 Chrome/macOS 主显示器的 `workArea` 可见安全工作区内。网格从 `workArea` 的 `left`/`top` 起算，避开菜单栏、左/右 Dock 和 Stage Manager；独立的第 9 个主控窗口也必须位于该安全工作区内。宽高余数按相邻切线分配，各列、各行最多相差 1 像素。真实 API 模式下确认临时账号文件路径和 URL，不在投屏、聊天或截图中暴露凭据。
3. 每块先读脚本的目标、导师任务、学员任务与证据门槛，再点击“执行”。系统完成后只会停在“待验收”。
4. 主 DM 对照实体作品、口头过程和证据门槛人工检查；通过才点击“验收并解锁”。不通过则保留现场记录，必要时重做当前块，绝不跳块。

## 逐块闸门

- B01 P：建房、4+4 席位、随机发 12 张卡（每人 3 张）；学员保留自己的历史身份；每人独立随机获得 3 张私密卡，只标 F/R/G/U，不分 P/D/M/O。个人 RP、个人钱包、团队资金分别显示，不能混用。
- B02 P：四人各发布卡片并互相追问，形成公开情报池。
- B03 P：情报成网，锁定可推翻的真问题；冻结判断后才揭晓史实。
- B04 P：比较至少三条路径，选唯一价值赌注并填写移交单。
- B05 D：接棒裁剪 MVP；预算与压力后仍能演示关键结果。
- B06 D：搭出第一版，让用户真的按一下。
- B07 D：经历两轮压力，故障后仍保住核心结果。
- B08 D：只改一处，冻结 MVP V1 并对照历史。
- B09 M：锁定窄目标人群与一句可验证承诺。
- B10 M：完成一次真实渠道实验，记录同意、拒绝及理由。
- B11 O：设计可重复 SOP、角色交接与交付记录。
- B12 O：核对成本、收入、反馈、留存和下一轮指标；确认四人的 RP 都对应具体作品，可分利润的 40% 已进入四个人钱包，团队资金仍有余额。系统不代学员花个人钱包。
- B13 O 运营导师总控：严格 6×60 秒：问题证据、方案取舍、MVP 演示、用户/市场证据、运营账本、下一步请求。O 控时收口；完成后再验收。

## 故障恢复与安全

- 执行失败：页面显示“错误”时先保存错误信息和现场证据，修复网络/API 或输入后点“重试”；不得直接改状态文件。
- 浏览器断开：重新打开控制台；状态是原子 JSON 持久化，先确认当前块与 API 房间引用，再继续。
- API 不可用：切换到经确认的 verified-simulation 仅做联测，不把模拟结果当真实课堂证据；真实课须恢复 API 后重做相关块。
- 原型故障：B13 立即使用纸面流程备份，计时不停，仍须展示证据闭环。
- 凭据：使用临时、最小权限账号；不写入 Markdown、Git、截图、终端回显或错误消息。API URL 与账号文件仅通过本地启动参数传入。
- 结束：导出脱敏回执，保留状态与证据；清理临时凭据，勿删除仍需审计的课堂数据。

## 交付前验收命令

```bash
sh tests/run_tests.sh
python3 tests/run_real_acceptance.py --course google-1995-2004 --reset-after
python3 tests/run_real_acceptance.py --course eleme-2008-find-problem --output docs/REAL_ACCEPTANCE_ELEME_RECEIPT.json --reset-after
python3 tests/verify_live_browser.py
```

第二条用于连续验证真实 API，课堂现场不要以它代替逐块人工验收。第三条要在 B01 已执行、主控正停在“待人工验收”时运行。

## 课程选择与五步战役

主控支持选择课程库。Google `google-1995-2004` 是 5 步/13 块完整战役，继续按 B01–B13 逐块执行、人工验收，并保留 Google 完整验收回执表述。饿了么 `eleme-2008-find-problem` 是教学团队素材支持的 5 步/13 块战役，action 顺序与 Google 一致；第1步源于史料，第2—5步明确标注为玩家平行世界实践。B13 为六分钟 Demo。新 v2 验收回执待真实重跑后覆盖，旧回执仅作审计。

切换课程总是新 Run；若当前 Run 已开始，切换前必须确认。旧 API 课堂只保留审计，不能复用。8 个角色窗口同步切换。饿了么历史揭晓前，学员只看到安全名称“2008 宿舍订餐调查小队”；第2—5步明确标注为玩家平行世界实践，不冒充历史，也不把单元课结果写成完整战役验收。
